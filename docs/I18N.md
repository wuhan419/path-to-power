# 多语言契约（I18N）

> 《权力之路》文档体系的一部分。字段级内容契约见 [`CONTENT-SCHEMA.md`](CONTENT-SCHEMA.md)，
> 并行派活规则见 [`PARALLEL-CONTENT-WORK.md`](PARALLEL-CONTENT-WORK.md)。

支持 **简体中文（zh，默认）** 与 **English（en）**。设计前提有两条，整个机制都建立在它们之上：

1. **中文没有翻译文件。** 引擎里每处界面串写成 `P.t(key, "中文原文")`，第二个参数就是默认值。
   中文侧永远走默认值，所以中文不需要任何词典；某条 key 缺英文，界面上就显示中文原文。
2. **内容原文件不动。** 事件卡的英文放在 `content/i18n/en/` 下的**覆盖层**里，
   `content/events/*.js` 一个字都不改。于是并行 worker 之间零冲突，也能一张一张回补。

切换语言：标题屏的语言按钮，或 URL 加 `?lang=en`。切换会写 `localStorage.potus_lang` 并**整页重载**
（覆盖层是 `boot()` 时一次性并进注册表的，不做运行时还原——所以也不需要快照，
不会踩到引擎各处缓存的 `reg` 子对象引用）。

---

## 1. 两条路，别混用

| 文本种类 | 机制 | 谁改 | 英文落在 |
|---|---|---|---|
| 引擎界面串（按钮、标签、提示） | `P.t(key, 中文原文[, 参数])` | 改**引擎**文件 | `content/i18n/en/ui.js`（可按模块分片） |
| 内容包文本（事件卡、注册表名字） | `POTUS.define("l10n", {lang,content})` | **不改**原内容文件 | `content/i18n/en/<镜像路径>.js` |

判断依据：文字在 `dev/engine/` 里 → 走 ①；在 `dev/content/` 里 → 走 ②。

## 2. ① 界面串：`P.t`

```js
P.t("ui.title.newGame", "开始新游戏")                    // 无参
P.t("ui.tier.level", "等级 {n}", { n: t + 1 })            // 带参：{name} 占位
```

- **key 命名**：`ui.<视图或模块>.<名字>`，全小写点分。例：`ui.leftbar.row.factions`、`ui.attr.CHA`。
  key 全局唯一，**不复用别人的 key**；一个 key 一个含义。
- **标点算在串里**：`"语言："` 整体作为一个 key 的值，不要把 `：` 拼在 `t()` 外面——英文要的是 `"Language: "`。
- **不要翻译数值/单位/颜色**，也不要 `t()` 一个拼出来的句子成分。英文语序和中文不同，
  需要整句时用带参数的模板：`P.t("ui.stage.slots", "{n} 个档期", {n})` → `"{n} slots"`。
- **别在 `t()` 外面做字符串长度判断或按中文字数截断**，那是 locale 假设。
- **模块顶层求值的常量必须在"用它的那一句"取词**，不能在定义处取词。`engine/i18n.js` 在 `core.js`
  之后才加载，`P.t` 那时还不存在；而在 boot 前求值的表（`create.js` 的 `DIFFS`、`scale.js` 的
  `VAL_LABEL`、`dice.js` 的 `TIER_LABEL`、`vignette.js` 的 `SLOT_NAME`、`balance.fuzzLabels`、
  `reg.factionUnknown`…）如果在定义处就调了 `t()`，拿到的永远是中文。做法：表里存中文原文，
  渲染/取用的那个函数里再 `P.t`（getter 或调用点包裹都行，别存翻译结果）。

## 3. ② 内容覆盖层：合并规则

```js
POTUS.define("l10n", {
  lang: "en",
  content: {
    event: [{ id: "gulf91_storm", title: "…", brief: { lede: "…" },
              choices: [{ id: "patriot", text: "…", outcomes: { crit: { body: "…" } } }] }],
    faction:   { base: { name: "Base Voters" } },
    category:  { crisis: { name: "Crisis" } },
    worldline: { brief: { "1991": "…" }, outlets: { "1991": ["CNN", …] } }
  }
});
```

定位与合并（实现见 `dev/engine/i18n.js`）：

| 载荷形状 | 对齐方式 | 注意 |
|---|---|---|
| 对象数组，元素带 `id`（event / choice / act） | **按 id** | 顺序无关 |
| 对象数组，元素无 id（`brief.terms`、vignette texts） | **按数组下标** | 别改顺序 |
| 纯标量数组（`known` / `rumor` / `unknown` / `texts`） | **整体替换** | **必须整条给全**，少一条就少一条，不做逐项合并 |
| 对象 | 递归深合并 | 只写你要覆盖的字段 |

**保护键**：结构性与引用性键一律不许改写（`id`、`era`、`minYear/maxYear`、`tierMin/tierMax`、
`weight`、`grade`、`category`、`valence`、`base`、`mods`、`flags`、`req`、`cost`、`cond`、`when`、
`contacts`、`tracks`、`parties`、`month/day`、`effects` 里的引用键 …完整清单见 `i18n.js` 的 `PROTECT`）。
值与原文相同（比如定位用的 `id`）放行；**改写会被记账，`validate.js` 直接判失败**。

## 4. 英文怎么写（不是逐字翻）

- **按英语重写**：第二人称、现在时、短句。中文一句 20 字常能压成英文 8 个词，别硬对。
- **专有名词回译，不翻译**：`有线电视新闻网`→`CNN`、`华尔街日报`→`The Wall Street Journal`、
  `今日美国`→`USA Today`、`哥伦比亚广播公司`→`CBS`、`布赖特巴特`→`Breitbart`。
  集中在 `09-flavor.js`（ORG/PLACE/PUB 池）、`20-eras.js`、`21-worldline.js`（outlets）。
- **`「」` 在英文里用 `"…"` 或改写掉**；英文正文不许出现残留中文标点（`，。、：；`）。
- **句子骨架类内容要整句重设计**，不能沿用中文槽位。两类已经做过，照它们的做法抄：
  `30-fillers.js` 的 `bodyTpl` 是"动词短语 + 名词主题"拼的（`你被卷进` + `一场市政债违约`）——
  英文侧把 `acts` 全写成及物动词/介词短语收尾、`topics` 全写成可直接接在后面小写名词短语、
  `bodyTpl` 与引擎兜底 `ui.events.fillerBodyTpl` 逐字相同，任意 act × topic 都拼得出合法英文；
  档位句不做 `good|bad + 后缀` 拼接，五档各写整句（少一句就露出中文后缀）。
  `13-year-tales.js` 把州名插在句子中间——英文侧 `texts` 整条重写，`{state}` 一律挪到介词后
  （`in {state}` / `the streets of {state}`），占位符名不许改。
  两处的口径都写在各自分片的文件头注释里。
- **数字与日期**走原语，别自己拼：`P.numGroup(n)`（en 千分位 / zh 原样）、
  `P.dateLabel(y, m, d)`（en `Feb 1991` / zh `1991 年 2 月`）、`P.isEn()`。
  注意 `万/亿` 与 `k/M/B` 不是一一对应，涉及数量级的展示换算一律用 `P.fmtUsd`（`dice.js`）。

## 5. 长度预算（§11.7 的上限怎么套到英文）

`text-audit.js` 的尺子已经改成**统一折算成"中文等价字"**：CJK 串按字符数，纯拉丁串按词数 ×0.5
（≈200 字 ↔ 100 词）。所以 `LIMIT=200`、`lede≤50`、`known≤4×30` 这些阈值**不用改**，英文自动按词计。
标题另有一条：中文 <8 字算短，英文满 4 词即算合格。

## 6. 存档与旧数据

存档 `POTUS.serialize` 里 `G.log` / `G.yearHeads` / `quietLog` 存的是**渲染完成的成品句**，
切语言后这些历史行仍是原语言（事件卡本体按 id 重渲染，会跟着变）。当前决定：**接受混排**，
不做存档迁移。若以后要彻底解决，得改成存 id + 参数再渲染——那是引擎活，先提 issue。

## 7. 自检命令

```bash
node dev/tools/gen-manifest.js            # 新文件登记进 index.html 托管区（必跑）
node dev/tools/validate.js --lang=en --games=1   # 秒级快通道：结构 + 覆盖层完整性
node dev/tools/text-audit.js --brief --file=<你的文件>   # 篇幅
node dev/tools/validate.js                # 提交前：默认 20 局全量
node dev/tools/i18n-coverage.js           # 逐屏中文占比（界面侧还有没有漏网的串）
node dev/tools/i18n-events.js             # 逐卡缺译表（内容侧还剩哪几张没翻）
```

`validate.js` 会额外检查覆盖层：改写保护键 / 指向不存在的 id 或路径 / 未知注册表类别 → **直接失败**；
并打印 `--lang=en` 下变成英文的卡数（缺译回落中文属预期，不算失败）。

两个探针的分工：`i18n-coverage` 只管**界面**（渲染十屏后数 CJK 字 vs 英文词，>5% 退出 1）；
`i18n-events` 只管**内容**（同一条内容在 zh / en 各 boot 一次后逐叶子对照，值相同且含中文 = 缺译）。
后者不需要知道英文分片叫什么名字，所以不会被"文件看着写了、其实没覆盖到"骗过去。

> 校验工具里凡断言玩家可见措辞的地方，一律包 `ZH(() => …)`（= `POTUS.i18n.withZh`）：
> 串提取成 `P.t(key, "中文")` 之后，写死中文的断言在 `--lang=en` 下必然假红。
> 它只回退 UI 取词这一层，**注册表派生的名字（如 `P.factionName("press")`）boot 时已被覆盖层翻掉，回退不了**——
> 那种断言要跟同源取值比（`x.k === P.factionName("press")`），别写字面量。
