# 内容契约（CONTENT-SCHEMA）

> 这是**引擎团队与内容团队之间的接口契约**。引擎保证这些字段的语义稳定；内容只依赖这里写明的字段。
> 契约变更必须改本文件并在 `CHANGELOG` 里标注（见 `docs/DEVELOPMENT-GUIDE.md`）；项目总览与快速上手见仓库根 [`README.md`](../README.md)。

## 0. 注册入口

内容包都是普通 `.js` 文件（**非 ES module**，保证 `file://` 双击可运行），只需调用：

```js
POTUS.define(kind, payload);
```

| kind | payload | 说明 |
|---|---|---|
| `"era"` | `{ eraId: {...} }` | 时代锚点 |
| `"origin"` | `{ id: {...} }` | 出身 |
| `"talent"` | `{ id: {...} }` | 天赋 |
| `"entry"` | `{ id: {...} }` | 起点路径 |
| `"track"` | `{ id: {...} }` | 晋升轨道 |
| `"party"` | `{ id: {...} }` | 党派 |
| `"stance"` | `{ id: {...} }` | 政治姿态 |
| `"faction"` | `{ id: {...} }` | 派系（好感度条） |
| `"blackswan"` | `{ eraId: [ ... ] }` | 黑天鹅事件表 |
| `"filler"` | `{ eraId: pack }` | 填充模板包（`"*"` 为全时代兜底） |
| `"contact"` | `{ id: {...} }` | **人脉登记表**（这一局里能反复出场的那些"人"），见 §4.10 |
| `"category"` | `{ id: {...} }` | **事件类型**（每个类型自带默认配图与配色），见 §4.8 |
| `"grade"` | `{ id: {...} }` | **事件量级**（大/中/小事），一般不用改 |
| `"medium"` | `{ id: {...} }` | **时代媒介时间轴**（报纸/电视/互联网/短视频… 各自起始年份），见 §4.9 |
| `"event"` | `[ event, ... ]` | 事件库（可多次调用，自动累加） |
| `"ending"` | `[ rule, ... ]` | 结局规则（可多次调用，自动累加） |
| `"vignette"` | `{ title?, lede?, fragments:[ ... ] }` | **静好岁月**：平静月份的随笔片段库（`fragments` 多次调用会**累加**），见 §4.13 |
| `"photo"` | `{ dir?, files:{ categoryId: "x.jpg" } }` | **事件配图的照片表**（`files` 多次调用会**合并**），没登记的类型自动退回程序化 SVG，见 §4.15 |
| `"balance"` | `{ key: value }` | 覆盖平衡参数，可只写要改的项 |
| `"effect"` | `{ key: function(value, G){} }` | 注册自定义效果键 |

新增**任何**内容都不需要修改 `engine/`。

## 0.5 时间模型：一个月一回合

这是整个节奏的地基，写内容前必须先理解。

```
年（12 个月）
 └─ 月          ← 一个月 = 一个回合
     └─ 档期     ← 一个档期 = 一次需要玩家决策的事件（抽一个事件出来出题）
```

**不是每个月都有事。** 引擎在每次推进时按下面的公式决定某个月有没有档期：

```
pActive = clamp(activeChance + 时代压力 × activePressureMul + 活跃度 × activeBonusMul,
                activeMin, activeMax)

时代压力 = era.pressure（内容在 era 里写，0-6）
活跃度   = 丑闻 0.8 + 被调查 0.8 + 选举年 0.6 + 层级≥T4 0.5   （权重见 balance.bonusPressure）

有事发生的月份 → 档期数 = slotsBase + (压力≥slotsPressureAt ?1:0)
                          + (活跃度≥slotsBonusAt ?1:0) + rint(0, slotsVariance)
没有事发生的月份 → 只往月历上记一行「平静」，玩家看到月历卡继续往前走
```

每个档期还会按 `balance.gradeWeights` 抽一个**量级**（大事件/中事件/小事）：

| 压力 | 大事件 | 中事件 | 小事 |
|---|---|---|---|
| 0 | ~3% | ~23% | ~74% |
| 5 | ~21% | ~44% | ~34% |

**由此得到的实际节奏**：常态年约 4~8 个档期，危机年 10~13 个，平静的月份 4~8 个。

**内容作者要理解的三件事**：

1. **想表达"这一年很乱"** → 调 `era.pressure`，不要靠堆事件数量。压力会同时把「有没有事」「有几件」「有多大」三个维度顶上去。
2. **事件池的深度决定了日期自洽率**。引擎抽题是四级降级（先要「就是本月」→ 再要「没写月份」→ 再放开月份 → 最后放开去重窗口），池子越深，前两级越够用。
3. **大事件默认一局只演一次**（`unique` 缺省为 `true`）。所以大事件池会被消耗光，之后自动降级到中事件。**多写大事件**是唯一解法，或者给某个大事件写 `unique: false`。

## 1. era（时代锚点）

```js
POTUS.define("era", {
  "2008_CRASH": {
    name: "大空头 (2008)",     // 必填，显示名
    startYear: 2008,           // 必填，开局年份
    diff: "★★★★",             // 可选，难度标签
    intro: "……",               // 可选，建角页简介
    electionCycle: 2,          // 可选，选举年周期（默认取 balance.midtermCycle）
    outlets: ["纽约时报", "…"],  // 可选，新闻媒体池（makeNews 用）
    newsTpl: "【{outlet}】…",    // 可选，新闻模板；占位符 {outlet}{year}{name}{headline}
    brief: {                   // 年度世界简报；键为年份字符串，"*" 为兜底
      "2008": "次贷危机全面爆发……",
      "*": "危机之后的世界仍在震荡。"
    },

    // —— 节奏：这个时代有多动荡（0-6，见 §0.5）——
    pressure: { "2008": 5, "2009": 5, "2010": 3, "2012": 4, "*": 2 },
    // 也可以写成固定数字：pressure: 3
    // 或写成函数：      pressure: function (G, POTUS) { return G.year < 1964 ? 5 : 2; }

    // —— 时代脚本：到了某年某月必定发生（默认一局只演一次）——
    scheduled: [
      { event: "2008_crash_offer", year: 2008, month: 9, grade: "major" },
      { event: "1960_civil", month: 10, fromYear: 1963, toYear: 1963,
        grade: "major", cond: function (G) { return G.tier >= 1; } }
    ]
  }
});
```

### 1.1 scheduled（时代脚本 / 定点事件）

到了某年某月**必定**发生，用来把时代的关键节点钉死在日历上。

| 字段 | 必填 | 说明 |
|---|---|---|
| `event` | ✔ | 事件 id（必须存在于事件库中） |
| `year` | ✖ | 精确年份 |
| `month` | ✖ | 精确月份（1-12） |
| `fromYear` / `toYear` | ✖ | 年份区间（写到 so 时段内每年到点都可能触发） |
| `fromMonth` | ✖ | 区间起始年内，早于这个月不算 |
| `grade` | ✖ | 这个档期的量级，默认取事件自己的 grade |
| `once` | ✖ | 默认 `true`（一局只演一次）；写 `false` 则每年到点都演 |
| `cond` / `flags` | ✖ | 额外条件，不满足就跳过 |

> **定点事件仍要过一遍普通事件的触发条件**（tier / flag / era / 媒介年份 …），不满足就跳过。
> 所以「写给高层级玩家的定点事件」不会硬塞给还没爬到那个位置的人。

## 4. event（事件）

```js
POTUS.define("event", [{
  id: "2008_crash_offer",           // 必填，全局唯一
  era: ["2008_CRASH"],              // 必填，可多个时代共用
  title: "一份'救市'内部简报",        // 必填
  body: "……",                       // 必填，事件正文

  // —— 事件核心字段：类型 / 量级 / 三值性 / 经济模式（全部必填，见 §4.8 / §4.16）——
  grade: "major",                   // 必填：major 大事件 ／ mid 中事件 / minor 小事
  category: "crisis",               // 必填：事件类型（决定默认配图与配色）
  valence: "bane",                  // 必填：boon 机遇 / risk 风险 / bane 威胁（三值性，见 §4.16.1）
  dyn: true,                        // 必填：经济字段写系数而非绝对金额（见 §4.16.2）
  medium: ["tv", "social"],         // 可选：这件事要靠哪种"说话方式"才能发生
  unique: true,                     // 可选：一局只演一次（grade=major 时默认 true）

  weight: 14,                       // 可选，抽样权重（默认 10）
  filler: false,                    // 可选，标记为填充事件

  // —— 时间与背景（见 §4.6 / §4.7）——
  month: 9, day: 24,                // 可选，只在"历史上真钉在某个日子"时才写
  brief: { /* 主角视角的背景卡，见 §4.7 */ },

  // —— 触发条件（全部可选，全部满足才可能被抽中）——
  tierMin: 0, tierMax: 5,           // 层级区间
  fromYear: 2008, toYear: 2020,     // 年份窗口（也可写 years: [2008, 2020]）
  tracks: ["electoral"],            // 仅这些轨道可触发
  parties: ["D"],                   // 仅这些党派
  entries: ["celebrity"],           // 仅这些起点
  origins: ["labor"],               // 仅这些出身
  flags: ["someFlag"],              // 必须已拥有的标记（全部满足）
  notFlags: ["otherFlag"],          // 必须没有的标记（任一命中即排除）
  minRep: 25, minFun: 200000,       // 资源门槛
  minLev: 1,                        // 把柄门槛（手上至少有 1 份）
  contacts: ["fixer"],              // 人脉门槛：必须已认识（全部满足）
  minTenure: 24,                    // 在位时长门槛：在当前层级至少蹲够 24 个月
  after: { id: "archive_get",       // 事件链（见 §4.11）：前情必须已演过
           minMonthsAfter: 3, maxMonthsAfter: 30 },
  cond: function(G){ return true; },// 自定义条件（完全自由）

  choices: [ /* 见 §4.1 */ ]
}]);
```

**触发条件里最容易踩的三个坑，都在上面这一块**：`contacts`（人要认得）、`minTenure`（台阶要熬）、`after`（前情要演过）。它们各自在 §4.10 / §4.11 里展开。

```js
  base: 0.5,                        // 必填，基础胜算（0-1）
  mods: [ /* 修饰符，见 §5 */ ],

    ok:       { body: "…", effects: {…} },

```

```js
req: { tier: 3 }                       // 层级门槛
req: { track: "operative" }            // 指定轨道
req: { party: "D" }                    // 指定党派
```

### 4.3 cost（选项的资源代价）

**选这个选项要先付的钱/精力/人情/把柄。** 付不起时按钮置灰，提示"缺少资金/精力/人情/把柄"，玩家点不动。

```js
cost: { fun: 400000 }        // 花 $400k
cost: { ap: 2 }              // 花 2 点精力
cost: { fav: 1 }             // 花 1 点人情
cost: { lev: 1 }             // 花掉 1 份把柄（把柄是"份"，花掉就没了，不能欠）
cost: { fun: 120000, ap: 1 } // 可以组合
```

| 键 | 含义 | 单位 | 归零/上限 |
|---|---|---|---|
| `fun` | 资金 | 美元 | **允许为负**（负债是有戏剧性的，别拿它当硬墙） |
| `ap` | 精力 | 点 | 夹在 `[apMin, apMax]`，每年按健康恢复 |
| `fav` | 人情 | 点 | 夹在 `[0, 20]` |
| `lev` | **把柄** | 份 | 下限 0（**不能为负**：花掉就没了，没有"欠人一份把柄"这回事） |
| `rep` / `hp` | 声望 / 健康 | 点 | 可以作代价，但谨慎（易造成死亡螺旋） |

> **把柄（lev）是什么**：通过灰色手段拿到的"让某人不敢开口"的东西——一份人事档案、一盘录音带、一个编号。
> 它换不来钱，只能换来沉默和让步。它有三个特性，写内容时要一直记着：
> 1. **会贬值**：每一份把柄每年有 `balance.leverageDecayChance`（默认 0.34）的概率失效（当事人下台、事情过去了）。所以把柄不能当永久资产囤。
> 2. **会招祸**：手上满 `bonusPressure.leverageAt`（默认 3）份，活跃度会被顶上去（调查、传唤、约谈接踵而来）。
> 3. **不可投注**：把柄不在 `stake` 体系里。它是"代价"，不是"加码"。

设计建议：
- **代价要"肉疼但不致命"**。一个事件里最多 1~2 个选项带重代价。
- 代价与收益要成比例：花 $400k 的选项，成功率应明显高于免费的。
- 要表达"钱买不到的东西"，用 `fav` / `ap` 当代价，而不是把 `fun` 门槛抬到天上去。
- 高代价选项配合 `req` 使用效果最好（有钱也要有资格）。

#### 4.3.1 保底选项（强制，`validate.js` 会拦）

**每个事件至少要有一个既没有 `cost`、也没有 `req` 的选项。**

原因：玩家的钱会被事件花光、声望会被打下去。如果一个事件的**所有**选项都要钱（或都设了门槛），资源见底的玩家就会撞上「每一个按钮都点不动」的死局——游戏直接卡住，只能读档。

```js
// ✗ 会被校验器拦下：两个选项都要钱
choices: [
  { id: "prime", text: "押上全部资金买黄金时段", cost: { fun: 400000 }, … },
  { id: "late",  text: "只买得起凌晨档",         cost: { fun: 90000 },  … }
]

// ✓ 留一条不要钱的路
choices: [
  { id: "prime",  text: "押上全部资金买黄金时段", cost: { fun: 400000 }, … },
  { id: "late",   text: "只买得起凌晨档",         cost: { fun: 90000 },  … },
  { id: "earned", text: "一个子儿不花，去免费的地方露脸", base: 0.45, … }   // ← 保底
]
```

保底选项不是"白送的失败选项"，它应该**有真实的机会、也有真实的代价**，只是不用资源结算：
- 常见写法：拼体力（`hp`）、拼时间（低基础成功率）、拼人（说清失败后果）。
- 设计感：`base` 通常比付费选项低 0.05~0.15，用 `mods` 让属性好的角色也能翻盘。
- 它的存在本身也是叙事：**"没钱的人怎么办"**往往比"有钱怎么办"更有戏。

引擎侧仍有保险丝：`P.fallbackIndex(chs)` 会在**全部**选项都被堵死时强行放行一个（优先放行"只是资源不够"的那个），界面标注「⚠ 保底选项：…，硬撑一次」。但这是防止内容写漏把玩家关死，**不是**可以让内容偷懒的替身——校验器会直接把违规事件报出来。

### 4.4 stake（D&D 式"投入资源加码"）

**声明 stake 的选项，点击后会先弹出一个投注面板**，玩家自己决定往判定里砸多少资源，再掷骰。这是本作把"资源"变成"博弈"的核心机制。

```js
stake: { fun: true, ap: true, fav: true }   // 三种都能投，用全局默认汇率
stake: { fun: true }                        // 只能投钱
stake: { fun: { per: 500000, w: 0.06, cap: 0.3 }, ap: true }  // 单项自定义
```

| 资源 | 效果 | 默认汇率（`balance.stakeRates`） | 实际可投档数 |
|---|---|---|---|
| `fun` | 提高判定目标值 | **动态汇率**（每档金额随职级/事件量级算出，见 §4.16.3）→ `+4%`，上限 `+30%` | **最多 8 档** |
| `ap` | 提高判定目标值 | 每 `1` 点 → `+3%`，上限 `+9%` | **最多 3 点** |
| `fav` | **重投取优**（D&D 的 advantage，掷两次取好的那次） | 花 `1` 点换一次 | 开关式，1 点 |

单项自定义字段：

```js
{ per: 500000, w: 0.06, cap: 0.30 }   // per=每多少美元一档；w=每档加值；cap=该项总上限
```

规则与边界（引擎已实现，内容无需关心实现只看结论）：
- **可投档数被两道闸夹住**：`ceil(cap ÷ w)`（超过就没有收益了）和「你手上还剩多少」。所以精力上限 +9%、每点 +3% 时，**不管你有几点精力，都只能投 3 点**。引擎在扣款前再过一次这个闸，界面就算被改坏也不会多扣资源。
- **投注额自动被余额夹住**：钱不够就只能投到刚好花完，不会出现负数投注。
- **投不起时按钮置灰并说明原因**（"资金不足：每档需 $X，你现在只有 $Y"，X 由动态汇率算出），不会出现"点了没反应"。
- **到顶后先置灰再提示**："已达上限 +9%（最多 3 点）"。
- 目标值仍受 `clamp(…, 0.05, 0.95)` 限制，**狂投也突破不了 95%**。
- 玩家点"返回"不消耗任何资源；只有点"确认判定"才扣。
- 结算时玩家会看到完整的 D&D 明细：`d100 = 79（重投 79 / 92 取优） ／ 目标 48` + 每项修饰符拆分 + "已消耗：资金 $500k · 精力 2 · 人情 1"。

**写 stake 时必须自检的一步**：`cap ÷ w` 必须 ≥ 1。若 `cap` 比 `w` 还小，玩家投第一档就是纯亏——校验器会拦（`stake 上限还不到一档加成`）。可投档数 = `ceil(cap ÷ w)`，写文案时可以顺手算一下，别让上限"看起来能到 +30% 却永远吃不满"。

**什么时候该加 stake？**
- 这一注该由玩家自己决定押多大（赌一把 vs 稳着来）→ 加 `stake`。
- 这个选项就是固定代价、无可选择 → 只用 `cost`，不要加 `stake`。
- 想让"人情"这个资源有独特的战术价值 → 在关键判定上给 `fav: true`。

### 4.5 三者的分工（别混用）

| 字段 | 玩家体验 | 扣资源的时机 |
|---|---|---|
| `req` | 按钮置灰 +「需要 XX」，**根本选不了** | 不扣 |
| `cost` | 能选，按钮上写「代价：资金 $400k」，**没得商量** | 点下去就扣 |
| `stake` | 能选，先弹投注面板让玩家自己加码 | 点「确认判定」才扣 |

`req` 和 `cost` 都会让按钮置灰。因此**一个事件里的所有 `req` / `cost` 加起来不能把按钮全堵死**——必须留一个两者都没有的保底选项（见 §4.3.1）。这是硬性要求，校验器会拦。

### 4.6 month / day（只有"历史上真钉在某一天"才写）

```js
month: 9, day: 24      // 2008 年 9 月 24 日
month: 4               // 只写 month：只在这个月才可能被抽到
```

**规则变了：`month` 现在是稀缺资源，不是默认配置。**

在"一个月一回合"的模型里，引擎会把每个档期落到某个具体的月份上（可能是 3 月、7 月、11 月…），
所以一个写了 `month: 9` 的事件在 3 月是抽不到的。**只有真的钉在某个日子的史实事件才写 `month`。**

| 该写 month 的 | 不该写 month 的 |
|---|---|
| 雷曼那一周、电视辩论当晚、听证会传票送达 | 一次金主晚宴、一场越界的酒后、一次游说电话 |
| 选举日、报税日、历史上真实发生的那天 | 「某个季节里可能发生的日常政治」 |

**为什么日期很重要**：玩家可能知道主角不可能知道的事。例如「做空的次贷」钉在 **2008 年 3 月 12 日**——一个熟悉那段历史的玩家会立刻意识到，距离贝尔斯登崩盘只剩四天。日期就是这种信息的载体。

**写日期的规矩**：
- 有真实历史锚点的事件，**用真实日期**（1960 电视辩论 = 9/26；1974 年最高法院要求交出录音带 = 7/24）。
- 虚构事件**不要**写 `month`（或者干脆用 `era.scheduled` 把它钉在特定年月上）。
- **不要**在 `body` 里重复日期，引擎已经显示在顶部。

**引擎抽题时的四级降级**（内容不用管实现，但要知道后果）：
1. 先找「`month` 就等于当前月」的事件；
2. 其次找「没写 `month`」的常青事件；
3. 再次才允许月份不符（此时会尽量挑离当前月最近的）；
4. 最后放开「近期演过」的去重窗口。

所以 **`month` 写得越多，1、2 级越容易空，日期自洽率越低**。`tools/validate.js` 会打印「日期自洽率」，
它是**内容量的指标**：事件池越深，这个数字越接近 100%。当前 32 个事件时约 90%。

### 4.8 category / grade（事件类型与量级）

**每个事件必须声明 `grade` 和 `category`。** 这两个字段决定了三件事：
界面上的徽章、配图、以及"把内容派给不同的人写"时的分片依据。

```js
grade: "major"        // major 大事件 ／ mid 中事件 ／ minor 小事
category: "scandal"   // 类型 id，必须在 category 注册表里
```

| grade | 定位 | 缺省 unique | 建议占比 |
|---|---|---|---|
| `major` | 时代级的大事件，一局最多演一次 | `true` | 少量，把重量级内容放这里 |
| `mid` | 有分量的中事件，可以反复出现 | `false` | 主力 |
| `minor` | 日常小事、生活流、过场 | `false` | 大量，用来铺密度 |

内置的事件类型（定义在 `content/05-categories.js`）：

| id | 名称 | 用于 |
|---|---|---|
| `general` | 综合 | 没分类的兜底 |
| `career` | 仕途 | 晋升、选举、任命 |
| `political` | 党务 | 立法、党内博弈、游说 |
| `media` | 舆论 | 媒体、辩论、社交网络 |
| `crisis` | 危机 | 时代大事件、崩盘、黑天鹅 |
| `scandal` | 丑闻 | 调查、传票、曝光 |
| `finance` | 金钱 | 金主、献金、做空、基金会 |
| `romance` | 私情 | 越界、家庭、把柄 |
| `civil` | 民权 | 民权与社会运动 |
| `foreign` | 外交 | 外交与安全 |
| `shady` | 灰产 | 灰色生意、把柄、地下交易、族群飞地里的"能办成事的人" |

**时代专属 vs 跨时代通用**：事件的 `era` 数组如果短于时代总数，它就是**时代专属**的，抽取时权重会乘 `balance.eraWeightMul`（默认 3），保证"这个时代自己的故事"不被通用内容淹没。校验器会统计**时代专属事件的抽取占比**，按时代分别打印，并要求整体 ≥ 15%——**低于这个数不是引擎 bug，是内容缺口**：说明某个时代只剩几个大事件（而大事件 `unique` 一局只演一次），玩家在那条时间线上看到的全是通用内容。补法只有一个：给那个时代写**中事件和小事**。

**新增一个类型**（在 `content/05-categories.js` 里加一条即可，引擎自动接纳）：

```js
POTUS.define("category", {
  "labor": {
    name: "劳工", ink: "#4a5a2a", base: "#e6e9d6",   // 主色 / 底色
    art: function (ev, P, ctx) {                      // 返回 SVG 片段（120×120 坐标系）
      return P.artFrame(
        '<rect x="24" y="30" width="72" height="52" fill="' + ctx.ink + '" opacity=".5"/>' +
        ctx.caption(ev, ctx.ink),                     // 底部标题带，建议都加上
        ctx.ink, ctx.base);
    }
  }
});
```

- `art` 是**类型的默认配图**。具体事件想出自定义图，就在事件里写 `art(ev, P)`，优先级更高；两者都没有时引擎兜底。
- 配图是**程序化 SVG**，零外部图片、零依赖。想换成真图片，让 `art` 直接返回 `<img src="…">` 之类的 HTML 也行。
- 配图会被 `ev.art` → `category.art` → 引擎兜底 三级降级解析，所以**新写事件不用画图也有图**。

### 4.9 medium（时代媒介时间轴）

**让事件按年代自动生效 / 失效。** 声明 `medium` 后，引擎会查该媒介在这年存不存在，不存在就直接排除。

```js
medium: "tv"                  // 要有电视才可能发生
medium: ["tv", "internet"]    // 电视或互联网，有其一就行（"靠哪种都传得开"）
// 不写 = 任何年代都可能发生（报纸时代的常青政治）
```

媒介时间轴定义在 `content/06-media.js`：

| id | 名称 | from | 它给政治带来的变化 |
|---|---|---|---|
| `print` | 报纸 | 1700 | 一封信就能毁掉一个人 |
| `radio` | 广播 | 1920 | 声音直接进入客厅，不必靠集会 |
| `tv` | 电视 | 1948 | 形象压过文字 |
| `cable` | 有线电视 | 1980 | 舆论拆成两个世界 |
| `internet` | 互联网 | 1995 | 信息不再经过编辑部，也无人把关 |
| `social` | 社交媒体 | 2008 | 人人都成了发布者 |
| `shortvideo` | 短视频 | 2018 | 十五秒定生死，算法成了新的党鞭 |
| `deepfake` | 合成影像 | 2022 | 「眼见为实」失效 |

**这套机制最实用的两个用法**：

1. **给同一件事写多个年代版本**。`content/events/55-media-timeline.js` 就是范例：广播时代撞上「麦克风」，
   电视时代撞上「上镜」，2025 年才撞上「十五秒」和「假视频」。
2. **让大事件"等媒介成熟了再登场"**。给它一个较晚的 `medium` + `grade: "major"`，
   于是 1960 年开局的玩家永远遇不到它，2025 年开局才遇得到——不需要写任何逻辑。

`medium` 之外还可以用绝对年份卡窗口：

```js
fromYear: 1945, toYear: 1991     // 只在冷战期间
years: [1945, 1991]              // 同上，写法糖
```

> 引擎在年卡与月历卡上会显示**「此刻存在的媒介」**，玩家能一眼看见这个年代的舆论环境。
> 新增媒介只需在 `content/06-media.js` 加一条（`from` 必填，`note` 会被展示给玩家）。

### 4.10 contact（人脉登记表）

**一个事件里写「你去找他」很容易，难的是让同一个"他"在十年后再次出现，并且记得上次你欠了他什么。** 人脉表解决的就是这件事。

**先登记，再引用。**（登记表在 `content/07-contacts.js`）

```js
POTUS.define("contact", {
  fixer: {
    name: "老雷", role: "掮客", tag: "门路",
    note: "没人说得清他到底替谁工作。他不解决问题，他介绍解决问题的人。"
  }
});
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✓ | 界面显示的名字（人脉面板、`req.contact` 的提示文案都用它） |
| `role` |  | 一句话身份，显示在名字右边 |
| `tag` |  | 分类短标签（"门路" / "钱" / "街头" …） |
| `note` |  | 给内容作者看的设定说明，不会显示给玩家 |

**在事件里怎么用**：

```js
// 选项门槛：不认识就点不动，且会告诉玩家"需要先认识「老雷」"
{ id: "ask", text: "让老雷替你牵一根线", req: { contact: "fixer" }, … }

// 事件级门槛：先认识，这件事才会发生
{ id: "deep_favor", contacts: ["fixer", "lobbyist"], … }   // 两个都要认识

// 好感变化：第一次出现就代表"从此认识"（从 0 起算，并自动登记进存档）
effects: { contact: { fixer: 12 } }       // +12
effects: { contact: { shark: -8 } }       // 得罪了也算认识
effects: { forget: ["fixer"] }            // 彻底断掉（你把他卖了，或者他死了）
```

**好感度语义**（夹在 `-100 ~ 100`，和派系好感同一套口径）：

| 区间 | 含义 |
|---|---|
| 30+ | 可以开口求一件难事 |
| 10 ~ 29 | 平时能办事 |
| 0 ~ 9 | 只是点头之交 |
| -1 ~ -19 | 需要先修关系 |
| -20 以下 | 他会主动坏你的事 |

**写人物时的三条约定**：
1. **一个人只负责一类资源**。找钱的别来找他要选票，要选票的别来找他借钱。
2. **人物不写死年代**——他们的"位置"在任何年代都存在（1960 年的电视制作人与 2008 年的电视制作人是同一个人设）。需要限定年代时写在**事件**上，不写在人物上。
3. **`content` 里提到的人，登记表里必须有**。校验器会逐条核对 `ev.contacts` / `req.contact` / `effects.contact` / `effects.forget` 里出现的每一个 id。

### 4.11 事件链（`ev.after`）：让一个故事横跨数月甚至数年

**这是"事件和流程太短"这个问题的正解。** 普通事件是"一个月里的一件事"；事件链是"一件事在几个月里长成另一个样子"。

```js
// 第一幕（头）：正常写，但要 unique: true
{ id: "archive_get", grade: "mid", unique: true, … }

// 第二幕：前情必须已演过，且间隔落在窗口内
{
  id: "archive_bite", grade: "mid", unique: true,
  flags: ["archive_taken"],                       // 只在"把档案带走了"这条岔路上继续
  after: { id: "archive_get", minMonthsAfter: 3, maxMonthsAfter: 30 },
  …
}
```

引擎会自动做三件事（`engine/events.js` 的 `P.eligible`）：

| 行为 | 规则 |
|---|---|
| 前情没演过 | `monthsSince(prev) == null` → **直接不可触发**（不是权重降低，是整个事件不存在） |
| 间隔不在窗口 | `minMonthsAfter` / `maxMonthsAfter` 是**月**，不是年。太早不像故事，太晚像巧合 |
| 前情演过 | 该事件权重 × `balance.chainWeightMul`（默认 9），所以它几乎一定会来，只是隔几个月才来 |

**界面上会出现一条「承 前」小条**，写着上一幕的标题和相隔几个月——让玩家明白这不是一堆随机事件，而是一件还没完的事。

**写链的四个坑（每个都会让链条穿帮）**：

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 忘了 `unique: true` | 同一幕会重复出现 | 链上每一幕都写 `unique: true`（`grade: "major"` 默认已是 true，其余要显式写） |
| 用 `flags` 当"前情" | 玩家没拿到那个 flag 时链就断了，而且看不出来为什么 | 用 `after` 表前情，用 `flags` 表**岔路**（"有没有把东西带走"） |
| 最后一幕不分岔 | 前面怎么选，结尾都一样 | 最后一幕用 `req: { flag: "…" }` 分支，并且**每一幕的每一个选择、每一档结果都要打上同一个标记** |
| 忘了保底选项 | 分支一多，很容易所有选项都带 `req` | 分岔之外永远留一条既无 `cost` 又无 `req` 的路（见 §4.3.1） |

样板实现：`content/events/84-archive.js`（四幕：拿到 → 被反噬 → 摊牌 → 了结，最后一幕按 `req.flag` 读出四种完全不同的收尾）。

### 4.12 minTenure：晋升要熬够月份

`ev.minTenure`（单位：**月**）要求玩家在当前层级至少待够这么久，才会出现该事件。

```js
{ id: "prog_senate", grade: "major", minTenure: 48, … }   // 在 T3 待满 4 年才谈得上去参议院
```

- 层级一变（`effects.tier`），在位计时**自动重置**（引擎侧）。
- 状态面板会显示「在位 X 个月」，玩家看得见自己离下一级还有多远。
- 这条是"一局太短"的第二根柱子：**光有事件不够，台阶本身也要花时间**。
- 取值：基层/州级 18~24；参议院/总统 48；任命/造王者/巨富 18；名人 12。
- 所有 `prog_*` 晋升事件都必须声明 `minTenure`——校验器会拦。

### 4.7 brief（背景卡：主角视角的认知边界）

事件最容易犯的错，是把玩家直接丢进一个他完全看不懂的局面——"什么是救市？为什么要救市？谁发动的？" **每个事件都应该交代主角此刻能看见什么、以及他看不见什么。**

```js
brief: {
  lede: "财政部深夜来电。你要在四个小时里，替一场你还没搞懂的事背书。",  // 可选，折叠时显示的一行
  known:   ["你确知的客观事实……"],          // 主角视角能看到、能理解、能核实的
  rumor:   ["你听到的、真假不明的话……"],    // 传闻：可能真、可能假、可能被人故意放出来
  unknown: ["你不知道的事……"],              // 认知边界：明确告诉玩家"这里有信息差"
  terms:   [{ k: "救市", v: "把名词讲清楚" }] // 名词表：给不熟悉时代背景的玩家
}
```

四块的定位，缺一块就少一层：

| 块 | 作用 | 写作要点 |
|---|---|---|
| `known` | 玩家做判断的**事实基础** | 写"主角视角能看到的"：他读到的数字、他认识的人、他手上的文件。**不要写成上帝视角的历史总结。** |
| `rumor` | **制造不确定性** | 用「有人说…」「有律师朋友在饭局上说…」。真假不明，其中可能有对手放的假消息。不要标注哪条是真的。 |
| `unknown` | **点明信息差** | 这是本机制的灵魂。写主角意识不到后果的地方，等价于对玩家说："你知道这段历史的话，这里可以占便宜。" |
| `terms` | **降低门槛** | 只解释名词（救市、TARP、初选、弹劾条款），**不解释剧情**。不熟悉这段历史的玩家也能跟上。 |

**三条硬规矩**：

1. **`known` 不能剧透**。主角不知道的事，就不许写进 `known`。想让玩家知道，放进 `terms` 或让他自己去联想。
2. **`unknown` 必须真的"不知道"，不能是"未来会怎样"的流水账**。写法是点出**后果的位置**，不是点出后果本身。
   - 好：`你读不懂的那几条授权条款，将来会成为对手手里的刀。`
   - 差：`两个月后国会会否决这个法案，你会因此丢掉席位。`（这是剧透，不是信息差）
3. **`rumor` 里可以埋真话，也可以埋假话**，但**不要用语气暗示真假**。让玩家自己赌。

**什么时候可以不写 brief？** 只有一种情况：事件本身就是纯机制演示、没有叙事场景。除此之外（包括跨时代通用的晋升链）都应该写。

### 4.13 vignette（静好岁月：平静月份的随笔与成长）

一个月的回合制里，**一年有 8 个月左右是"平静"的**（没有档期、没有事件）。原本它们只在月历条上留一行「平静」二字。
`vignette` 就是那些月份的内容：给主角一段**日子**，并且让他在这些日子里**按部就班地长**。

```js
POTUS.define("vignette", {
  title: "静好岁月",              // 卡片标题（可选，默认「静好岁月」）
  lede: "没有大事发生的月份。",     // 卡片副题（可选）
  fragments: [ /* 片段，见下 */ ]   // 可多次 define，fragments 会累加
});
```

#### 一个片段

```js
{
  id: "se03",              // 唯一（校验器查重）
  slot: "season",           // 必填，见下面的槽位表
  months: [3],              // 只有 3 月能用（时令片段用）
  texts: [                  // 随机挑一句 —— 同一个处境给几种写法，素材量翻倍
    "三月。雪化得比往年早，路上的泥一踩一陷，风里有股湿土的味道。",
    "三月，树还是光的，但那种光已经不同了——你知道它底下正在动。"
  ],
  // text: "…"              // 只写一句时可以用 text 代替 texts
  weight: 1,                // 同槽位内的相对权重，默认 1
  brk: false                // true = 这一段前面断开（另起一段）
}
```

#### 六个槽位（顺序固定，引擎每个槽位抽一条，按顺序接起来）

| slot | 意思 | 该写什么 |
|---|---|---|
| `season` | 时令 | 跟着月份走：三月化雪、七月暑气、十二月橱窗亮起来。**必须覆盖 12 个月** |
| `world` | 世相 | 这个年代的人靠什么知道世界：报纸/电视/电台/手机/邮件/加油站的队伍 |
| `work` | 案头 | 他每天在干什么（按轨道 + 层级分） |
| `life` | 日常 | 家、身体、朋友。**建议 `brk: true`**，让它另起一段 |
| `self` | 心绪 | 由当前处境决定：病了、手里有把柄、名声在外、年岁渐长 |
| `close` | 收束 | 一句余味。**建议 `brk: true`**，让它自己收尾 |

#### 片段的条件（全部可选，可组合）

| 字段 | 含义 |
|---|---|
| `era` / `notEra` | 时代 id 数组 |
| `tracks` / `parties` / `stances` / `origins` | 对应注册表的 id 数组 |
| `tiers` / `minTier` / `maxTier` | 权力层级 |
| `minAge` / `maxAge` | 年龄 |
| `months` | 月号数组（1-12），时令片段用 |
| `flags` / `notFlags` | 状态标记 |
| `minLev` / `maxLev` | 把柄份数 |
| `minRep` / `maxRep` | 声望 |
| `minHp` / `maxHp` | 健康 |
| `minFun` / `maxFun` | 资金 |
| `minContacts` / `maxContacts` | 认识的人数 |
| `cond(G, P)` | 自由判定，返回 true 才可用 |

#### 硬性要求（`validate.js` 会拦）

1. **时令必须覆盖 12 个月** —— 否则某个月的随笔会缺掉开头。
2. **除 `season` 外，每个槽位至少要有一条"无条件片段"**（不写任何条件字段）。
   理由：玩家可能同时病重、破产、被调查、年迈——条件写满了，反而一段都抽不出来。
3. `slot` 必须是上面六个之一；`text`/`texts` 不能空；`id` 唯一；`weight` 为正数；
   引用的 era / track / stance 必须存在。
4. 校验器还会跑遍 **时代 × 轨道 × 层级 × 月份** 的全部组合（3×5×6×12），以及 9 种极端处境（病重/穷困/巨富/丑闻/把柄/垂暮…），
   任意一种拼不出文字都会报错。

#### 成长曲线（`balance.vignette`）

叙事之外，平静的月份还会让主角"按部就班地长"。**数字不在内容片段里，统一在 `balance.vignette`**：

| 键 | 默认 | 含义 |
|---|---|---|
| `enabled` | `true` | 关掉就完全没有随笔与成长 |
| `maxShown` | `4` | 一次最多展开几段（更久的平静收成一句「另有 N 个月」） |
| `attrChance` / `attrGain` / `attrCap` | `0.14` / `1` / `88` | 每个平静月长属性的概率与上限 |
| `attrKeys` | `["CHA","INT","CUN","INTG"]` | 哪些属性会长（**轨道对应的主属性权重 ×3**） |
| `attrAgeFade` | `true` | 越老越长不动：`×(1 - 已从政年数/60)`，下限 0.25 |
| `hpChance` / `hpGain` | `0` / `1` | 平静月恢复健康的机会。**默认 0，是个刻意的选择，见下** |
| `repChance` / `repGain` | `0.06` / `1` | 常年露面攒下的一点名声 |
| `contactChance` / `contactGain` | `0.20` / `1` | 关系要维护：随机一位人脉好感 +1 |
| `funRate` | `0` | 平静月的资金生息（默认放在年终结算） |

> **`hpChance` 为什么默认是 0**：这个游戏的死亡率正好卡在退休年龄那条线上（年度衰减约 2 点，100 点撑 50 年），
> 所以平静月只要回一点点健康，就会把一大批"累死"翻成"退休"。
> 实测（`validate.js` 的 300 局结局分布）：`0.00` → 因病去世 ~111-126；`0.04` → 48；`0.28` → 0。
> 想要"平静的月份让人喘口气"的手感，就调到 `0.04`，但要知道整个终局会明显变温和。

#### 三个坑

1. **不要在片段里写具体数值**（「你涨了 3 点声望」）。数值由 `balance.vignette` 统一结算，片段只负责画面。
2. **时代准确性**：1960 年不能出现手机、短视频、网络。校验器不会拦这个（它读不懂文学），靠你自己把关；
   不过接了大模型之后，`P.llm.stateBrief()` 会把"这个年代还不存在的媒介"列进 prompt 里替你兜一道。
3. **不要把"事件"写进随笔**。平静月之所以是平静月，就是因为它没有转折。写成小高潮，就等于把事件的活儿干了两遍。

**样板文件**：`content/08-vignettes.js`（65 条片段，时令 12 个月全覆盖）。

## 4.14 大模型适配层（可选，`engine/llm.js`）

引擎内置一层**完全可选**的大模型适配，用来给「静好岁月」的随笔**润色**或**另写一段**。
它和内容契约的关系只有一条：**它读得到游戏状态，但内容永远不依赖它。**

三条铁律：

1. **离线优先**：引擎先把模板文本拼好、先渲染出来。模型回来了才替换；模型不回、超时、报错、被墙 —— 玩家看到的仍是一段完整的话。
2. **绝不抛错、绝不阻塞**：任何失败都消化成界面上一句提示。
3. **密钥不进代码**：`endpoint` / `model` / `apiKey` 全部存在玩家自己的 `localStorage`（键 `potus_llm`），仓库里不存任何凭据。

| 接口 | 说明 |
|---|---|
| `P.llm.config()` / `setConfig(patch)` / `clearConfig()` | 读写配置 |
| `P.llm.ready()` | 是否可用（`enabled` 且地址以 http 开头）。**没配好时调用方一律走本地模板** |
| `P.llm.stateBrief(extra?)` | 把当前局面写成人话（含"这个年代还不存在的媒介"），供 prompt 使用 |
| `P.llm.buildPrompt(kind, ctx)` | **纯函数**，返回 `{system, user}`。`kind`: `"vignette_polish"` / `"vignette_fresh"` |
| `P.llm.cacheKey(kind, ctx)` | 按 prompt 内容取哈希 —— 同样的局面不重复花钱 |
| `P.llm.request(kind, ctx, cb)` | 发请求。返回 `"cache"` / `"sent"` / `null`；`cb(text, err)` 二者必有其一是 null |
| `P.llm.extractText(data)` | 兼容 OpenAI chat / Responses / Anthropic / Gemini 几种返回形状 |
| `P.llm.left()` / `cap()` / `used()` | 本局额度（受 `balance.aiCallCap` 限制） |
| `P.llm.putCache(k, v)` / `cacheSize()` / `clearCache()` | 缓存（上限 60 条，按写入时间淘汰） |

**关于跨域**：浏览器 `fetch` 会带 `Origin`，多数厂商接口不会给 `file://` 放行。这不是 bug。
用 `python3 -m http.server` 打开，或者在设置里填一个自己搭的转发地址。

## 4.15 photo（事件配图的照片层）

引擎的配图是**三级降级**的（`engine/art.js` 的 `P.artSVG`）：

```
1) 内容级渲染器（POTUS.art(fn) 注册）   ← 照片层挂在这里，最优先
2) 事件自带的 ev.art
3) 事件类型 category 的默认图（程序化 SVG，见 §4.8）
4) 引擎内置兜底（永远有图）
```

照片层的实现是 `content/09-photo-art.js`，它只做一件事：**能给照片就给照片，给不了就 `return null`**，
让下面三层照常工作。所以「有照片」「没照片」「照片挂了」三种情况都不会白屏。

### 登记表

```js
POTUS.define("photo", {
  dir: "assets/events/",                  // 相对 index.html；多次调用时后写的覆盖它
  files: {
    career: "career.jpg",                 // 类型 key → 文件名；多次调用会逐条合并
    scandal: "scandal.jpg"
    // …没登记的类型 = 走程序化 SVG
  }
});
```

| 字段 | 说明 |
|---|---|
| `dir` | 图片目录，相对 `index.html`。默认 `assets/events/` |
| `files` | `{ 类型key: 文件名 }`。key 必须是 `reg.category` 里真实存在的类型，否则照片永远轮不到 |

### 单个事件覆盖 / 关闭

| 写法 | 效果 |
|---|---|
| `ev.photo = "my-shot.jpg"` | 这个事件用指定图片（文件名相对 `dir`） |
| `ev.photo = false` | 这个事件不要照片，走程序化 SVG |

### 三条硬规矩

1. **文件名由登记表给，代码里不硬编码路径** —— 换图只要把新图命名成 `<类型 key>.jpg` 覆盖同名文件。
2. **每张照片卡里都预垫了一张"本来会画的"程序化 SVG**（`.art-back`）。图片加载失败时 `onerror`
   把它翻出来顶上，玩家不会看到破图。这条是为了兜住「只拷了部分文件」「改了文件名」这类事故。
3. **照片层坏掉不能连累配图**：整段逻辑包在 `try` 里，抛异常就退回 SVG。

### 尺寸与配色

- 卡片正文列宽约 636px（`#app` 980px、`.grid` 1fr+260px、`.news` 内边距 16px）。
  照片压到**最大边 900px / JPEG q78** 就够（1x 清晰、2x 不糊），十张合计约 860 KB。
- 画框是 `aspect-ratio:16/9` + `max-height:260px` + `object-fit:cover`，所以**原图比例不必统一**，
  但主体尽量居中，否则会被裁掉。
- 卡片上会压一层时代主色（`--era1`）的淡色罩，让照片和报纸版式同一个调子；左下角有类型角标。

### 怎么验收

- `node tools/validate.js` 会**逐个检查登记的照片文件在不在于磁盘上**（这是最容易静默翻车的地方），
  并断言「有照片出 `<img>`、没照片退回 SVG、`ev.photo` 覆盖与关闭都生效」。
- `node tools/smoke-ui.js` 会真的渲染事件卡，断言 `.art-photo` / `<img src>` / 角标 / `.art-back` 垫片，
  并**派发一次 `error` 事件**验证破图态会切换。
- 要看照片在卡片里的实际观感（不真开局）：浏览器打开 `tools/preview-photos.html`。

### 4.16 valence / dyn：三值性与动态经济（v0.6+，每张卡必填）

这是本项目最核心的两条契约。**每张事件卡都必须显式声明 `valence` 和 `dyn`。** 它们一起实现了整部作品的设计哲学——**同一件事，对不同处境的人，意义完全不同。**

#### 4.16.1 valence（三值性：机遇 / 风险 / 威胁）

每张卡属于三种"情绪基调"之一。抽取时**每个档期独立掷一类**（两段式：先掷三值性，再在该类池里按量级抽卡），类与类互不挤占——有了好运不会挡掉坏事。

| valence | 徽标 | 语义 | 引擎保证（`shapeByValence` 强制） |
|---|---|---|---|
| `boon` | 🟢 机遇 | 净收益是**下限** | 删掉所有 `cost`、抬升 `base`、把每一档结果里的**负值抹平为 0**——掷骰最差也只是"少赚"，绝不转盈为亏。 |
| `risk` | 🟡 风险 | 保底或博一下 | 缺保底时**自动注入**一条无风险退路；波动幅度可以很大。 |
| `bane` | 🔴 威胁 | 默认净损 | **保持原样**——但靠高掷骰 / 高属性 / 花钱仍可规避，甚至"化险为夷"。 |

- **内容侧只写"意图"，契约由引擎在结算层（`engine/scale.js` 的 `shapeByValence`）强制执行**——所以不用担心 boon 卡里手滑写了一个负数会破坏契约。
- 漏标 `valence` 时按 `balance.valenceDefault`（默认 `risk`）兜底；校验器 `--val-strict` 会把漏标判为错误。
- 掷三值性的权重见 `balance.valenceWeights` / `valencePressure`（§10）。该类池空时按 `VAL_CHAIN` 优雅降级（优先降级到 risk 当缓冲垫），不会崩——但代价是"掷中机遇却被静默降级"，所以**每个时代都要有 boon 卡**。

#### 4.16.2 dyn（动态经济：卡只存系数，结算时 × 人物标尺）

声明 `dyn: true` 的卡，其 `effects` 里的 `fun` / `rep` / `hp`（以及 `cost` 里的 `fun`）都是**系数**，不是绝对金额。抽中这张卡的瞬间，引擎调用 `P.realize(ev)` 把系数翻译成"此刻这个人物"应得的绝对值副本。

```
钱的标尺 fun = 职位月薪 officeSalary × funMonths[grade] × 属性系数 × 职级系数
声望的标尺 rep = repBase[grade] × (1 + tierLean × 层级偏离)
健康的标尺 hp  = hpBase[grade]  × (1 + hpTierLean × 层级偏离)
```

于是**同一句"赚 0.5 份钱"，社区小兵拿到是几千块，州长拿到是几十万**——经济的"体感通胀"随生涯自动缩放，而内容只需维护一份系数。

系数合法区间由 `balance.econ` 校验：`fun` / `rep` / `hp` 等资源系数在 `[coefMin, coefMax]`（默认 `[-8, 8]`）；`money` 单独放宽到 `coefMaxFun`（默认 150，因为大额贿金/收购对低标尺天然上百份）。参数明细见 §10 的 `econ` 行。

> 迁移：把一批写死绝对金额的旧卡转成系数，用 `dev/tools/migrate-scale.js`；改 `econ` 参数会平移全局经济曲线，**改完必须重跑 `validate.js`**。

#### 4.16.3 动态投注汇率（`stakeRates.fun`）

投注（§4.4）里"钱"这一档的金额也是动态的，避免"为 $50k 收益去掏 $250k"的荒诞：

```
每档金额 per = min( √(身位锚 A × 事件锚 X), X )
  身位锚 A = officeSalary × perSalaryMonths(默认 3) × gradeMul[人物的事件量级]
  事件锚 X = stakePot × potShare(默认 0.25)      ← 这笔投注最多吃到事件收益的四分之一
```

档位仍由 `cap ÷ w`（默认 `0.30 ÷ 0.04` = 8 档）决定，只是**每档是多少钱随人物和事件浮动**。不变量：8 档总投入永远 ≤ 2 × 事件钱量级。`perMin` / `perMax` 给绝对兜底夹逼，防止标尺极端时出现"每档一毛钱"或"每档五百万"。内容写死 `per` 时以内容为准（绝对覆盖，不参与换算）。

#### 4.16.4 三层状态感知（把"一切结合人物属性"落到机制上）

设计哲学的完整落地是三层判定，写卡时对应到三个字段族：

| 问题 | 引擎机制 | 你要写的字段 |
|---|---|---|
| **这件事该不该发生？** | `engine/when.js` 声明式条件 | `era` / `tierMin` / `minFun` / `flags` / `after` / `scandalMin` / `contacts` / `minTenure` …（见 §4） |
| **这个选项该不该让他选？** | `render.js` 的 `reqBlock`/`costBlock` 把不够格/付不起的选项**置灰并写明原因** + `fallbackIndex` 保底 | 选项上的 `req` / `cost`（见 §4.2 / §4.3） |
| **该花多大代价、换多大收益？** | `scale.js` 标尺 + `stakeFunPer` 汇率 | `dyn` 系数 + `stake`（见 §4.4 / §4.16.2 / §4.16.3） |

一句话：**你只管把"意图 + 系数 + 门槛"写清楚，"此刻对这个人意味着多少钱、能不能选"交给引擎。**

## 5. mods（胜算修饰符）
每个修饰符是一条 `{ src, key, w, ... }`。命中则把 `w` 折算进胜算。

| src | 语义 | 需要的字段 | 计算公式 |
|---|---|---|---|
| `"attr"` | 属性 | `key`(CHA/INT/CUN/INTG), `w`(默认 0.6) | `(属性-50)/100 × w` |
| `"fac"` | 派系好感 | `key`(派系 id), `w`(默认 0.3) | `好感/100 × w` |
| `"flag"` | 状态标记 | `key`, `w` | 命中则 `+w` |
| `"talent"` | 天赋 | `key`(天赋 id), `w` | 命中则 `+w` |
| `"track"` | 轨道 | `key`, `w` | 命中则 `+w` |
| `"party"` | 党派 | `key`, `w` | 命中则 `+w` |
| `"stance"` | 姿态 | `key`, `w` | 命中则 `+w` |
| `"tier"` | 层级 | `w`(每层加值) | `层级 × w` |
| `"res"` | 资源 | `key:"fun"`, `min`, `w` | 资金 ≥ min 时 `+w` |

最终：`P = clamp(base + Σmods + 天赋全局mods, 0.05, 0.95)`
玩家只会看到**模糊档位**（渺茫/不利/五五开/有利/稳操胜券/几乎必胜），不显示精确概率。

## 6. effects（后果）

```js
effects: { attr:{CHA:5}, fac:{base:10,press:-8}, fun:400000, rep:6, hp:-3, ap:1, fav:-1, lev:-1, tier:1,
           contact:{fixer:12}, forget:["shark"],
           score:5, flags:["whistleblower"], notFlags:["bailout_stain"] }
```

> **当 `dyn: true`（现在所有卡的默认）时**，下表里的 `fun` / `rep` / `hp`（以及 `cost` 里的 `fun`）不是绝对金额/点数，而是**系数**——引擎在抽中这张卡的瞬间，用当前人物的"标尺"把它翻译成绝对值（见 §4.16.2）。`attr` / `fac` / `ap` / `fav` / `lev` / `tier` / `contact` 等仍是字面数值。

| 键 | 语义 | 范围 |
|---|---|---|
| `attr` | 属性增减 | 0-100 |
| `fac` | 派系好感增减 | -100~100 |
| `fun` | 资金增减（美元，可为负） | — |
| `rep` | 声望增减 | 0-100 |
| `hp` | 健康增减 | 0-100（归零 = 死亡结局） |
| `ap` | 精力增减 | 0-12 |
| `fav` | 人情点增减 | 0-20 |
| `lev` | **把柄份数增减** | 下限 0（可为负 = 花掉一份，但不会变成负数） |
| `contact` | **人脉好感增减**（`{id: 数字}`，首次出现即"从此认识"） | -100~100 |
| `forget` | **彻底断掉一段关系**（`["id"]` 或 `"id"`） | — |
| `tier` | 层级升降（变动会把"在位时长"重置） | `balance.tierMin~tierMax` |
| `score` | 自定义累计分（供结局条件用） | — |
| `flags` | 增加状态标记 | — |
| `notFlags` | 移除状态标记 | — |

**把柄的"得到"和"花掉"是两种不同的写法**：
- **花掉**：用 `cost: { lev: 1 }`（付不起就点不动，玩家看得见代价）。这比在 effects 里写 `lev:-1` 准确 —— 后者在每一档结果里都得重复，容易漏。
- **得到**：写在 `effects` 里（`lev: 1`），通常只在成功档给，失败档不给 —— 用"把柄没拿到"来惩罚失败。

**自定义效果键**（内容团队可自行扩展，无需改引擎）：

```js
POTUS.define("effect", {
  legacy: function (v, G) { G.legacy = (G.legacy || 0) + v; }   // v 为该键的值，G 为存档状态
});
// 之后效果里就能写 effects: { legacy: 10 }
```

> 用未注册的键会打印警告但不报错——这是有意设计，方便先写内容后补注册。

## 7. ending（结局规则，声明式）

引擎按 `priority` 从高到低取**第一条命中**的规则。

```js
POTUS.define("ending", [{
  id: "retire_kingmaker",
  priority: 85,                          // 越大越优先
  when: { /* 条件，全部可选；空对象 = 永远命中（做兜底） */
    reason: "retire",                    // 触发原因：president|prison|death_health|retire|default
    flags: ["owns_media"],               // 必须全部拥有
    notFlags: ["scandal_4"],             // 必须全部没有
    tierMin: 4, tierMax: 5,
    trackIn: ["operative"], partyIn:["D"], entryIn:["celebrity"],
    scandalMin: 3, ageMin: 70, ageMax: 90, funMin: 1000000, repMin: 60,
    cond: function(G){ return true; }    // 自定义条件
  },
  title: "从不参选的人",
  grade: "S",                            // S/A/B/C/D/F
  body: "支持 {age} {tier} {track} 占位符；也可写成 function(G, POTUS){ return "..."; }"
}]);
```

`reason` 的取值由引擎在终局时给出：
- `president`：层级达到 `balance.tierMax` 且首次触发
- `prison`：拥有 `prison` 或 `scandal_5` 标记
- `death_health`：健康 ≤ 0
- `retire`：年龄 ≥ `balance.retireAge`

## 8. filler（填充模板）

事件池抽空时使用，保证**事件永不枯竭**。两种写法：

**声明式**
```js
POTUS.define("filler", {
  "2008_CRASH": {
    topics: ["一场市政债违约", "…"],       // 标题池
    acts:   ["你被卷进", "媒体追问："],     // 前缀池
    bodyTpl: "{act}{topic}。你必须在聚光灯下做出选择。",
    choices: [ /* 与事件 choice 同构，五档结果必须齐全 */ ]
  },
  "*": { /* 全时代兜底包 */ }
});
```

**函数式**（完全自由）
```js
POTUS.define("filler", {
  "2016_POPULIST": function (P, G) {
    return { id:"…", era:["2016_POPULIST"], title:"…", body:"…", choices:[…] };
  }
});
```

## 11. 事件写作规范（强制）

1. **多行格式**。每个选项的 `outcomes` 独占一块，五档逐行排列：
   ```js
   { id:"x", text:"…", base:0.5, mods:[…],
     outcomes:{
       crit:{ body:"…", effects:{…} },
       ok:{ body:"…", effects:{…} },
       meh:{ body:"…", effects:{…} },
       fail:{ body:"…", effects:{…} },
       critfail:{ body:"…", effects:{…} }
     }
   },
   ```
   **不要**把整个选项压成一行手数括号——本项目历史上最大的坑就是单行紧凑写法导致的括号失衡。
2. **文本一律用 ASCII 双引号 `"` 作为字符串定界**；正文里要强调某个词时，用全角引号 `「」`，**绝不要**在字符串内部再写 ASCII 双引号（会直接语法报错）。这是本项目第二大的坑。
3. **不要写逻辑**。事件里不写 `if`/循环/副作用；需要特殊判断用 `cond(G)`。
4. **id 全局唯一**，建议前缀用时代或支线名（`2008_`、`prog_`、`affair_`）。
5. 模板可以直接内联在事件里（`templates:` 字段）——见下一节扩展点。
6. **每个事件都要有 `brief`、`grade`、`category`、`valence`、`dyn`**（见 §4.7 / §4.8 / §4.16）。经济字段一律写**系数**（配 `dyn: true`），不写绝对金额。这是可玩性与分工的底线：
   - 玩家不该被丢进一个连"发生了什么、谁在推动"都看不懂的局面；
   - 玩家也不该在 `brief` 里读到主角不可能知道的东西；
   - 没有 `grade` / `category`，界面就没有量级徽章和配图，也没法按类型分工。
   校验脚本会对三者逐个检查，缺一个直接判失败。
7. **`month` 只在史实锚点上写**（见 §4.6）。写了 `month` 的事件在那个月之外抽不到，写多了会让事件池变浅。
8. **`known` 是主角视角，不是上帝视角**。写之前先问一句：**这一刻，他手上有哪些纸、见过哪些人、听过哪些话？** 只写这些。
9. **`unknown` 要写"后果的位置"，不是"后果本身"**。它存在的意义是让懂历史的玩家知道"这里可以占便宜"，而不是替他做决定。
10. **日期要对得上历史**。有真实锚点就用真实日期；这不只是装饰，是给玩家的信息。
11. **年代不对的事不要写**。1910 年没人发推文，1960 年没有热搜，2010 年没有短视频。
    如果这个事件依赖某种媒介，写上 `medium`（见 §4.9），让引擎按年份自动放行——
    **不要**用 `fromYear` 硬编码一大堆年份窗口，那是引擎该做的事。
12. **每个事件必须留一个保底选项**：既没有 `cost`、也没有 `req` 的那个（见 §4.3.1）。
    否则玩家钱花光 / 声望被打下去之后，会撞上"所有选项都点不动"的死局。
    校验脚本会逐个检查，`validate.js` 直接判失败。
13. **写 `stake` 时核对 `cap ÷ w ≥ 1`**，并算一下可投档数 `ceil(cap ÷ w)` 是否和你在文案里
    承诺的上限对得上（见 §4.4）。上限比一档还小的投注是"花钱买 0"，校验器会拦。
14. **提到一个人，就必须先在 `content/07-contacts.js` 里登记他**（见 §4.10）。
    `ev.contacts` / `req.contact` / `effects.contact` / `effects.forget` 里的每一个 id 都会被逐条核对：
    id 不一致是最典型的"内容团队自己踩自己的坑"——文案里写着"老雷"，代码里写着 `broker`，接口就跑不通。
15. **链上的每一幕都要 `unique: true`，并且用 `after` 表前情、用 `flags` 表岔路**（见 §4.11）。
    顺序写错会让故事要么重复演，要么悄悄断掉。
16. **把柄（`lev`）用来"花"，不用来"囤"**（见 §4.3）。它的设计意图是**易腐**的临时筹码：
    手里超过 `leverageAt` 份就会招来调查，而且每年都会坏掉几份。
    某个事件若让玩家能无限囤把柄，那是内容失衡，不是机制问题。
17. **每个时代都要有中事件和小事**。只给一个时代写大事件是不够的——大事件 `unique`，
    一局只演一次，之后那个时代在抽取里就等于不存在（校验器的"按时代专属占比"会直接把这件事报出来，见 §4.8）。
18. **写静好岁月的片段时，记住它没有转折**（见 §4.13）。它是"日子"，不是"事件"：
    写成小高潮就等于把事件的活儿干了两遍，而且会让平静的月份显得不平静。
19. **每个槽位都留一条无条件片段**（时令除外，时令要覆盖 12 个月）。
    条件写得越满，越容易在"玩家又病又穷又被调查"的时候一段都抽不出来。
20. **不要替模型写数值**。随笔里只写画面，成长由 `balance.vignette` 统一结算；
    接上大模型之后，prompt 里也明确要求"不要出现任何具体数值"。

## 11.6 设计原则（v0.5.2 从玩家实测反馈沉淀，写事件前必读）

这些原则来自真实试玩反馈，validate.js 有对应断言。新事件不遵守会被校验器拦下或被打回。

### 原则一：经济要诚实（投入与回报）
- **投资型选项**（押本金做生意/竞选自掏腰包）：回报用 `funMul`（比例），不要写死 `fun` 数额——
  押 $30k 和押 $2M 的人不应该都赚 $15k。
- **消费型选项**（买广告/请律师/压稿）：ok 档必须有看得见的非钱回报（rep≥5 或 派系净变动≥5 或 contact/flag），否则就是花钱打水漂。
- 高投入（≥$50k）选项会被校验器逐个审查：ok 档要么回本 30%+，要么拿资产。
- 投注（stake）只加胜算不加回报——面板上已明示，写事件时不要再拿"加码"当收益卖点。

### 原则二：触发门槛要与身份匹配
- **大资金事件不要对低地位穷人开放**：要么 `req.fun` 挡住，要么给穷人留一条"出力不出钱"的变体选项。
- **高地位没钱的人**：应该有"用人际关系牵线/空手套白狼"的选项（req.tier 或 req.contact）。
- **低地位有钱的人**：可以有"直接投钱入局"的选项（钱开门，但政治后果自负）。
- 同一个局面按身份分化选项，比按身份屏蔽整个事件更好。

### 原则三：事件必须有前因后果
- 玩家读到的第一句就要知道**为什么是我、为什么是现在**：谁牵的线、你做过什么让这件事找上你。
- 禁止"头目听了你十分钟"这种无来由开场——他是谁？你们怎么认识的？他要什么？
- brief.known 的第一条永远先交代来龙去脉，再写局势。
- **深远影响**：重要事件要有 `after` 余波幕（minMonthsAfter 通常 6-42），让选择在几个月/几年后回响
  （工会的背书两年后会来兑账、救市签名会在下次竞选被翻出来）。unique:true 一局一次；
  互斥用 flags + notFlags（事件 A 的 a 结果给 flag，事件 B 用 notFlags 挡）。

### 原则四：身份驱动一切
- **工资按职位实算**（reg.officeSalary，参考真实公职薪水的月度换算），不按抽象层级。
- **职位名要用真人间的叫法**（学区委员/州参议员/竞选经理），"T2"这种内部代号不允许裸奔见玩家。
- 事件的 rep/fac 收益量级要配身份：市议员的事件给 rep 4-8，联邦级事件给 10-16。
- 每月日常（quietWorks）按 轨道×层级 写具体的工作颗粒（见选民/开会/巡排水系统），不写抽象散文。

### 原则五：显示要让人看懂
- 属性/资源一律中文名（魅力/智力/手腕/公信力；人脉好感不叫"人情往来"）。
- 诚信=**公信力**：不设选项门槛（不挡"你能不能选"），只在需要公信的判定里加分（吹哨/作证/改革）；
  UI 上放声望旁边。它只能被选择改变，不随年龄自然长。
- 状态标记一律带 hover 说明：是什么 + 游戏里有什么影响（tagNames 的 {name, desc, effect}）。
- 没登记词条的 flag 不显示原文（宁缺毋滥）。
- **事件标题是一句通顺、完整、一眼看得懂的陈述句**，直接说清「发生了什么」。`title` 是玩家扫视事件列表、看「承前」链、事后翻存档时的唯一索引，读不懂就等于这条事件对他不存在。比喻、留白、意象这类文学性写法一律放进 `body`（正文），不拿它当标题——标题是索引，正文才是散文。
  - 反例（看不出在说什么）：「第七版上的那支笔」「名单的最后一位」「冷板凳与椅子」
  - 正例（一眼明白）：「你在饭局上被介绍给本市报纸的专栏编辑」「你被列进州贸易代表团的出访名单，排在最后一位」

### 原则六：数字的语义要经得起追问
- 任何 -100~100 的条满了都要能回答"这意味着什么"（基层+100=全国满意？）。
- 选民维度用具体人数（warm/diehard/oppose 三池，见 reg 选民池一节），不用百分比——
  人数随选区扩大重新换算，直接影响选举判定的胜算。
- 静好岁月的账要实：工资进、开销出（quietAccount），别让玩家"几个月不吃饭"。

**提交前的自检**（跑一条命令就够）：

```bash
node tools/validate.js
```

脚本会逐条检查：`grade` / `category` / `medium` 是否存在、五档结果是否齐全、
`brief` 结构是否合法、引用的 era/track/party/faction/**contact** 是否存在、`month`/`day` 是否越界、
**每个事件是否有保底选项**、**stake 的 `cap ÷ w` 是否至少给得出一档**、
**事件链是否闭合（无悬空前情、无自环、无环）**、**`minTenure` 是否合法**、
**所有 `prog_*` 晋升事件是否都声明了 `minTenure`**、
**静好岁月片段是否合法（槽位、时令 12 个月全覆盖、每槽位有无条件兜底、全组合可拼、极端处境可拼）**、
**大模型适配层在没有配置时是否安全降级**；
并模拟 300 局给出量级分布、类型分布、**按时代拆分的时代专属占比**、日期自洽率、填充事件占比。

**看哪几个数字**：

| 指标 | 健康值 | 说明 |
|---|---|---|
| 无保底选项的事件 | **0** | 不为 0 就是硬 bug：玩家资源见底会卡死（见 §4.3.1） |
| 填充事件占比 | < 30% | 超过说明真事件池太薄（或去重窗口太大） |
| 日期自洽率 | 越高越好 | 太低说明 `month` 写太多、事件池太浅 |
| 时代专属事件占比（总数） | ≥ 15% | 太低说明通用内容淹没了时代内容 |
| **按时代的专属占比** | **每个时代都 ≥ 15%** | 只看总数会骗人：某个时代可能只有一个大事件，而大事件一局只演一次（见 §4.8） |
| 续集加权实测 | 接近 `chainWeightMul/(chainWeightMul+1)`，默认 ≈ 90% | 偏低说明一条故事线会被几百个档期冲散（见 §4.11） |
| **抽不出文字的随笔段数** | **0** | 不为 0 说明素材在某种处境下缺槽位（见 §4.13） |
| 结局分布 | 因病去世应保持两位数（默认约 1/3） | 静好岁月的 `hpChance` 一旦开大，死亡率会被推平、整个终局变温和（见 §4.13） |
| 类型分布 | 不少于 5 种 | 太低说明内容类型单一 |
| 大事件数量 | 越多越好 | 大事件一局只演一次，池子浅了会很快耗尽 |
