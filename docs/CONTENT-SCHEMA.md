# 内容契约（CONTENT-SCHEMA）

> 这是**引擎团队与内容团队之间的接口契约**。引擎保证这些字段的语义稳定；内容只依赖这里写明的字段。
> 契约变更必须改本文件（本项目无独立 CHANGELOG 文件，变更历史以 git log 为准；见 `docs/DEVELOPMENT-GUIDE.md`）；项目总览与快速上手见仓库根 [`README.md`](../README.md)。

## 0. 注册入口

内容包都是普通 `.js` 文件（**非 ES module**，保证 `file://` 双击可运行），只需调用：

```js
POTUS.define(kind, payload);
```

| kind | payload | 说明 |
|---|---|---|
| `"era"` | `{ eraId: {...} }` | 时代锚点（**迁移期兼容层**：开局皮肤 + 未迁移年代的兜底，新内容主推 `worldline`/`fixed`，见 §1.5）。现役仅 5 个时代（1980—2016），1980 前时代已冻结进 `deprecated/snapshots/`） |
| `"worldline"` | `{ pressure:{年:值}, brief:{年:...}, outlets:{年:...} }` | **连续时间轴**：按**绝对年份**键控的时代压力 / 年终简报 / 新闻口径（取代"选时代"，见 §1.5） |
| `"fixed"` | `[ {event, year, ...}, ... ]` | **全局定点事件表**：某年某月**必发**的大事件与固定事件串（取代 `era.scheduled`，可多次调用累加，见 §1.6） |
| `"origin"` | `{ id: {...} }` | 出身 |
| `"talent"` | `{ id: {...} }` | 天赋 |
| `"entry"` | `{ id: {...} }` | 起点路径 |
| `"track"` | `{ id: {...} }` | 晋升轨道 |
| `"party"` | `{ id: {...} }` | 党派 |
| `"stance"` | `{ id: {...} }` | 政治姿态 |
| `"state"` | `{ id: {...} }` | **出生州登记表**（州名/倾向 lean/铁杆强度 strength/城市选区/entryEffects），`content/12-states.js`，建角与州联动事件用 |
| `"office"` | `{ "track_tier": 职位名 }` | **各层级职位名**（字符串或 `{name}`），`content/14-offices.js`，界面按 轨道_层级 查 |
| `"officeSalary"` | `{ "track_tier": 月薪 }` | **职位月薪表**（美元/月），`content/14-offices.js`；`core.js officeSalary()` 解析顺序：轨道_层级 → `*_层级` 通配 → 兜底。**它是"这个身位值多少钱"的唯一口径**：平静月工资、投注级别价（每档 ≈ 一档月薪，§4.16.3）、`scale.js` 的人物钱标尺（§4.16.2）都从这里派生 |

| `"wrath"` | `{ 组: { name, desc } }` | **仇家群体**（清算系统）：press/establishment/money/opposition/agency 五组，仇恨值存 `G.counters["wrath_<组>"]`，见 §4.18 |
| `"blackswan"` | `{ eraId: [ ... ] }` | 黑天鹅事件表 |
| `"filler"` | `{ eraId: pack }` | 填充模板包（`"*"` 为全时代兜底） |
| `"yeartale"` | `{ id: {kind, when, texts} }` | **年终随笔素材**（`content/13-year-tales.js`，`texts` 里用 `{year}` 占位，每 kind 留无条件兜底） |
| `"flavor"` | `{ TOKEN: [ {minYear, maxYear, text} ] }` | **口语 token 池**（`content/09-flavor.js`，`engine/flavor.js` 展开 `{ORG}{PLACE}{MEET}{PUB}`；内置 `{HOME}{STATE}{CITY}{DISTRICT}` 无需登记） |
| `"contact"` | `{ id: {...} }` | **人脉登记表**（这一局里能反复出场的那些"人"），见 §4.10 |
| `"category"` | `{ id: {...} }` | **事件类型**（每个类型自带默认配图与配色），见 §4.8 |
| `"grade"` | `{ id: {...} }` | **事件量级**（大/中/小事），一般不用改 |
| `"medium"` | `{ id: {...} }` | **时代媒介时间轴**（报纸/电视/互联网/短视频… 各自起始年份），见 §4.9 |
| `"event"` | `[ event, ... ]` | 事件库（可多次调用，自动累加） |
| `"campaign"` | `{ campId: {...} }` | **竞选链**（一条民选晋升 = 一串分幕、强制推进的竞选事件，见 §14） |
| `"ending"` | `[ rule, ... ]` | 结局规则（可多次调用，自动累加） |
| `"vignette"` | `{ title?, lede?, fragments:[ ... ] }` | **静好岁月**：平静月份的随笔片段库（`fragments` 多次调用会**累加**），见 §4.13 |
| `"photo"` | `{ dir?, files:{ categoryId: "x.jpg" } }` | **事件配图的照片表**（`files` 多次调用会**合并**），没登记的类型自动退回程序化 SVG，见 §4.15 |
| `"l10n"` | `{ lang: "en", content: { event: [...] } }` | **多语言内容覆盖层**：按 id 定位、按字段合并回中文原文，结构键受保护不许改写；契约见 `engine/i18n.js` 与 `docs/I18N.md` |
| `"balance"` | `{ key: value }` | 覆盖平衡参数，可只写要改的项（`tagNames` 深合并） |
| `"effect"` | `{ key: function(value, G){} }` | 注册自定义效果键 |

> **已停用的 kind**：`"arc"`（主线）——玩法大改造砍掉多支路主线，`dev/index.html` 已把 `content/11-arcs.js` 移出加载清单（`P.reg.arc` 为空，引擎不再推进任何主线），抽取权重里的 arc 因子恒为 1。引擎文件 `engine/arc.js` 与 §4.16 暂留作考古。

新增**任何**内容都不需要修改 `engine/`。

**挂载（白名单制）**：`dev/index.html` 的 `<script src>` 清单是白名单——没挂载 = 引擎不认识 = 静默死亡，无运行时报错。清单分三区：**手工区**（engine 块 + content 01–11x 段 + events 110–119 段，新文件手改登记）、**gen-manifest 托管区**（`BEGIN/END content-auto-manifest` 注释对，120 系列年带/补隙与 140 清算包由 `node dev/tools/gen-manifest.js` 自动重写挂载——**往托管区手塞行 = 下次重写时蒸发**；CI 用 `--check` 比对磁盘与托管区，有 diff 即 exit 1）、**i18n-manifest 托管区**（`content/i18n/` 镜像清单，zh 永远在前）。新事件文件的正确姿势：放进 `content/events/` 对应编号段 → 跑 `gen-manifest.js` → 跑 `validate.js` 验收。

## 0.5 时间模型：一个月一回合

这是整个节奏的地基，写内容前必须先理解。

```
年（12 个月）
 └─ 月          ← 一个月 = 一个回合
     └─ 档期     ← 一个档期 = 一次需要玩家决策的事件（抽一个事件出来出题）
```

**不是每个月都有事。** 引擎在每次推进时按下面的公式决定某个月有没有档期：

```
pActive = clamp(activeChance + 时代压力 × activePressureMul + 活跃度 × activeBonusMul,
                activeMin, activeMax)

时代压力 = 优先按绝对年份读 worldline.pressure[年]；该年不在时间轴里则回落 era.pressure（内容在 era 里写，0-6）
活跃度   = 丑闻 0.8 + 被调查 0.8 + 选举年 0.6 + 层级≥T4 0.5 + 把柄≥3 档 0.4   （权重见 balance.bonusPressure）

有事发生的月份 → 档期数 = slotsBase + (压力≥slotsPressureAt ?1:0)
                          + (活跃度≥slotsBonusAt ?1:0) + rint(0, slotsVariance)
没有事发生的月份 → 只往月历上记一行「平静」，玩家看到月历卡继续往前走
```

每个档期还会按 `balance.gradeWeights` 抽一个**量级**（大事件/中事件/小事）。实测（`node dev/tools/validate.js`「月度回合」节，2026-09-24 快照）：

| 压力 | 大事件 | 中事件 | 小事 |
|---|---|---|---|
| 0 | ~3.2% | ~31.3% | ~65.5% |
| 5 | ~22.9% | ~51.1% | ~26.0% |

**由此得到的实际节奏**：常态年月历基本是满的——20 局生涯模拟实测每年档期平均 12.6 个（validate 输出「每年档期」行）。

**内容作者要理解的三件事**：

1. **想表达"这一年很乱"** → 调 `era.pressure`，不要靠堆事件数量。压力会同时把「有没有事」「有几件」「有多大」三个维度顶上去。
2. **事件池的深度决定了日期自洽率**。引擎抽题是四级降级（先要「就是本月」→ 再要「没写月份」→ 再放开月份 → 最后放开去重窗口），池子越深，前两级越够用。
3. **大事件默认一局只演一次**（`unique` 缺省为 `true`）。所以大事件池会被消耗光，之后自动降级到中事件。**多写大事件**是唯一解法，或者给某个大事件写 `unique: false`。

## 1. era（时代锚点）

```js
POTUS.define("era", {
  "2008_CRASH": {
    name: "大空头 (2008)",     // 必填，显示名
    startYear: 2008,           // 必填，开局年份
    diff: "★★★★",             // 可选，难度标签
    intro: "……",               // 可选，建角页简介
    electionCycle: 2,          // 可选，选举年周期（默认取 balance.midtermCycle）
    outlets: ["纽约时报", "…"],  // 可选，新闻媒体池（makeNews 用）
    newsTpl: "【{outlet}】…",    // 可选，新闻模板；占位符 {outlet}{year}{name}{headline}
    brief: {                   // 年度世界简报；键为年份字符串，"*" 为兜底
      "2008": "次贷危机全面爆发……",
      "*": "危机之后的世界仍在震荡。"
    },

    // —— 节奏：这个时代有多动荡（0-6，见 §0.5）——
    pressure: { "2008": 5, "2009": 5, "2010": 3, "2012": 4, "*": 2 },
    // 也可以写成固定数字：pressure: 3
    // 或写成函数：      pressure: function (G, POTUS) { return G.year < 1964 ? 5 : 2; }

    // —— 时代脚本：到了某年某月必定发生（默认一局只演一次）——
    // 旧机制，仅剩迁移兜底：现役 5 时代里只有 2008_CRASH 还留着 3 条 scheduled，
    // 新内容一律改走全局 fixed 表（§1.6）。
    scheduled: [
      { event: "2008_crash_offer", year: 2008, month: 9, grade: "major" }
    ]
  }
});
```

### 1.1 scheduled（时代脚本 / 定点事件）

到了某年某月**必定**发生，用来把时代的关键节点钉死在日历上。

| 字段 | 必填 | 说明 |
|---|---|---|
| `event` | ✔ | 事件 id（必须存在于事件库中） |
| `year` | ✖ | 精确年份 |
| `month` | ✖ | 精确月份（1-12） |
| `fromYear` / `toYear` | ✖ | 年份区间（写到 so 时段内每年到点都可能触发） |
| `fromMonth` | ✖ | 区间起始年内，早于这个月不算 |
| `grade` | ✖ | 这个档期的量级，默认取事件自己的 grade |
| `once` | ✖ | 默认 `true`（一局只演一次）；写 `false` 则每年到点都演 |
| `cond` / `flags` | ✖ | 额外条件，不满足就跳过 |

> **定点事件仍要过一遍普通事件的触发条件**（tier / flag / era / 媒介年份 …），不满足就跳过。
> 所以「写给高层级玩家的定点事件」不会硬塞给还没爬到那个位置的人。

> ⚠ **迁移已收尾**：`era.scheduled` 是**旧机制**，引擎仍支持（`time.js scheduledHits` 照旧合并），但现役树只剩 5 个时代（1980_REAGAN / 1990_GULF / 2001_WARONTERROR / 2008_CRASH / 2016_SOCIAL），且仅 2008_CRASH 还留着 3 条兜底 scheduled；1980 前的 1912…1970s 时代已整体冻结进 `deprecated/snapshots/20-eras.js`，不再挂在加载清单上。新铺的年代一律用**全局 `fixed` 表**（§1.6）+ **绝对年窗 `minYear`/`maxYear`**，不再往 era 里写 `scheduled`、事件也不再钉 `era`。

### 1.5 worldline（连续时间轴 · 取代"选时代"）

玩法核心已从**"选一个时代"**改为**一条按绝对年月推进的连续时间轴**：历史在特定年份自动变脸，玩家与作者层面都不再出现"时代"这个词。`worldline` 就是这条轴的**按年键控**数据，`content/21-worldline.js` 承载：

```js
POTUS.define("worldline", {
  pressure: { "1980": 4, "1982": 5, "1986": 2, /* …按绝对年份 */ },  // 该年时代压力（0-6）
  brief:    { "1981": "里根遇刺未遂、国会风向突变……" },               // 年度世界简报（字符串或 {lede,…}）
  outlets:  { "1987": ["CNN", "纽约时报", "…"] }                        // 该年新闻口径池
});
```

- 引擎读点全部改为**"优先按 `G.year` 读 worldline，读不到则整体回落 era"**（`time.js` 的 `pressure`、`view/stage.js` 的简报与黑天鹅、`progression.js` 的选举年、`events.js` 的 `makeNews`/filler）。era 兼容层因此仍可兜底，但现役时间轴已按年无缝铺满。
- **不要给 `pressure`/`brief`/`outlets` 写 `"*"` 兜底键**：留空即让未覆盖的年份整体回落到 era，避免"半新半旧"串味。
- 时间轴现已**按年铺满 1980—2024**：`21-worldline.js` 承载 1980—1990；1991 起由各年代带文件 `events/120-line-1991-94.js` … `events/128-line-2022-24.js` 各自 `define("worldline")` + 随卡 `define("fixed")`；`events/129-133` 为补空隙的纯 `fixed` 表。2025 起撞上 `balance.endYear` 硬墙（见 §4.19）。

### 1.6 fixed（全局定点事件表 · 取代 era.scheduled）

与 `worldline` 配套的**按绝对年月必发**的事件表，是"到点必发的大事件 / 固定事件串"的落点。可多次 `POTUS.define("fixed", […])`，自动累加：

```js
POTUS.define("fixed", [
  { event: "rg81_shooting", year: 1981, month: 3, grade: "mid" },
  { event: "rg87_iran_hearings", year: 1987, month: 7, grade: "major" },   // 事件串后幕：靠 after 续接
  { event: "rg89_iran_after", fromYear: 1988, toYear: 1989, month: 3 }     // 弹性年月窗口
]);
```

字段与 §1.1 的 `scheduled` **完全一致**（`event/year/month/fromYear/toYear/fromMonth/grade/once/cond/flags`）；差别只在它是**全局表、与 era 无关**。`time.js` 的 `scheduledHits()` 会把 `fixed` 与（迁移期）`era.scheduled` **两路合并**，同一事件只演一次。

- **固定事件串**不复活已停用的 `arc.js`，而是用现有机制拼：把 2~3 幕（前奏→爆发→余波）各自钉进 `fixed`，后幕靠事件自带的 `after:{id,minMonthsAfter}` / `flags` 续接。**前幕若因层级/机缘没演，后幕的 `after` 不成立即静默跳过**——是一条"可断裂"的串，符合"历史 catch-up 但不强灌"。
- 串里的每一幕事件本身仍写 `minYear`/`maxYear` + `scoped:true`（见 §4 / §4.2.1），`fixed` 只负责"到点必发"，事件自己负责"够不够格发"。

```js
POTUS.define("talent", {
  orator: { name:"天生演说家", desc:"…", mods:[ {src:"attr", key:"CHA", w:0.15} ] },  // 全局修正
  gambler: { name:"赌徒直觉", desc:"…", critMul:2, critfailBoost:2 },                  // 大成功/大失败倍率
  stomach: { name:"铁胃",     desc:"…", hpDecayMul:0.5 }                               // 健康衰减倍率
});
```

```js
POTUS.define("entry", {
  celebrity: {
    name:"名人起手", desc:"…",
    tier: 1,                         // 开局层级
    track_suggest: "celebrity",      // 建议轨道（键须存在于 track）
    effects: { rep:45, fac:{base:20}, attr:{INTG:-15} }
  }
});
```

> **属性纪律（#37②）**：`origin` / `entry` / `state`（用 `entryEffects`）与难度 `bonus` 的 `effects` 里
> **不写正属性**——补偿只能走 声望 / 人情 / 派系 `fac` / 判定 `mods`。上面 `celebrity` 那条
> `attr:{INTG:-15}` 是**唯一**被批准的写法：隐藏诚信的**负数**，语义是"名声不等于信任"这种出身代价。
> 越界（任何正向 attr、或非诚信的负 attr）validate 直接红；文案里也别再写"智力 +15"这类承诺——
> 建角第 3 步的预览只可能显示 自由点 + 卡池 两份来源。

## 4. event（事件）

```js
POTUS.define("event", [{
  id: "2008_crash_offer",           // 必填，全局唯一
  era: ["2008_CRASH"],              // 可选（迁移期兼容）：钉在哪个/哪些时代。**新内容不再写 era**，改用绝对年窗 minYear/maxYear（见 §1.5）
  title: "一份'救市'内部简报",        // 必填
  body: "……",                       // 必填，事件正文

  // —— 事件核心字段：类型 / 量级 / 三值性 / 经济模式（全部必填，见 §4.8 / §4.16）——
  grade: "major",                   // 必填：major 大事件 ／ mid 中事件 / minor 小事
  category: "crisis",               // 必填：事件类型（决定默认配图与配色）
  valence: "bane",                  // 必填：boon 机遇 / risk 风险 / bane 威胁（三值性，见 §4.16.1）
  dyn: true,                        // 必填：经济字段写系数而非绝对金额（见 §4.16.2）
  medium: ["tv", "social"],         // 可选：这件事要靠哪种"说话方式"才能发生
  unique: true,                     // 可选：一局只演一次（grade=major 时默认 true）；140-reckoning 的 5 张清算卡显式写 unique:true
  rereq: { flags: ["someFlag"] },   // 可选「debuff 续燃」：满足该条件时本卡豁免终身衰减、改吃更短冷却窗（见 §4.20）
  rereqMul: 1,                      // 可选：rereq 满足时的权重倍率（默认 1）。不满足时终身权重 × balance.idRepeatMul
  pace: "exempt",                   // 可选「豁免通道」：投机/灰产生意可反复做——不吃单卡衰减、不吃硬冷却、走 balance.pace.grayMax 额度。**必须同时显式写 unique:false**（见 §4.21）
  chore: true,                      // 可选：标记为「日常公务/选民服务」卡——**不进随机卡池**，只经 time.js 的 choresSlot 按月兜底注入（v0.12 起 T0 志愿者也发），见 §4.17

  weight: 14,                       // 可选，抽样权重（默认 10）
  filler: false,                    // 可选，标记为填充事件

  // —— 时间与背景（见 §4.6 / §4.7）——
  month: 9, day: 24,                // 可选，只在"历史上真钉在某个日子"时才写
  brief: { /* 主角视角的背景卡，见 §4.7 */ },

  // —— 触发条件（全部可选，全部满足才可能被抽中）——
  tierMin: 0, tierMax: 9,           // 层级区间（引擎 tier 0..9 = 界面等级 1..10）
  tierRaw: true,                    // 可选：为 true 时 tierMin/tierMax 直接按真实 0..9 解释，跳过 when.js 旧的 tierBand 6 档映射（晋升脊柱 prog_* / 竞选链各幕一律带上）
  minYear: 1980, maxYear: 1989,     // 推荐（新内容首选）：绝对年窗，走 when.js 统一条件词汇；配 scoped:true 标为分期专属
  scoped: true,                     // 可选：去 era 后标记「某一时期专属」，供 eraWeightMul 加权（不参与年份判定）
  fromYear: 2008, toYear: 2020,     // 另一套年份窗口（走 core.js 的 POTUS.yearOK，也可写 years: [2008, 2020]）
  tracks: ["electoral"],            // 仅这些轨道可触发
  parties: ["D"],                   // 仅这些党派
  entries: ["celebrity"],           // 仅这些起点
  origins: ["labor"],               // 仅这些出身
  flags: ["someFlag"],              // 必须已拥有的标记（全部满足）
  notFlags: ["otherFlag"],          // 必须没有的标记（任一命中即排除）
  minRep: 25, minFun: 200000,       // 资源门槛
  minLev: 1,                        // 把柄门槛（手上至少有 1 份）
  contacts: ["fixer"],              // 人脉门槛：必须已认识（全部满足）
  minTenure: 24,                    // 在位时长门槛：在当前层级至少蹲够 24 个月
  countMin: { wrath_press: 25 },    // 计数器门槛：G.counters 里的键 ≥ n 才放行（树敌/清算系统，见 §4.18；同族还有 countMax / countEq）
  after: { id: "archive_get",       // 事件链（见 §4.11）：前情必须已演过
           minMonthsAfter: 3, maxMonthsAfter: 30 },
  cond: function(G){ return true; },// 自定义条件（完全自由）

  choices: [ /* 见 §4.1 */ ]
}]);
```

**触发条件里最容易踩的三个坑，都在上面这一块**：`contacts`（人要认得）、`minTenure`（台阶要熬）、`after`（前情要演过）。它们各自在 §4.10 / §4.11 里展开。

### 4.1 choice（选项）

```js
{
  id: "sign",                       // 必填，事件内唯一
  text: "签名背书，登上全国荧幕",     // 必填，按钮文案
  base: 0.5,                        // 必填，基础胜算（0-1）
  mods: [ /* 修饰符，见 §5 */ ],
  req: { /* 可选，前置条件，见 §4.2 */ },
  cost: { /* 可选，资源代价，见 §4.3 */ },
  stake: { /* 可选，判定前可投入资源加码，见 §4.4 */ },
  outcomes: {                       // 必填，五档结果
    crit:     { body: "…", effects: {…} },
    ok:       { body: "…", effects: {…} },
    meh:      { body: "…", effects: {…} },
    fail:     { body: "…", effects: {…} },
    critfail: { body: "…", effects: {…} }
  }

```

- **五档结果必须齐全**（`crit/ok/meh/fail/critfail`）。缺失会在校验脚本里报错。
- `body`：结果叙事文本。
- `when`（可选，写在**选项**上，见 §4.21 的分层变体）：同一张历史大事件按玩家层级只露出对应的选项支。
  命不中的选项**直接隐藏**（不是灰掉），所以三档必须铺满 0—9 不留缝。


  ```js
  meh: { body:"…", news:"你签下救市背书，对手开始称你'华尔街的年轻人'", effects:{…} }
  ```

```js
req: { fun: 50000 }                    // 资金门槛
req: { rep: 25 }                       // 声望门槛（口径 ruler.repGate：量级×职级系数，不吃属性系数，硬顶 repGateMax）
```

### 4.3 cost（选项的资源代价）

**选这个选项要先付的钱/人情/把柄。** 付不起时按钮置灰，提示"缺少资金/人情/把柄"，玩家点不动。

```js
cost: { fun: 400000 }         // 花 $400k
cost: { fav: 1 }              // 花 1 点人情
cost: { lev: 1 }              // 花掉 1 份把柄（把柄是"份"，花掉就没了，不能欠）
cost: { fun: 120000, fav: 1 } // 可以组合
```

| 键 | 含义 | 单位 | 归零/上限 |
|---|---|---|---|
| `fun` | 资金 | 美元 | **允许为负**（负债是有戏剧性的，别拿它当硬墙） |
| `fav` | 人情 | 点 | 夹在 `[0, 20]` |
| `lev` | **把柄** | 份 | 下限 0（**不能为负**：花掉就没了，没有"欠人一份把柄"这回事） |
| `rep` | 声望 | 点 | 可以作代价，但谨慎（易造成死亡螺旋） |

> ⚠️ **精力(`ap`)、健康(`hp`) 已于 v0.9 退役**：不再作为代价（也不上界面）。历史内容里残留的 `cost:{ap}` 会被引擎忽略（不展示、不扣减）；**新事件不要再写 `ap`/`hp` 代价**。

> **把柄（lev）是什么**：通过灰色手段拿到的"让某人不敢开口"的东西——一份人事档案、一盘录音带、一个编号。
> 它换不来钱，只能换来沉默和让步。它有三个特性，写内容时要一直记着：
> 1. **会贬值**：每一份把柄每年有 `balance.leverageDecayChance`（默认 0.34）的概率失效（当事人下台、事情过去了）。所以把柄不能当永久资产囤。
> 2. **会招祸**：手上满 `bonusPressure.leverageAt`（默认 3）份，活跃度会被顶上去（调查、传唤、约谈接踵而来）。
> 3. **不可投注**：把柄不在 `stake` 体系里。它是"代价"，不是"加码"。

设计建议：
- **代价要"肉疼但不致命"**。一个事件里最多 1~2 个选项带重代价。
- 代价与收益要成比例：花 $400k 的选项，成功率应明显高于免费的。
- 要表达"钱买不到的东西"，用 `fav`（或把柄 `lev`）当代价，而不是把 `fun` 门槛抬到天上去。
- 高代价选项配合 `req` 使用效果最好（有钱也要有资格）。

#### 4.3.1 保底选项（强制，`validate.js` 会拦）

**每个事件至少要有一个既没有 `cost`、也没有 `req` 的选项。**

原因：玩家的钱会被事件花光、声望会被打下去。如果一个事件的**所有**选项都要钱（或都设了门槛），资源见底的玩家就会撞上「每一个按钮都点不动」的死局——游戏直接卡住，只能读档。

```js
// ✗ 会被校验器拦下：两个选项都要钱
choices: [
  { id: "prime", text: "押上全部资金买黄金时段", cost: { fun: 400000 }, … },
  { id: "late",  text: "只买得起凌晨档",         cost: { fun: 90000 },  … }
]

// ✓ 留一条不要钱的路
choices: [
  { id: "prime",  text: "押上全部资金买黄金时段", cost: { fun: 400000 }, … },
  { id: "late",   text: "只买得起凌晨档",         cost: { fun: 90000 },  … },
  { id: "earned", text: "一个子儿不花，去免费的地方露脸", base: 0.45, … }   // ← 保底
]
```

保底选项不是"白送的失败选项"，它应该**有真实的机会、也有真实的代价**，只是不用资源结算：
- 常见写法：拼时间（低基础成功率）、拼人（说清失败后果）。
- 设计感：`base` 通常比付费选项低 0.05~0.15，用 `mods` 让属性好的角色也能翻盘。
- 它的存在本身也是叙事：**"没钱的人怎么办"**往往比"有钱怎么办"更有戏。

引擎侧仍有保险丝：`P.fallbackIndex(chs)` 会在**全部**选项都被堵死时强行放行一个（优先放行"只是资源不够"的那个），界面标注「⚠ 保底选项：…，硬撑一次」。但这是防止内容写漏把玩家关死，**不是**可以让内容偷懒的替身——校验器会直接把违规事件报出来。

### 4.4 stake（D&D 式"投入资源加码"）

**声明 stake 的选项，点击后会先弹出一个投注面板**，玩家自己决定往判定里砸多少资源，再掷骰。这是本作把"资源"变成"博弈"的核心机制。

```js
stake: { fun: true, fav: true }   // 两种都能投，用全局默认汇率（资金 = 级别价，见 §4.16.3）
stake: { fun: true }              // 只能投钱
stake: { fun: { per: 500000, w: 0.06, cap: 0.3 } }  // 单项自定义：写死 per = 这一注的价码由剧情定
```

| 资源 | 效果 | 默认汇率（`balance.stakeRates`） | 实际可投档数 |
|---|---|---|---|
| `fun` | 提高判定目标值 | **级别价**（每档金额 = 你这个位子的月薪 × 量级系数，只看身位不看家底，见 §4.16.3）→ `+4%`，上限 `+30%` | **最多 8 档** |
| `fav` | **重投取优**（D&D 的 advantage，掷两次取好的那次） | 花 `1` 点换一次 | 开关式，1 点 |

> ⚠️ **精力(`ap`) 已于 v0.9 从投注退役**：不再是加码轴。历史上写过 `stake:{ap:true}` 的选项会退化为“无投注面板”（休眠，不报错）。

单项自定义字段：

```js
{ per: 500000, w: 0.06, cap: 0.30 }   // per=每多少美元一档（写了就关闭级别价换算）；w=每档加值；cap=该项总上限
```

规则与边界（引擎已实现，内容无需关心实现只看结论）：
- **可投档数被两道闸夹住**：`ceil(cap ÷ w)`（超过就没有收益了）和钱包。资金现行 `+4%`/档、上限 `+30%` → **最多 8 档**；每档金额是**级别价**（见 §4.16.3），余额 `floor(现金 ÷ per)` 押不满 8 档时以余额为准。**单价与余额无关**——家底只决定你押得起几档。引擎在扣款前再过一次这个闸，界面就算被改坏也不会多扣资源。
- **投注额自动被余额夹住**：钱不够就只能投到刚好花完，不会出现负数投注。
- **投不起时按钮置灰并说明原因**（"资金不足：每档需 $X，你现在只有 $Y"，X 就是这个身位的级别价），不会出现"点了没反应"。
- **到顶后先置灰再提示**（"已经加到这项的上限了"，`ui.actions.atMax`）。
- 目标值仍受 `clamp(…, 0.05, 0.95)` 限制，**狂投也突破不了 95%**。
- 玩家点"返回"不消耗任何资源；只有点"确认判定"才扣。
- 结算时玩家会看到完整的 D&D 明细：`d100 = 79（重投 79 / 92 取优） ／ 目标 48` + 每项修饰符拆分 + "已消耗：资金 $500k · 人情 1"。

**写 stake 时必须自检的一步**：`cap ÷ w` 必须 ≥ 1。若 `cap` 比 `w` 还小，玩家投第一档就是纯亏——校验器会拦（`stake 上限还不到一档加成`）。可投档数 = `ceil(cap ÷ w)`，写文案时可以顺手算一下，别让上限"看起来能到 +30% 却永远吃不满"。

**什么时候该加 stake？**
- 这一注该由玩家自己决定押多大（赌一把 vs 稳着来）→ 加 `stake`。
- 这个选项就是固定代价、无可选择 → 只用 `cost`，不要加 `stake`。
- 想让"人情"这个资源有独特的战术价值 → 在关键判定上给 `fav: true`。

> **竞选幕有一档更陡的价目表**（#39）：`stake: { fun: { w: 0.06, cap: 0.42 } }` —— 6%/档、7 档封顶 +42%（日常事件 4%/30% → 8 档）。理由：宣布、初选、买量、最后冲刺这几场本来就是要花钱办事的，+30% 配不上"入场券"。**单价口径不变**（仍走 §4.16.3 级别价，禁止钱包锚），**投票日（`ballot`）一概不许接**（validate 判红）。详见 §14.3。

### 4.5 三者的分工（别混用）

| 字段 | 玩家体验 | 扣资源的时机 |
|---|---|---|
| `req` | 按钮置灰 +「需要 XX」，**根本选不了** | 不扣 |
| `cost` | 能选，按钮上写「代价：资金 $400k」，**没得商量** | 点下去就扣 |
| `stake` | 能选，先弹投注面板让玩家自己加码 | 点「确认判定」才扣 |

`req` 和 `cost` 都会让按钮置灰。因此**一个事件里的所有 `req` / `cost` 加起来不能把按钮全堵死**——必须留一个两者都没有的保底选项（见 §4.3.1）。这是硬性要求，校验器会拦。

### 4.6 month / day（只有"历史上真钉在某一天"才写）

```js
month: 9, day: 24      // 2008 年 9 月 24 日
month: 4               // 只写 month：只在这个月才可能被抽到
```

**规则变了：`month` 现在是稀缺资源，不是默认配置。**

在"一个月一回合"的模型里，引擎会把每个档期落到某个具体的月份上（可能是 3 月、7 月、11 月…），
所以一个写了 `month: 9` 的事件在 3 月是抽不到的。**只有真的钉在某个日子的史实事件才写 `month`。**

| 该写 month 的 | 不该写 month 的 |
|---|---|
| 雷曼那一周、电视辩论当晚、听证会传票送达 | 一次金主晚宴、一场越界的酒后、一次游说电话 |
| 选举日、报税日、历史上真实发生的那天 | 「某个季节里可能发生的日常政治」 |

**为什么日期很重要**：玩家可能知道主角不可能知道的事。例如「做空的次贷」钉在 **2008 年 3 月 12 日**——一个熟悉那段历史的玩家会立刻意识到，距离贝尔斯登崩盘只剩四天。日期就是这种信息的载体。

**写日期的规矩**：
- 有真实历史锚点的事件，**用真实日期**（里根遇刺未遂 = 1981/3/30；黑色星期一 = 1987/10/19）。
- 虚构事件**不要**写 `month`（要钉年月就写进全局 `fixed` 表，见 §1.6）。
- **不要**在 `body` 里重复日期，引擎已经显示在顶部。

**引擎抽题时的四级降级**（内容不用管实现，但要知道后果）：
1. 先找「`month` 就等于当前月」的事件；
2. 其次找「没写 `month`」的常青事件；
3. 再次才允许月份不符（此时会尽量挑离当前月最近的）；
4. 最后放开「近期演过」的去重窗口（`recentIds`）。

注意第 4 级放开的只是**近月去重窗**：v0.12 的**单卡硬冷却**（见 §4.20）在任何一级都不放行，"本月已演过"的卡（`_monthSeen`）也不会被重选。

所以 **`month` 写得越多，1、2 级越容易空，日期自洽率越低**。`tools/validate.js` 会打印「日期自洽率」，
它是**内容量的指标**：事件池越深，这个数字越接近 100%。当前 306 个事件、带日期钉月的 131/306，20 局×100 抽的自洽率实测 100.0%（**一切以 `node dev/tools/validate.js` 输出为准，本文数字为 2026-09-24 快照**）。

### 4.8 category / grade（事件类型与量级）

**每个事件必须声明 `grade` 和 `category`。** 这两个字段决定了三件事：
界面上的徽章、配图、以及"把内容派给不同的人写"时的分片依据。

```js
grade: "major"        // major 大事件 ／ mid 中事件 ／ minor 小事
category: "scandal"   // 类型 id，必须在 category 注册表里
```

| grade | 定位 | 缺省 unique | 建议占比 |
|---|---|---|---|
| `major` | 时代级的大事件，一局最多演一次 | `true` | 少量，把重量级内容放这里 |
| `mid` | 有分量的中事件，可以反复出现 | `false` | 主力 |
| `minor` | 日常小事、生活流、过场 | `false` | 大量，用来铺密度 |

内置的事件类型（定义在 `content/05-categories.js`）：

| id | 名称 | 用于 |
|---|---|---|
| `general` | 综合 | 没分类的兜底 |
| `career` | 仕途 | 晋升、任命、官场台阶 |
| `campaign` | 竞选 | 竞选链各幕与拉票日常 |
| `political` | 党务 | 立法、党内博弈、游说 |
| `govt` | 政务 | 执政、官僚、政策执行 |
| `media` | 舆论 | 媒体、辩论、社交网络 |
| `crisis` | 危机 | 时代大事件、崩盘、黑天鹅 |
| `scandal` | 丑闻 | 调查、传票、曝光 |
| `finance` | 金钱 | 金主、献金、做空、基金会 |
| `romance` | 私情 | 越界、家庭、把柄 |
| `civil` | 民权 | 民权与社会运动 |
| `foreign` | 外交 | 外交与安全 |
| `shady` | 灰产 | 灰色生意、把柄、地下交易、族群飞地里的"能办成事的人" |

**分期专属 vs 跨时代通用**（`events.js` 的 `periodScoped`）：一条事件要么写窄 `era` 数组（短于现役时代总数），要么显式 `scoped: true` 配绝对年窗——它就是**分期专属**的，抽取时权重乘 `balance.eraWeightMul`（默认 3），保证"这段年月自己的故事"不被常青通用内容淹没。`tierRaw` 晋升脊柱视为跨年代通用，豁免此标签要求（validate 会拦缺分期标签的卡）。校验器统计**分期专属事件的抽取占比**，按时代分别打印，要求整体 ≥ 15%（2026-09-24 实测 18.3%）——**低于这个数不是引擎 bug，是内容缺口**：说明那段年月只剩几个大事件（而大事件 `unique` 一局只演一次），玩家在那条时间线上看到的全是通用内容。补法只有一个：给那个年代写**中事件和小事**。

**新增一个类型**（在 `content/05-categories.js` 里加一条即可，引擎自动接纳）：

```js
POTUS.define("category", {
  "labor": {
    name: "劳工", ink: "#4a5a2a", base: "#e6e9d6",   // 主色 / 底色
    art: function (ev, P, ctx) {                      // 返回 SVG 片段（120×120 坐标系）
      return P.artFrame(
        '<rect x="24" y="30" width="72" height="52" fill="' + ctx.ink + '" opacity=".5"/>' +
        ctx.caption(ev, ctx.ink),                     // 底部标题带，建议都加上
        ctx.ink, ctx.base);
    }
  }
});
```

- `art` 是**类型的默认配图**。具体事件想出自定义图，就在事件里写 `art(ev, P)`，优先级更高；两者都没有时引擎兜底。
- 配图是**程序化 SVG**，零外部图片、零依赖。想换成真图片，让 `art` 直接返回 `<img src="…">` 之类的 HTML 也行。
- 配图会被 `ev.art` → `category.art` → 引擎兜底 三级降级解析，所以**新写事件不用画图也有图**。

### 4.9 medium（时代媒介时间轴）

**让事件按年代自动生效 / 失效。** 声明 `medium` 后，引擎会查该媒介在这年存不存在，不存在就直接排除。

```js
medium: "tv"                  // 要有电视才可能发生
medium: ["tv", "internet"]    // 电视或互联网，有其一就行（"靠哪种都传得开"）
// 不写 = 任何年代都可能发生（报纸时代的常青政治）
```

媒介时间轴定义在 `content/06-media.js`：

| id | 名称 | from | 它给政治带来的变化 |
|---|---|---|---|
| `print` | 报纸 | 1700 | 一封信就能毁掉一个人 |
| `radio` | 广播 | 1920 | 声音直接进入客厅，不必靠集会 |
| `tv` | 电视 | 1948 | 形象压过文字 |
| `cable` | 有线电视 | 1980 | 舆论拆成两个世界 |
| `internet` | 互联网 | 1995 | 信息不再经过编辑部，也无人把关 |
| `social` | 社交媒体 | 2008 | 人人都成了发布者 |
| `shortvideo` | 短视频 | 2018 | 十五秒定生死，算法成了新的党鞭 |
| `deepfake` | 合成影像 | 2022 | 「眼见为实」失效 |

**这套机制最实用的两个用法**：

1. **给同一件事写多个年代版本**。`content/events/55-media-timeline.js` 就是范例：广播时代撞上「麦克风」，
   电视时代撞上「上镜」，2025 年才撞上「十五秒」和「假视频」。
2. **让大事件"等媒介成熟了再登场"**。给它一个较晚的 `medium` + `grade: "major"`，
   于是 1980 年开局的玩家永远遇不到「短视频风暴」，打到 2010 年代才遇得到——不需要写任何逻辑。

`medium` 之外还可以用绝对年份卡窗口：

```js
fromYear: 1945, toYear: 1991     // 只在冷战期间
years: [1945, 1991]              // 同上，写法糖
```

> 引擎在年卡与月历卡上会显示**「此刻存在的媒介」**，玩家能一眼看见这个年代的舆论环境。
> 新增媒介只需在 `content/06-media.js` 加一条（`from` 必填，`note` 会被展示给玩家）。

### 4.10 contact（人脉登记表）

**一个事件里写「你去找他」很容易，难的是让同一个"他"在十年后再次出现，并且记得上次你欠了他什么。** 人脉表解决的就是这件事。

**先登记，再引用。**（登记表在 `content/07-contacts.js`）

```js
POTUS.define("contact", {
  fixer: {
    name: "掮客", role: "牵线搭桥的门路", tag: "门路",
    note: "没人说得清他到底替谁工作。他不解决问题，他介绍解决问题的人。"
  }
});
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✓ | 界面显示的名字（人脉面板、`req.contact` 的提示文案都用它） |
| `role` |  | 一句话身份，显示在名字右边 |
| `tag` |  | 分类短标签（"门路" / "钱" / "街头" …） |
| `note` |  | 给内容作者看的设定说明，不会显示给玩家 |

**在事件里怎么用**：

```js
// 选项门槛：不认识就点不动，且会告诉玩家"需要先认识「掮客」"
{ id: "ask", text: "让掮客替你牵一根线", req: { contact: "fixer" }, … }

// 事件级门槛：先认识，这件事才会发生
{ id: "deep_favor", contacts: ["fixer", "lobbyist"], … }   // 两个都要认识

// 好感变化：第一次出现就代表"从此认识"（从 0 起算，并自动登记进存档）
effects: { contact: { fixer: 12 } }       // +12
effects: { contact: { shark: -8 } }       // 得罪了也算认识
effects: { forget: ["fixer"] }            // 彻底断掉（你把他卖了，或者他死了）
```

**好感度语义**（夹在 `-100 ~ 100`，和派系好感同一套口径）：

| 区间 | 含义 |
|---|---|
| 30+ | 可以开口求一件难事 |
| 10 ~ 29 | 平时能办事 |
| 0 ~ 9 | 只是点头之交 |
| -1 ~ -19 | 需要先修关系 |
| -20 以下 | 他会主动坏你的事 |

**写人物时的三条约定**：
1. **一个人只负责一类资源**。找钱的别来找他要选票，要选票的别来找他借钱。
2. **人物不写死年代**——他们的"位置"在任何年代都存在（1980 年的电视制作人与 2008 年的电视制作人是同一个人设）。需要限定年代时写在**事件**上，不写在人物上。
3. **`content` 里提到的人，登记表里必须有**。校验器会逐条核对 `ev.contacts` / `req.contact` / `effects.contact` / `effects.forget` 里出现的每一个 id。

### 4.11 事件链（`ev.after`）：让一个故事横跨数月甚至数年

**这是"事件和流程太短"这个问题的正解。** 普通事件是"一个月里的一件事"；事件链是"一件事在几个月里长成另一个样子"。

```js
// 第一幕（头）：正常写，但要 unique: true
{ id: "archive_get", grade: "mid", unique: true, … }

// 第二幕：前情必须已演过，且间隔落在窗口内
{
  id: "archive_bite", grade: "mid", unique: true,
  flags: ["archive_taken"],                       // 只在"把档案带走了"这条岔路上继续
  after: { id: "archive_get", minMonthsAfter: 3, maxMonthsAfter: 30 },
  …
}
```

引擎会自动做三件事（`engine/events.js` 的 `P.eligible`）：

| 行为 | 规则 |
|---|---|
| 前情没演过 | `monthsSince(prev) == null` → **直接不可触发**（不是权重降低，是整个事件不存在） |
| 间隔不在窗口 | `minMonthsAfter` / `maxMonthsAfter` 是**月**，不是年。太早不像故事，太晚像巧合 |
| 前情演过 | 该事件权重 × `balance.chainWeightMul`（默认 9），所以它几乎一定会来，只是隔几个月才来 |

**界面上会出现一条「承 前」小条**，写着上一幕的标题和相隔几个月——让玩家明白这不是一堆随机事件，而是一件还没完的事。

**写链的四个坑（每个都会让链条穿帮）**：

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 忘了 `unique: true` | 同一幕会重复出现 | 链上每一幕都写 `unique: true`（`grade: "major"` 默认已是 true，其余要显式写） |
| 用 `flags` 当"前情" | 玩家没拿到那个 flag 时链就断了，而且看不出来为什么 | 用 `after` 表前情，用 `flags` 表**岔路**（"有没有把东西带走"） |
| 最后一幕不分岔 | 前面怎么选，结尾都一样 | 最后一幕用 `req: { flag: "…" }` 分支，并且**每一幕的每一个选择、每一档结果都要打上同一个标记** |
| 忘了保底选项 | 分支一多，很容易所有选项都带 `req` | 分岔之外永远留一条既无 `cost` 又无 `req` 的路（见 §4.3.1） |

样板实现：`content/events/84-archive.js`（四幕：拿到 → 被反噬 → 摊牌 → 了结，最后一幕按 `req.flag` 读出四种完全不同的收尾）。

### 4.12 minTenure：晋升要熬够月份

`ev.minTenure`（单位：**月**）要求玩家在当前层级至少待够这么久，才会出现该事件。

```js
{ id: "prog_senate", grade: "major", minTenure: 48, … }   // 在 T3 待满 4 年才谈得上去参议院
```

- 层级一变（`effects.tier`），在位计时**自动重置**（引擎侧）。
- 状态面板会显示「在位 X 个月」，玩家看得见自己离下一级还有多远。
- 这条是"一局太短"的第二根柱子：**光有事件不够，台阶本身也要花时间**。
- 取值：基层/州级 18~24；参议院/总统 48；任命/造王者/巨富 18；名人 12。
- 所有 `prog_*` 晋升事件都必须声明 `minTenure`——校验器会拦。

### 4.7 brief（背景卡：主角视角的认知边界）

事件最容易犯的错，是把玩家直接丢进一个他完全看不懂的局面——"什么是救市？为什么要救市？谁发动的？" **每个事件都应该交代主角此刻能看见什么、以及他看不见什么。**

```js
brief: {
  lede: "财政部深夜来电。你要在四个小时里，替一场你还没搞懂的事背书。",  // 可选，折叠时显示的一行
  known:   ["你确知的客观事实……"],          // 主角视角能看到、能理解、能核实的
  rumor:   ["你听到的、真假不明的话……"],    // 传闻：可能真、可能假、可能被人故意放出来
  unknown: ["你不知道的事……"],              // 认知边界：明确告诉玩家"这里有信息差"
  terms:   [{ k: "救市", v: "把名词讲清楚" }] // 名词表：给不熟悉时代背景的玩家
}
```

四块的定位，缺一块就少一层：

| 块 | 作用 | 写作要点 |
|---|---|---|
| `known` | 玩家做判断的**事实基础** | 写"主角视角能看到的"：他读到的数字、他认识的人、他手上的文件。**不要写成上帝视角的历史总结。** |
| `rumor` | **制造不确定性** | 用「有人说…」「有律师朋友在饭局上说…」。真假不明，其中可能有对手放的假消息。不要标注哪条是真的。 |
| `unknown` | **点明信息差** | 这是本机制的灵魂。写主角意识不到后果的地方，等价于对玩家说："你知道这段历史的话，这里可以占便宜。" |
| `terms` | **降低门槛** | 只解释名词（救市、TARP、初选、弹劾条款），**不解释剧情**。不熟悉这段历史的玩家也能跟上。 |

**三条硬规矩**：

1. **`known` 不能剧透**。主角不知道的事，就不许写进 `known`。想让玩家知道，放进 `terms` 或让他自己去联想。
2. **`unknown` 必须真的"不知道"，不能是"未来会怎样"的流水账**。写法是点出**后果的位置**，不是点出后果本身。
   - 好：`你读不懂的那几条授权条款，将来会成为对手手里的刀。`
   - 差：`两个月后国会会否决这个法案，你会因此丢掉席位。`（这是剧透，不是信息差）
3. **`rumor` 里可以埋真话，也可以埋假话**，但**不要用语气暗示真假**。让玩家自己赌。

**什么时候可以不写 brief？** 只有一种情况：事件本身就是纯机制演示、没有叙事场景。除此之外（包括跨时代通用的晋升链）都应该写。

### 4.13 vignette（静好岁月：平静月份的随笔与成长）

一个月的回合制里，**一年有 8 个月左右是"平静"的**（没有档期、没有事件）。原本它们只在月历条上留一行「平静」二字。
`vignette` 就是那些月份的内容：给主角一段**日子**，并且让他在这些日子里**按部就班地长**。

```js
POTUS.define("vignette", {
  title: "静好岁月",              // 卡片标题（可选，默认「静好岁月」）
  lede: "没有大事发生的月份。",     // 卡片副题（可选）
  fragments: [ /* 片段，见下 */ ]   // 可多次 define，fragments 会累加
});
```

#### 一个片段

```js
{
  id: "se03",              // 唯一（校验器查重）
  slot: "season",           // 必填，见下面的槽位表
  months: [3],              // 只有 3 月能用（时令片段用）
  texts: [                  // 随机挑一句 —— 同一个处境给几种写法，素材量翻倍
    "三月。雪化得比往年早，路上的泥一踩一陷，风里有股湿土的味道。",
    "三月，树还是光的，但那种光已经不同了——你知道它底下正在动。"
  ],
  // text: "…"              // 只写一句时可以用 text 代替 texts
  weight: 1,                // 同槽位内的相对权重，默认 1
  brk: false                // true = 这一段前面断开（另起一段）
}
```

#### 六个槽位（顺序固定，引擎每个槽位抽一条，按顺序接起来）

| slot | 意思 | 该写什么 |
|---|---|---|
| `season` | 时令 | 跟着月份走：三月化雪、七月暑气、十二月橱窗亮起来。**必须覆盖 12 个月** |
| `world` | 世相 | 这个年代的人靠什么知道世界：报纸/电视/电台/手机/邮件/加油站的队伍 |
| `work` | 案头 | 他每天在干什么（按轨道 + 层级分） |
| `life` | 日常 | 家、身体、朋友。**建议 `brk: true`**，让它另起一段 |
| `self` | 心绪 | 由当前处境决定：病了、手里有把柄、名声在外、年岁渐长 |
| `close` | 收束 | 一句余味。**建议 `brk: true`**，让它自己收尾 |

#### 片段的条件（全部可选，可组合）

| 字段 | 含义 |
|---|---|
| `era` / `notEra` | 时代 id 数组 |
| `tracks` / `parties` / `stances` / `origins` | 对应注册表的 id 数组 |
| `tiers` / `minTier` / `maxTier` | 权力层级 |
| `minAge` / `maxAge` | 年龄 |
| `months` | 月号数组（1-12），时令片段用 |
| `flags` / `notFlags` | 状态标记 |
| `minLev` / `maxLev` | 把柄份数 |
| `minRep` / `maxRep` | 声望 |
| `minHp` / `maxHp` | 健康 |
| `minFun` / `maxFun` | 资金 |
| `minContacts` / `maxContacts` | 认识的人数 |
| `cond(G, P)` | 自由判定，返回 true 才可用 |

#### 硬性要求（`validate.js` 会拦）

1. **时令必须覆盖 12 个月** —— 否则某个月的随笔会缺掉开头。
2. **除 `season` 外，每个槽位至少要有一条"无条件片段"**（不写任何条件字段）。
   理由：玩家可能同时病重、破产、被调查、年迈——条件写满了，反而一段都抽不出来。
3. `slot` 必须是上面六个之一；`text`/`texts` 不能空；`id` 唯一；`weight` 为正数；
   引用的 era / track / stance 必须存在。
4. 校验器还会跑遍 **时代 × 轨道 × 层级 × 月份** 的全部组合（现役 5 时代 × 5 轨道 × 层级 0-9 × 12 个月），以及 9 种极端处境（病重/穷困/巨富/丑闻/把柄/垂暮…），
   任意一种拼不出文字都会报错。

#### 成长曲线（`balance.vignette`）

叙事之外，平静的月份还会让主角"按部就班地长"。**数字不在内容片段里，统一在 `balance.vignette`**：

| 键 | 默认 | 含义 |
|---|---|---|
| `enabled` | `true` | 关掉就完全没有随笔与成长 |
| `maxShown` | `4` | 一次最多展开几段（更久的平静收成一句「另有 N 个月」） |
| `attrChance` / `attrGain` / `attrCap` | `0.08` / `1` / `88` | 每个平静月长属性的概率与上限。**#37③ 从 0.20→0.14→0.08**；`attrCap` 刻意压在**自由点硬顶 100 之下**——岁月永远不该把点推到玩家自己分配不满的高度（撞顶即停止成长，不倒扣），validate 钉 `attrCap < 100` |
| `attrKeys` | `["CHA","INT","CUN"]` | 哪些属性会长（**轨道对应的主属性权重 ×3**；INTG 自 v0.5.2 起不再靠平静月长，改由事件塑造） |
| `attrAgeFade` | `true` | 越老越长不动：`×(1 - 已从政年数/60)`，下限 0.25 |
| `hpChance` / `hpGain` | `0` / `1` | 平静月恢复健康的机会。**默认 0，是个刻意的选择，见下** |
| `repChance` / `repGain` | `0.06` / `1` | 常年露面攒下的一点名声 |
| `contactChance` / `contactGain` | `0.20` / `1` | 关系要维护：随机一位人脉好感 +1 |
| `apChance` / `favChance` | `0.25` / `0.08` | 平静月的人情/精力小惊喜（精力 ap 已退役、不上界面，键仍可读） |

> **平静月不再产生资金（#37③）**：原 `funChance 0.30`（±$0.5k—$8k）与 `funRate` 两条通道**整条删除**，
> 因为随笔侧直接改 `G.fun` 会绕开 `P.monthlyLedger` 这单一流水，玩家在月账上找不到来源
> （实测投诉：「这个月账是赤字，下面却写『按部就班 资金 +$6k』」）。
> 钱从此只有两条门：**月账**（工资−开销−学贷，年终结算吃 `interestRate`）与**事件卡**。
> validate 侧 `funChance`/`funRate`/`trackBonus.*.fun` 任一出现即红。生息要重启请走月账，不要走这里。

> **`hpChance` 为什么默认是 0**：这个游戏的死亡率正好卡在退休年龄那条线上（年度衰减约 2 点，100 点撑 50 年），
> 所以平静月只要回一点点健康，就会把一大批"累死"翻成"退休"。
> 历史 A/B（`validate.js --games=300` 全量口径，同种子才可比）：`0.00` → 因病去世 ~111-126；`0.04` → 48；`0.28` → 0。日常快速校验默认 20 局，小样本看趋势别看绝对值。
> 想要"平静的月份让人喘口气"的手感，就调到 `0.04`，但要知道整个终局会明显变温和。

#### 三个坑

1. **不要在片段里写具体数值**（「你涨了 3 点声望」）。数值由 `balance.vignette` 统一结算，片段只负责画面。
2. **时代准确性**：1980 年不能出现短视频、社交轰炸。校验器不会拦这个（它读不懂文学），靠你自己把关。
3. **不要把"事件"写进随笔**。平静月之所以是平静月，就是因为它没有转折。写成小高潮，就等于把事件的活儿干了两遍。

## 4.15 photo（事件配图的照片层）

引擎的配图是**三级降级**的（`engine/art.js` 的 `P.artSVG`）：

```
1) 内容级渲染器（POTUS.art(fn) 注册）   ← 照片层挂在这里，最优先
2) 事件自带的 ev.art
3) 事件类型 category 的默认图（程序化 SVG，见 §4.8）
4) 引擎内置兜底（永远有图）
```

照片层的实现是 `content/09-photo-art.js`，它只做一件事：**能给照片就给照片，给不了就 `return null`**，
让下面三层照常工作。所以「有照片」「没照片」「照片挂了」三种情况都不会白屏。

### 登记表

```js
POTUS.define("photo", {
  dir: "assets/events/",                  // 相对 index.html；多次调用时后写的覆盖它
  files: {
    career: "career.jpg",                 // 类型 key → 文件名；多次调用会逐条合并
    scandal: "scandal.jpg"
    // …没登记的类型 = 走程序化 SVG
  }
});
```

| 字段 | 说明 |
|---|---|
| `dir` | 图片目录，相对 `index.html`。默认 `assets/events/` |
| `files` | `{ 类型key: 文件名 }`。key 必须是 `reg.category` 里真实存在的类型，否则照片永远轮不到 |

### 单个事件覆盖 / 关闭

| 写法 | 效果 |
|---|---|
| `ev.photo = "my-shot.jpg"` | 这个事件用指定图片（文件名相对 `dir`） |
| `ev.photo = false` | 这个事件不要照片，走程序化 SVG |

### 三条硬规矩

1. **文件名由登记表给，代码里不硬编码路径** —— 换图只要把新图命名成 `<类型 key>.jpg` 覆盖同名文件。
2. **每张照片卡里都预垫了一张"本来会画的"程序化 SVG**（`.art-back`）。图片加载失败时 `onerror`
   把它翻出来顶上，玩家不会看到破图。这条是为了兜住「只拷了部分文件」「改了文件名」这类事故。
3. **照片层坏掉不能连累配图**：整段逻辑包在 `try` 里，抛异常就退回 SVG。

### 尺寸与配色

- 卡片正文列宽约 636px（`#app` max-width 1600px、`.grid` 1fr+260px、`.news` 内边距 16px；style.css 断点 1000/820/600px，600px 以下走竖屏三区竖排版式，照片层不变）。
  照片压到**最大边 900px / JPEG q78** 就够（1x 清晰、2x 不糊），十张合计约 860 KB。
- 画框是 `aspect-ratio:16/9` + `max-height:260px` + `object-fit:cover`，所以**原图比例不必统一**，
  但主体尽量居中，否则会被裁掉。
- 卡片上会压一层时代主色（`--era1`）的淡色罩，让照片和报纸版式同一个调子；左下角有类型角标。

### 怎么验收

- `node tools/validate.js` 会**逐个检查登记的照片文件在不在于磁盘上**（这是最容易静默翻车的地方），
  并断言「有照片出 `<img>`、没照片退回 SVG、`ev.photo` 覆盖与关闭都生效」。
- `node tools/smoke-ui.js` 会真的渲染事件卡，断言 `.art-photo` / `<img src>` / 角标 / `.art-back` 垫片，
  并**派发一次 `error` 事件**验证破图态会切换。
- 要看照片在卡片里的实际观感（不真开局）：浏览器打开 `tools/preview-photos.html`。

### 4.16 valence / dyn：三值性与动态经济（v0.6+，每张卡必填）

这是本项目最核心的两条契约。**每张事件卡都必须显式声明 `valence` 和 `dyn`。** 它们一起实现了整部作品的设计哲学——**同一件事，对不同处境的人，意义完全不同。**

#### 4.16.1 valence（三值性：机遇 / 风险 / 威胁）

每张卡属于三种"情绪基调"之一。抽取时**每个档期独立掷一类**（两段式：先掷三值性，再在该类池里按量级抽卡），类与类互不挤占——有了好运不会挡掉坏事。

| valence | 徽标 | 语义 | 引擎保证（`shapeByValence` 强制） |
|---|---|---|---|
| `boon` | 🟢 机遇 | 净收益是**下限** | 删掉所有 `cost`、抬升 `base`、把每一档结果里的**负值抹平为 0**——掷骰最差也只是"少赚"，绝不转盈为亏。 |
| `risk` | 🟡 风险 | 保底或博一下 | 缺保底时**自动注入**一条无风险退路；波动幅度可以很大。 |
| `bane` | 🔴 威胁 | 默认净损 | **保持原样**——但靠高掷骰 / 高属性 / 花钱仍可规避，甚至"化险为夷"。 |

- **内容侧只写"意图"，契约由引擎在结算层（`engine/scale.js` 的 `shapeByValence`）强制执行**——所以不用担心 boon 卡里手滑写了一个负数会破坏契约。
- 漏标 `valence` 时按 `balance.valenceDefault`（默认 `risk`）兜底；校验器 `--val-strict` 会把漏标判为错误。
- 掷三值性的权重见 `balance.valenceWeights` / `valencePressure`（§10）。该类池空时按 `VAL_CHAIN` 优雅降级（优先降级到 risk 当缓冲垫），不会崩——但代价是"掷中机遇却被静默降级"，所以**每个时代都要有 boon 卡**。

#### 4.16.2 dyn（动态经济：卡只存系数，结算时 × 人物标尺）

声明 `dyn: true` 的卡，其 `effects` 里的 `fun` / `rep` / `hp`（以及 `cost` 里的 `fun`）都是**系数**，不是绝对金额。抽中这张卡的瞬间，引擎调用 `P.realize(ev)` 把系数翻译成"此刻这个人物"应得的绝对值副本。

```
钱的标尺 fun = 职位月薪 officeSalary × funMonths[grade] × 属性系数 × 职级系数
声望的标尺 rep = repBase[grade] × (1 + tierLean × 层级偏离)
健康的标尺 hp  = hpBase[grade]  × (1 + hpTierLean × 层级偏离)
```

于是**同一句"赚 0.5 份钱"，社区小兵拿到是几千块，州长拿到是几十万**——经济的"体感通胀"随生涯自动缩放，而内容只需维护一份系数。

系数合法区间由 `balance.econ` 校验：`fun` / `rep` / `hp` 等资源系数在 `[coefMin, coefMax]`（默认 `[-8, 8]`）；`money` 单独放宽到 `coefMaxFun`（默认 150，因为大额贿金/收购对低标尺天然上百份）。参数明细见 §10 的 `econ` 行。

> 迁移：把一批写死绝对金额的旧卡转成系数，用 `dev/tools/migrate-scale.js`；改 `econ` 参数会平移全局经济曲线，**改完必须重跑 `validate.js`**。

#### 4.16.3 投注级别价（`stakeRates.fun` · #28① 只留身位锚）

投注（§4.4）里"钱"这一档的金额从来不是全游戏常数，它换过四套口径（`engine/dice.js` 的 `P.stakeFunPer` 顶注同步记着这段演进）：

- **v0.6 之前**：`per` 全库写死 $250k —— 小兵永远投不进第一档，"收益 $50k 的事让你压 $250k"。
- **v0.7**：加**事件钱量级锚**（这件事本身押着多少钱），两锚几何平均 `per = min(√(A×X), X)`。
- **v0.12**：再加**钱袋闸**（单档 ≤ 现金×6%），合成升成立方根 `min(∛(A×X×G), G)`。它保证了"永远押得起"，却让玩家实测投诉「同一件事，穷时便宜富时贵」——单价自己又成了一次随机。
- **#28①（现行）**：两锚都删，**只留身位锚**。

```
每档金额 per = clamp( officeSalary(轨道,层级) × perSalaryMonths(默认 1) × gradeMul[本档量级], perMin, perMax )
              再抹成整数（dice.js 的 niceUsd，一律向下）
  月薪口径 = P.officeSalary()（reg.officeSalary，§0 表）—— 与平静月工资同源
  gradeMul {minor .6, mid 1, major 1.8}；perMin 500 / perMax 500000（content/01-config.js 的 stakeRates.fun）
  一档 ≈ 你这个位子一个月的月薪（大事按 1.8 倍放大手笔）
```

- **余额彻底不参与单价**：v0.12 的钱袋闸参数 `cashStakeShare` 与事件锚参数 `potShare` **已删除**，连算事件钱量级的 `P.stakePot()` 函数本身都不存在了。余额唯一的用处是决定你押得起几档：`stakeMax = min( ceil(cap ÷ w) = 8 档, floor(现金 ÷ per) )`。**投得起几档是家底的事，一档多少钱是位子的事。**
- 手感基准（照 `reg.officeSalary` 的表值算，抹零一律向下）：T0 志愿者月薪 $1k → 小事一档 $500、大事 $1.5k，押满 8 档要小半个月工资；T7 联邦参议员/州长月薪 $17k → 一档 $10k—$30k；财富轨 T7 超级富豪月薪 $80k → 大事一档 $140k。六位数的档位是"钱买出来的位子"给出的，不是内容写出来的。全部由薪资表推导（`perMax 500000` 在当前薪资表下几乎够不着，它是护栏不是常态）——**改工资表会同时改日常收入与投注价码，这是有意的**。
- 内容在 `stake.fun` 里写死 `per`（`stake:{fun:{per:777000}}`）时以内容为准（绝对覆盖，汇率来源标 `source:"content"`），供"这一注就是天价"的剧情用。
- 界面把依据摊开成一条 `.stake-rate` 说明（`engine/view/actions.js` 的 `P.stakeRateNote`），只有两分支：级别价 → 「每档 {v}：按身位定价 —— 月薪 {s} × {m} 个月{gm}。家底只决定你押得起几档，不改单价。」；写死 per → 「这一注的价码由剧情写定」。金额一律走 `P.fmtUsd()`（$400 / $6.1k / $1.5M）。
- **断言口径**（`validate.js`「投注级别价（单价随身位·不随钱包）」）：旧的「8 档总投入 ≤ 2× 事件钱量级」随事件锚退役、「单档 ≤ 资金×cashStakeShare×量级系数」随钱袋闸退役，两条都已从 validate 里删除。现行钉死的是：同一身位下**单价恒定**（余额 2 万与 200 万报同一个 per、选项写没写钱都同价）、档数 = `min(8, floor(余额÷单价))`、major 一档贵过 minor、T0 家底 $10k 至少投得起 1 档、写死的 `per` 原样保留且 `source==="content"`、per 落在 `[perMin, perMax]` 且为 500 的整数倍。

#### 4.16.4 三层状态感知（把"一切结合人物属性"落到机制上）

设计哲学的完整落地是三层判定，写卡时对应到三个字段族：

| 问题 | 引擎机制 | 你要写的字段 |
|---|---|---|
| **这件事该不该发生？** | `engine/when.js` 声明式条件 | `era` / `tierMin` / `minFun` / `flags` / `after` / `scandalMin` / `contacts` / `minTenure` …（见 §4） |
| **这个选项该不该让他选？** | `engine/view/stage.js` 的 `reqBlock`/`costBlock` 把不够格/付不起的选项**置灰并写明原因** + `P.fallbackIndex` 保底 | 选项上的 `req` / `cost`（见 §4.2 / §4.3） |
| **该花多大代价、换多大收益？** | `scale.js` 标尺 + `stakeFunPer` 级别价 | `dyn` 系数 + `stake`（见 §4.4 / §4.16.2 / §4.16.3） |

一句话：**你只管把"意图 + 系数 + 门槛"写清楚，"此刻对这个人意味着多少钱、能不能选"交给引擎。**

### 4.17 chore（日常公务 / 选民服务池）

为了让"在任者"每个月都有轻量的选民经营可做的事，新增一条**不走随机卡池**的注入通道（`content/events/111-chores.js`）：

- **入口**：事件写 `chore: true` + `category: "govt"`。`events.js` 的 `eligible` 顶部会 `if (ev.chore) return false`——chore 卡**永不进随机池**，只经 `time.js` 的 `P.choresSlot(isEmptyMonth)` 注入。
- **谁能撞上**：不设全局层级闸（v0.12 起 T0 志愿者也有家务事可做）——层级由每张 chore 卡自己的 `tierMin/tierMax`（`tierRaw:true` 分簇）逐条把关。
- **频率**：加权随机 0～1 + 空月保底 1——本月若已有 fixed/竞选档期则按小概率 `chance` 追加；本月本来空档时按 `emptyFillChance` 兜底一条。**优先级低于 fixed**，不抢定点事件。#32 曾把它抬到 `{chance:0.25, emptyFillChance:0.7}`（随机类被年度额度限到 1—2 件之后，「几个月蹦一次职业事务」这条节奏线改由公务池自己补，目标 T2—T6 每 2—4 个月一蹦 ≈ 3—5 件/年）；**现行 `{chance:0.10, emptyFillChance:0.40, repeatMonths:18}`**（`core.js` 的 `choreDynamic`，配置未覆盖）——`repeatMonths` 是同一张公务的重演间隔，它不走随机卡的 `recentIds` 窗口（那条 20 抽窗口≈2.4 年，一个层级只有几张公务卡共用它，抽完一张就饿两年多）。定标口径是**四大类不许倒挂**（固定 ≥ 职业 ≥ 随机）而不是「公务越多越好」：关掉通道时职业 0.62/年（随机 1.85）被倒压，全开 0.25/0.7 时冲到 3.68/年把固定历史（2.3）盖掉。**#35 之后重标**：竞选改按选情收口，拖垮/提前结束的月份空出来被空月兜底吃掉，0.45 时职业涨到 2.54/年、重新压过固定 2.31/年 → 水位下调到 **0.40**，实测（`--games=20`·样本 626 年）**固定 2.51 ≥ 职业 2.13 ≥ 随机 1.89**（灰产另计 1.73·竞选 0.57）。这条线是**联动量**：动竞选节奏、动随机额度或动钉卡密度之后都要重读一次 `四大类【年均/局】`。
- **年代覆盖是硬要求**：通道的候选闸是 `P.yearOK(e)`，所以**每张 chore 卡的 `maxYear` 就是这条线在那一年的生死**。实测教训：111-chores 最初十二张全写 `maxYear: 1999`，2000 年以后整个职业节奏线直接断流（年均 1.1 件），概率旋钮怎么抬都灌不进来。写新 chore 时按「四个层级簇 × 每十年」自查一遍，任何一格都不该空着。
- **形状**：按 `tierRaw:true` 分四层级簇（基层 T0–2 / 市政 T2–4 / 州 T4–6 / 联邦 T6+），`grade:"minor"`、低权重、`valence` 多为 `boon`（经营选民"只赚不赔但赚得不多"）、主吃 `voters`（warm/diehard↑、oppose↓）+ 少量 rep。
- **开关**：`balance.choreDynamic = { enabled:true, chance:0.10, emptyFillChance:0.40, repeatMonths:18 }`；`enabled:false` 即完全回到现状（引擎不注入任何 chore）。删掉 `111-chores.js` 两行接入亦可一键回退。

> 每卡仍守硬约束：≥ 2 选项、每选项五档齐全、至少一个既无 cost 又无 req 的保底选项（§4.3.1）。

### 4.18 树敌与清算（wrath · v0.12 生存线）

v0.12 的顶层交换率：**生存率是拿升官速度换的**。大收益选项往隐藏计数器里攒恨，恨攒够了来收你。

**注册表**（`01-config.js` 的 `POTUS.define("wrath", …)`，五组仇家）：

| 组 id | 名称 | 报复手段（叙事口径） |
|---|---|---|
| `press` | 新闻界 | 围剿、构陷式报道、旧话逐条对质 |
| `establishment` | 党建制派 | 初选候选人、黑名单、听证会上给你留位置 |
| `money` | 金主 | 断供、转向扶持对手、让银行「重新评估」你的每一笔钱 |
| `opposition` | 政敌 | 政治陷害、诬告、往人群里派拿枪的人 |
| `agency` | 情报/执法系统 | 匿名泄密、翻旧账、让卷宗「恰好」出现在记者桌上 |

**攒恨**：效果写 `count: { wrath_press: 8 }`（§6，累加、下限 0、**永不衰减**）。
刻意不上状态面板——玩家在决策预览里看到的是红色「⚠ 树敌：媒体」角标（stage.js 扫全 outcome 档的 `count.wrath_*`）。
**全游戏只有约 15 处精选树敌点**：只标真正结仇的选择，不许遍地开花，更不许逢晋升就记恨。

**两拍节奏**（`events/140-reckoning.js` 清算包，10 张卡 = 5 组 × 两拍）：

1. **前哨战**：`grade:"mid"` + `when.countMin: { wrath_<组>: 25 }`。给出泄压阀——低头/交钱/示好选项用实打实的声望与派系代价削恨（`count` 负值）。认怂是统一手感：高成功率、削一大块恨、但政治代价照付。
2. **清算**：`grade:"major"` + `unique: true` + `countMin: { wrath_<组>: 55 }`。赌赢踩着尸体上位，**fail/critfail 直接 `hardEnd`——即死，无保底**。

**死法 reason 四新值**：`assassinated`（政敌的枪）/ `framed`（情报系统的档案）/ `ruined`（报业围剿收官）/ `purged`（党的机器）。
每条对应 `40-endings.js` 的 reck_* 黑色幽默成就（F 级，zh+EN 双语，梗全部锚在真实史上——肯尼迪发型、尼克松敌人名单第 21 位）。

**写法契约**（照 140 的骨架，别自创）：
- `tierMin` 一律配 `tierRaw: true` 按 10 级空间直写，不走旧档映射；
- `era: ERAS`（全时代文件头 `Object.keys(POTUS.reg.era)`），年份门槛靠 `minYear/maxYear` 绝对年窗；
- 安全选项可以存在，但每一条都必须有实价——**「不许有免费的不出头选项」是这条线的立身之本**；
- 报复手段要有真实历史原型，写进文件头注释（140 的十条出处即范本）。

### 4.19 2025 硬墙与生涯结算（career_end · v0.11+）

`balance.endYear = 2025` 是唯一权威终年（core.js 默认 + 01-config 覆盖；stage.js 的 `endYear()/nextSlot()` 收口，越不过终点年）。

- **当总统不再即时终局**：登顶后照常按月往前走，直到 2025；死亡/入狱/清算等 hardEnd 仍可提前结束。
- 到点年终结算屏弹「查看生涯结算 →」按钮 → `P.careerEnd()` → `P.ending("career_end")`。
- `G.peakTier`（core.js 初始化、每次升层级同步）记录生涯峰值——**结算看峰值，不看终局那一刻的处境**；结算页同时展示 peakTier 与生涯跨度。
- 结局规则写法（`40-endings.js` career_* 家族 7 条，priority 95→65）：
  - `career_president_great` / `career_president`：`when: { reason:"career_end", flags:["president_done"] }`（great 另排除 scandal_4/5）——前总统用 `president_done` 标签区分；
  - `career_heavyweight/federal/state/local`：`{ reason:"career_end", tierRaw:true, tierMin:7|5|3|1 }` 按峰值发阶梯成就；
  - `career_quiet`：无 tierMin 兜底——「平静的一生」也是一枚成就。
- 定点大事（worldline/fixed）铺到 2024；**2025 年起没有任何抽取内容**，别往 2025+ 挂卡。

### 4.20 单卡节奏：终身衰减 · 硬冷却 · debuff 续燃（v0.12）

「宁少重复，不要刷屏」。同一张卡不许年报式刷脸，实现全部在 `events.js`：

1. **终身权重衰减**：一张卡这局演过一次，再入池时整条权重 × `balance.idRepeatMul`（默认 **0.15**，全局旋钮、不吃 clamp）——回访也基本撞不上。
2. **硬冷却**：演出后 `idRepelMonths`（默认 **24**）个月内，抽取四级降级的最后一级兜底（pass3）都不再放行该 id——和「本月已演」同级的硬闸。豁免：`prog_*` 晋升卡与定点档期（竞选幕/公务/重试那几条结构通道各有自己的节奏闸，validate 有作用域断言钉死）、以及 `pace:"exempt"` 的投机卡（见 §4.21）。
3. **debuff 续燃例外**：卡上写 `rereq: {…}`（when 词汇）且当前命中 → 豁免终身衰减（权重改吃 `ev.rereqMul`，默认 1），冷却缩短为 `idRepelRereqMonths`（默认 **12**）——「麻烦的家人可以回来，但不能变成年报」。示范卡：`sca2_family_member`。
4. `period` 字段仍可按卡覆写冷却月数；`skipUntil` 是已死字段，别写。

探针口径（validate「同卡重演」面板）：同卡 **<12 个月重演占比应≈0**（v0.12 前是 38.9%）；dyn 填充卡 147 次/局 → ~24 次/局，填充器代价 ~7.9%。内容侧无需配合——**这是引擎契约，写卡时不要试图用 `unique:false` + 高权重绕开节奏**，会被冷却闸原地没收。

### 4.21 事件四大类（eventKind）· 年度节奏（pace）· 同年分层（#32）

一局生涯的月份被四种"性质不同"的事件填满。分类**不新增人工字段**，全部由已有声明派生（`P.eventKind(ev)`，`engine/events.js`），所以老卡零迁移、也不会出现"字段与卡面自相矛盾"：

| 类 | 派生规则（按顺序命中即止） | 节奏由谁负责 |
|---|---|---|
| `campaign` 竞选 | `category:"campaign"`，或 `P.isCampaignActEvent(id)`（竞选幕） | `campaign.js` 逐幕推进，**计进四桶账但从不被额度拦**（链要一幕幕演完），只受"每月一幕"约束 |
| `fixed` 固定历史 | 在钉卡表里（`P.pinIds()` = `reg.fixed` ∪ 各 era 的 `scheduled`），**或** `minYear === maxYear` | 到点必演（`planMonth` 以 eventId 定点排期），**不计入也不吃额度** |
| `career` 职业/公务 | `chore:true`，或 `category:"career"` / `"govt"` | `time.js` 的 `choresSlot` 注入（§4.17），**吃 `careerMax` 年额度**（#38 起） |
| `random` 随机 | 其余全部（含 `shady` 灰产、`civil` 民权、`media`、`scandal`…） | **吃年度额度**，见下 |

> #21 M1 起还有第 5 类：`whitehouse`（`ev.wh`，派生顺序在 `fixed` 之后、`career` 之前）。它和公务同性质——到点必演、不吃额度，但只在总统在位时由 `presidency.js` 的 `whiteHouseSlot` 每月排一条，详见 §4.22。

> 口径备案：WORKPLAN 原写的是 `category ∈ {govt, civic}`，登记表里没有 `civic` 这一类（有 `civil` = 民权社会运动）。民权运动是"时代氛围里撞上的事"而不是"你职务上的活"，故留在 `random`；`career` 仕途类补进职业通道。

#### 年度额度（`balance.pace` · #32 → #38 定稿）

`pace: { enabled: true, yearRandomMax: 1, grayMax: 1, careerMax: 2, eventMax: 6 }`（键在 `engine/core.js` 的 `BALANCE_DEFAULTS`，`01-config.js` 未覆盖）。

**#38 的产品承诺**：玩家一年看到 **2—6 件"会刷屏"的事**——这个数只统计**非固定四桶**：日常公务（career）＋随机（random）＋灰产（shady）＋竞选幕（campaign）。
**真实历史钉卡（`fixed`）与总统在位期的白宫月决策（`wh`）不计入、也永不被额度拦**——它们是"到点必演"通道，把 2—6 套在它们头上等于把 1989/2008 削成空白年。

| 键 | 管什么 | 由来 |
|---|---|---|
| `eventMax` | **非固定四桶的年总闸**（=6）：`P.nonFixedRoom()` 归零时，随机不再排档期、公务通道直接闭流 | #38 新增——前三轮都在调概率，而概率只管"哪个月有空档期" |
| `careerMax` | 日常公务的年额度（=2）：`P.careerRoom()` | #38 新增——它从前只吃触发概率，实测 1.9 件/年且方差极大，是"月月有会开"的主渠道 |
| `yearRandomMax` | 非灰产随机档期的年额度 | #32 立 2 → **#38 收到 1**：事件总量的一半不该是巧合 |
| `grayMax` | 灰产/豁免（`category:"shady"` 或 `pace:"exempt"`）单独记账、单独上限 | #28 留的投机门 → #37① 4→2 → **#38 2→1** |

> **额度才是事件总量的真闸门**（#37 实测教训）：一个月一旦被判定"有事"，档期会一路填到年度额度为止。
> 所以只下调 `activeChance` 几乎不减事件数——它减的是"有事月的个数"。要调密度，动 `pace`。

三道闸，缺一不可：

1. **排期侧**（`time.js` 的 `planMonth`）：本月要排几条随机档期，先看 `P.randomRoom()`（它已经夹了 `nonFixedRoom()`），再扣掉**本月已排但还没结算**的竞选幕/公务（`pending`）——没额度就**少排**，多余的月份落回安静月/静好岁月，而不是硬抽。
2. **公务侧**（`time.js` 的 `choresSlot`）：开头查 `careerRoom()/nonFixedRoom()`，满额直接不注入（公务是注入通道，不走 `eligible`，所以必须单独查一遍）。
3. **抽取侧**（`events.js` 的 `eligible`）：`P.paceBlocked(ev)` 逐条拦——`random` 看自己的桶 + 总闸，`career` 看 `careerMax` + 总闸。

`P.grayRoom(snap)` 还做一次库存探针：额度没满但池子里已无可抽灰产卡时，不把额度预支掉——否则会出现"有预算却抽不到卡 → 掉进 `generateFiller` 填充器"的填充风暴（实测 28.5% → 5.8%）。

计数器挂在 `G.yearKinds` 上、按 `G.year` 自动翻篇，因此存档读档、`advanceMonth`、模拟器直接改年份都不需要额外的复位钩子。**豁免（永不被额度拦）**：`fixed` 定点档期、`wh` 白宫月决策、`prog_*` 晋升重试——以及**竞选幕**：它**计进四桶账**（2—6 的口径包含它），但从不被拦在半路，否则多幕链会留下演不完的「承前」。正因这条不拦，验收里的硬闸是「年均 ≤6 ＋ p90 ≤ `eventMax`+1」而不是"逐年 ≤6"。

同一条理由还决定了**开局两年该不该更薄**怎么量：validate 的方向断言只对着**吃额度的三桶**（公务/随机/灰产）说话。竞选幕在头两年常常一串四五幕（新人第一场地方选举），四桶总数因此会**高于**全局均值——那是竞选，不是冷静期失效；把它当回归就会把闸门越调越歪。

#### 开局冷静期（`balance.earlyCalm` · #37① → #38 降级为"轻闸"）

「刚开局前几个月接二连三发生」是最伤第一印象的一条，所以**开局 24 个月**有一条独立的减益层（定义在 `core.js` 的 `BALANCE_DEFAULTS`，与 `pace` 同一处；`01-config.js` 覆盖实际值）：

```js
earlyCalm: { enabled: true, months: 24, activeMul: 0.8, choreMul: 0.6, quotaMul: 0.5, slotsCap: 1 }
```

**#38 之后它的定位变了**：全局密度已经由 `pace` 收进 2—6 件/年，冷静期不再负责"补偿过吵的全局"（那轮的值是 activeMul 0.7／choreMul 0.4），只负责让**开局两年比全局再薄一档**。四个倍率各管一条通道，且都必须 ≤1（validate 拦方向做反的情况）。调参改 `content/01-config.js`：

| 键 | 作用点 | 实现 |
|---|---|---|
| `activeMul` | "这个月有没有事"的概率 | `time.js` 的 `planMonth`，**在 `clamp(activeMin, activeMax)` 之后**才乘——乘在前面会被下限默默吃掉 |
| `choreMul` | 日常公务注入频率 | `time.js` 的 `choresSlot`（#38 起这条通道还有 `careerMax` 年额度兜着） |
| `quotaMul` | **年度额度总闸** | `events.js` 的 `calmQuota(n)` = `floor(n × quotaMul)`，只乘在 `pace.eventMax`（6→3）与 `pace.careerMax`（2→1）上。**不能乘在随机/灰产的桶额度上**：那两个桶各只有 1 件名额，`floor(1×0.5)=0` 等于整桶封死而公务没闸，实测开局两年反而比全局稠（4.17 vs 3.10）。折扣只能落在**有降空间**的闸上 |
| `slotsCap` | 单月档期数上限 | `planMonth` 里 `n = Math.min(n, calm.slotsCap)`，夹在 `slotsMax` 之后 |

读数口是 `P.monthsInRun()`（`(年龄 − startAge)×12 + (月份 − 1)`）与 `P.earlyCalm()`：**出窗之后四个倍率必须完全中性**（`{1,1,1,Infinity}`），validate 有一条边界断言守着——它是"开局少打扰"，不是永久减速。`enabled: false` 或 `months: 0` 即整层关闭，回到 #37 之前的节奏。

> `paceQuota` 故意**不**写进 `P.paceCfg()`：那函数是 validate「随机 ≤ `yearRandomMax`」读的配置原值，把冷静期的折扣混进去会让断言量不到回归。

#### 豁免通道：`pace: "exempt"`（#28②，投机/灰产生意可以反复做）

灰色生意的设计前提是**可以重复**：同一笔庄家生意这局做三次不荒谬，一场家庭葬礼演三次才荒谬。卡上声明 `pace: "exempt"`（`P.paceExempt`，`engine/events.js` 文件头）换来三件事：

1. **不吃单卡终身衰减**——`idRepeatFactor` 对这类卡恒为 1（§4.20 第 1 条的例外）；
2. **不吃 24 个月硬冷却**——`eligible` 里的 `idRepelMonths` 闸直接跳过它；
3. **走 `shady` 年度额度而不是随机额度**——`paceBucket()` 把 `random` 类里 `category:"shady"` **或** `pace:"exempt"` 的卡单独记进 `yearKinds.shady`，上限是 `balance.pace.grayMax`（**#37① 收到 2/年、#38 再收到 1/年**；键在 `engine/core.js` 的 BALANCE_DEFAULTS，`01-config.js` 未覆盖），既不挤占 `yearRandomMax` 的那 1 条名额，也不会被它误杀。两个桶都还要吃 `eventMax` 总闸。

代价与边界，写卡时必须一起记住：

- **必须同时显式写 `unique:false`**。`grade:"major"` 的卡默认一局一次（`P.isUnique`），豁免了冷却却仍被 unique 挡死 = 永远只出一次。validate 有内容纪律断言逐条拦（`pace:"exempt"` 却 unique 的卡会直接报出来）。
- 豁免的是"同卡重复"，**不是"无限量供应"**：`grayMax` 满了照样 `paceBlocked`。
- `P.grayRoom(snap)` 的库存探针只探 `category:"shady"` 的卡，所以豁免卡**建议复用 `shady` 类型**（不新增 key），否则额度会空转成填充器。

现成的范例包是 `content/events/138-speculation.js`（【投机包 · 庄家生意】6 张：`sp85_plaza` / `sp87_monday` / `sp97_currency` / `sp07_cracks` / `sp08_liquidity` / `sp22_run`），六张全是 `category:"shady"` + `pace:"exempt"` + `unique:false` + `dyn:true`。它与年代史实卡的分工：**史实卡写"这件事找上你的政治身份"**（听证、救灾、表态），这一包写"同一天的另一条街"——你的仓位、你的经纪人、你手里那点现金；两张同年出现不重复，一个问「你怎么回应」，一个问「你赌不赌」。钱的写法也有讲究：收益一律走 `funMul`（比例，见 §6）而不是绝对额，入场费写在 `req.fun`（账上没这么多钱就吃不下这单）**而不是单价**——#28① 之后一档投注多少钱只看身位（§4.16.3）。

#### 同年分层：一件大事，三种身份视角（`P.visibleChoices`）

十件旗舰历史事件（911 / 阿富汗 / 伊拉克 / 卡特里娜 / 次贷 / 救市 / 班加西 / 棱镜 / 查理周刊 / 疫情）用**选项级 `when`** 写成"底/中/高"三档：

- 底 `when: { tierRaw: true, tierMin: 0, tierMax: 3 }` —— 旁观与自救：你只是个街坊，能做的是一封信、一次到场。
- 中 `when: { tierRaw: true, tierMin: 4, tierMax: 6 }` —— 表态与办事：州一级的人物，公开定性、开听证、争条款。
- 高 `when: { tierRaw: true, tierMin: 7 }` —— 决策与担当：你自己那一票/那道命令就是历史的一部分。

硬规矩三条：① 三档必须铺满 0—9（`tierRaw` 别忘，否则档位被旧 `tierBand` 重映射）；② **每一档内部**至少留一条既无 `cost` 又无 `req` 的选项——全局保底检查只看"整卡存在保底"，档位一切走后穷人档里没路可点，玩家就被自己的身份卡死；③ 量级随档位递增，高档的 critfail 要真的能毁掉一条仕途。
引擎的兜底顺序（`visibleChoices`）：命中 `when` 的选项 > 全部不带 `when` 的选项 > 原样全给——任何情况下都不会渲染出零按钮的卡，但那是保险丝，不是设计。

#### 连锁后幕：可以断，不可以硬灌

后幕写 `after: { id: 前幕, minMonthsAfter, maxMonthsAfter? }`（§4.11），**并且不要再钉进 `fixed`**。定点档期是绕过 `eligible` 强制排期的，一旦钉死，"前幕没演则后幕静默跳过"这条可断裂性质就没了。已落地的两条链：`136-chain-911.js`（爱国法之后的国内监视 → 情报失实的两党攻讦）、`137-chain-credit.js`（大空头 → 华尔街问责与立新规矩）。链上每一幕 `unique:true`，前情用 `after`、岔路才用 `flags`。

#### 验收看哪几个数

- `node dev/tools/trigger-scan.js`：逐年钉卡 **≥2**（1980—`endYear`，2025 收官年 ≥1）+ tier8 结构可发率 ≥80% + 零死引用。密度不足直接 FAIL 退出码。
- `node dev/tools/validate.js --games=20` 的「四大类【年均/局】」行：**固定 ≥ 职业 ≥ 随机**（倒挂必须转正），且非灰产随机年均 ≤ `yearRandomMax`、公务年均 ≤ `careerMax`、灰产 ≤ `grayMax`；填充率与"每年档期"两个面板同时看，随机被限流后若填充率抬头，说明额度被空耗了（回看 `grayRoom` 那类库存探针）。
- 「#38 非固定四桶【年均】」行是**密度总承诺**：全生涯 2—6 件/年、p90 ≤ `eventMax`+1（+1 是竞选链的宽限，它记账但不被拦）、开局两年**吃额度的三桶**（公务/随机/灰产）均值不高于全局——四桶总数在开局两年反而可能更高，那是新人第一场选举的一串竞选幕，冷静期管不到也不该管。开局两年另有「#37 开局密度」行（第 1/2 年**含钉卡**的总件数带），单月竞选幕 ≤1。
- 「一年 2—6 件」是**全生涯**口径（#38 起），不再是"只管开局两年"；含钉卡后玩家实际屏显 ≈ 非固定 + 2 件/年。若某段实测仍嫌吵，该动的是 `pace` 的四个数，不是 `activeChance`。

### 4.22 wh（白宫事务池 · 总统月决策槽 · #21 M1—M4）

爬到 `tierMax`（总统）之后，"一年抽象一次"的引擎就管不动了：总统一月不出一个决策，玩家手里只剩工资条。所以开了**第三条强制档期通道**（前两条：竞选幕 `campaignForceSlot`、日常公务 `choresSlot`），语义同一条：**到点必演，不看运气**。引擎在 `engine/presidency.js`，卡池在 `content/events/147—151`（轮转 24 张 + 弹劾 1 张），在任选举链在 `153/154`。

- **入口**：事件写 `wh: true` + `whFamily:` 四族之一（`crisis` 危机 / `legislation` 立法 / `foreign` 外交 / `personnel` 人事）。`eligible` 顶部 `if (ev.wh) return false` —— 白宫卡**永不进随机池**，只经 `P.whiteHouseSlot(month)` 注入。
- **谁能撞上**：`P.isPresident()` = `G.tier >= balance.tierMax`；卡上仍写 `tierRaw:true, tierMin:9, tierMax:9` 把身份闸显式留在内容里。
- **节奏**：四族轮转，游标 `G.pres.famIdx` 逐月往后走一格，本族饿着就顺延下一族 → 总统在位**每月恰 1 条**白宫档期（validate 有硬断言），同族绝不连刷三个月。四族都饿着时这个月就静着，不硬塞刚演过的卡。
- **⚠ 池子容量公式**：`每族「首任可用」张数 × 4 ≥ repeatMonths`（现 18，与公务卡同频）。"首任可用"= 该族卡里**剔掉**次任专属（事件级 `flags:["pres_two_terms"]`）与弹劾卡（`id === balance.presidency.impeach.card`，它不占轮转名额）之后剩下的张数——把它们算进分母就是假绿灯（M1 首落地时正是这条断言把误抄的 18 抓回 8）。轮转周期是 4 个月，所以 5 张的下限就是 `repeatMonths 20`，留 2 点余量。
- **⚠ 每族必留 1 张次任专属卡**（`flags:["pres_two_terms"]`）：这面旗由引擎在连任胜选那月插上了（`presRaces`），所以它的判据留在**事件级** `flags`，走 `whEligible → P.when` 那条现成的闸，不新增机制。第一届它一张都不该出现，第二届它必须出现——两个方向 validate 都钉。
- **⚠ 必须显式写 `unique:false`**：`grade:"major"` 的卡默认一局一次（§4.20 同一条坑），而任期 96 个月靠的就是同一批卡轮演——漏写就是一次性卡，第二轮起整族饿死。
- **支持率（`G.pres.appr`，0—100）不是展示件**：卡上每卡至少一个选项挂 `mods:[{src:"approval"}]`（§5），效果键写 `effects:{ appr: ±n }`。`appr` **不进 `SCALE_KEYS`**（`dyn:true` 卡的钱/声望系数会折算它，但支持率是刻度不是体量，`engine/scale.js` 里没有这个键，所以 `+4` 就是 +4 个百分点）。
- **水位**：每月 `appr += (baseline-appr)·revert + drift`，默认定出 ~42 的均衡点 —— 一事一事挣来的涨幅会自己往下掉，"在位越久越难"是刻意的；丑闻/调查另按 `pressure` 逐月加压。低于 `pressureBelow` 连续 `pressureMonths` 月：先出"党内压力"一句日志，条件再叠上"丑闻 ≥2 级或调查未结"就触发 §4.23 的弹劾门。
- **开关**：`balance.presidency.enabled:false` 一键下线整条通道 —— 决策槽、任期条、支持率瓷贴同时消失，回到"当总统 = 拿高薪的普通上班年"。
- **探针**：`node dev/tools/out/presprobe.js`（headless 把人摆到 tier 9 跑满 96 个月，**每月档期都真的结算成效果**，逐项打印 每族命中／同族连刷／两条在任链开闸与末幕／届数与次任卡／离任后清算池可出场 的 PASS·FAIL）。

> 读数件复用竞选条那套皮（`.campbar` 的兄弟 `.presbar`），支持率另挂在资源栏第五枚瓷贴上（`data-diff="appr"`，白卡结算的红绿高亮自动吃到）。白宫月的卡片本体换椭圆办公室的皮：`stage.js` 的 `P.ovalCls(ev)` 只认 `ev.wh` 一个字段，样式在 `style.css` 的 `.news.editorial.oval`（深藏青左边框 + 金徽底纹 + `.cchip` 换色），非总统月份渲染出的字符串一字不变。

### 4.23 在任者的选举链与总统账本（#21 M2—M3）

总统已经在 `tierMax`，而竞选引擎的两道硬闸都假设"竞选是往上爬"：`campaignCandidates` 要求 `def.tier === 现级+1`，`campaignTick` 见 `G.tier >= def.tier` 就把这场判 `DROPPED`。所以**不假造第十级**，改用三个字段把这两道闸豁免掉，胜负口径同时换掉：

- `def.incumbent: true` —— 跳过上面那两道闸（`campaign.js`）。**别把它理解成"这场不算数"**：中期链不动总统本人的位子，它结算的是国会、派系与清算账。
- `def.winKind: "retain"` + `def.winFlag: "<旗>"` —— 链走完时不看 `tier`，只认末幕某条胜局 outcome 亲手盖下去的那面旗。**内容侧的硬契约**：末幕必须真有选项写 `effects:{flags:[winFlag]}`，否则永远判负（validate 查这条死引用）。
- `def.gate.cond: function (G) { return G.pres && G.pres.raceDue === "reelect"; }` —— 档期由届内日历开（`termStart + midtermAt` / `+termMonths−reelectLead`），引擎只负责置/摘 `raceDue`；"该打这场了"与"你恰好想打"分成两件事表达。`ctx` 默认取 `String(G.pres.term)`，所以同一场中期选举每届各打一次。
- **⚠ 在任链的选票选项不许再挂 `mods:{src:"approval"}`**：`incumbentAppr`（`balance.campaign`）已经把 `G.pres.appr` 折进 `ballotBase` 的起步选情，再挂一次就是民心算两遍。这条与 §4.22 的"每卡至少一个 approval 选项"不冲突——那是白宫事务卡的规矩，这是投票日。
- **败选与定罪都只落 `fall:1`**，不用 `hardEnd`：与 #35「竞选不再由引擎掷赌骰判死」同一条纪律。`fall` 把 tier 摔下 `tierMax`，白宫通道随 `isPresident()` 转 false 自动关账，离任结算在 `presidencyTick` 的离场分支里幂等地做一次（`presExitSettle`：低支持率/长期危险线 → `wrath_establishment`，丑闻 → `wrath_press`，调查或弹劾 → `wrath_agency`，并插 `president_left`）。**这正是 §4.18 清算池的入口**，卸任后真的会演清算，不需要新数值系统。
- **弹劾卡**（`balance.presidency.impeach.card`）：白宫殿把它排在四族轮转**之前**、且不推游标（它占的还是"每月恰 1 条"那个名额，弹完照原节奏继续轮），卡自带 `cond: P.impeachmentDue()`，于是被当普通卡抽也只有该演的那个月抽得到。演过插 `impeached`，`retryMonths` 内不再敲同一扇门。
- **遗产三档**（`content/40-endings.js`）：`career_president_great/adequate/flawed` = S/A/B，判据一律走 `when` 的 `cond` 逃生口读 `G.pres`（**快照里没有 `pres`，第一个参数才是真 `G`**），外加 `impeached`/`scandal_4·5` 两道上限闸。没有白宫账本的旧档才落到通用 `career_president`。
- **总统视角历史锚点**：给 1xx 年代线卡补 `when:{tierRaw:true,tierMin:9}` 的**决策档选项**（§4.21 的选项级分层），不动既有选项 id。`tierRaw` 不可省；这一档**必须**至少有一个档位吃 `appr`、且胜算挂 `approval`（validate 逐条查），否则"总统的桌子"和普通表态没有区别。

## 5. mods（胜算修饰符）
每个修饰符是一条 `{ src, key, w, ... }`。命中则把 `w` 折算进胜算。

| src | 语义 | 需要的字段 | 计算公式 |
|---|---|---|---|
| `"attr"` | 属性 | `key`(CHA/INT/CUN/INTG), `w`(默认 0.6) | `(属性-50)/100 × w` |
| `"fac"` | 派系好感 | `key`(派系 id), `w`(默认 0.3) | `好感/100 × w` |
| `"flag"` | 状态标记 | `key`, `w` | 命中则 `+w` |
| `"talent"` | 天赋 | `key`(天赋 id), `w` | 命中则 `+w` |
| `"track"` | 轨道 | `key`, `w` | 命中则 `+w` |
| `"party"` | 党派 | `key`, `w` | 命中则 `+w` |
| `"stance"` | 姿态 | `key`, `w` | 命中则 `+w` |
| `"tier"` | 层级 | `w`(每层加值) | `层级 × w` |
| `"res"` | 资源 | `key:"fun"`, `min`, `w` | 资金 ≥ min 时 `+w` |
| `"voters"` | 选民底气 | `w`(默认 0.06) | `voterEdge()`(∈[-1,1]，均衡点为 0)`× w`（`dice.js`）。晋升/连任类选项（`isContestChoice`）由 `computeP` **自动附加**（`balance.voterDynamic.contestW`，默认 0.08），政策推进类才需显式声明 |
| `"approval"` | 总统支持率 | `w`(默认 0.25) | `(支持率-50)/100 × w`（`dice.js`，#21 M1）。**50% 是零点**：平稳水位（baseline 45）附近不偏不倚，高支持率才买到优势。不在任（没有 `G.pres`）时 `v=0` 且明细里不出这一行 —— 所以只有白宫卡（`wh:true`）该写它 |

最终：`P = clamp(base + Σmods + 天赋全局mods, 0.05, 0.95)`
玩家只会看到**模糊档位**（渺茫/不利/五五开/有利/稳操胜券/几乎必胜），不显示精确概率。

## 6. effects（后果）

```js
effects: { attr:{CHA:5}, fac:{base:10,press:-8}, fun:400000, rep:6, fav:-1, lev:-1, tier:1,
           voters:{warm:800,oppose:-300}, count:{wrath_press:8}, debt:-20000,
           contact:{fixer:12}, forget:["shark"],
           score:5, flags:["whistleblower"], notFlags:["bailout_stain"] }
```

> **当 `dyn: true`（现在所有卡的默认）时**，下表里的 `fun` / `rep` / `hp`（以及 `cost` 里的 `fun`）不是绝对金额/点数，而是**系数**——引擎在抽中这张卡的瞬间，用当前人物的"标尺"把它翻译成绝对值（见 §4.16.2）。`attr` / `fac` / `fav` / `lev` / `tier` / `count` / `debt` / `voters` / `contact` 等仍是字面数值。

| 键 | 语义 | 范围 |
|---|---|---|
| `attr` | 属性增减。**#37② 书写纪律：事件卡是后天唯一的属性门（另一半在建角：自由点 + 天赋卡池），出身/起点/州/难度一律不许写 `attr`**（validate 静态扫内容表 + 运行时逐组合断言零分配时 `G.attr === startAttr`；唯一例外是起点上那两条**隐藏诚信负数**，只减不增）。单维增益照**自由点尺**取值：**1 点 = +10 属性 = $2k**，一次性 major 卡最多 +10~+20，别写 +30。**这把尺只管事件卡，不管开局卡池**——池子自 #40 起走更小的「卡面尺」（1 属性点 = $1k，档位 白1/蓝3/紫6/金15），两把尺不同源，见 §16 卡池节。**同卡重演不再给属性**（见下「attr 只首次生效」）——所以想靠重复卡刷满一维已经不可能了 | 0-100 |
| `fac` | 派系好感增减 | -100~100 |
| `fun` | 资金增减（美元，可为负） | — |
| `funMul` | **按本金算的投资回报**（1.0 = 翻倍赚，-1.0 = 全亏）。本金 = 选项 `cost.fun` / 入场费 `req.fun` / 投注资金（`stage.js` 结算前写进 `G.__stakeBase`）。**没有本金声明则空转并告警**（v0.12 起不再按总余额乘——那是"点一下家底翻 2.2 倍"的漏洞）。**#28②：倍率吃智力** —— `effects.js` 的 `funMulIntMul` 给倍率再乘 `1 + (INT-50)/100 × balance.funMulIntLev`（默认 0.4 → INT100 得 1.20、INT0 得 0.80）：**盈利一侧乘 k、亏损一侧除 k**，同一笔生意聪明人赚得多、翻车时亏得少，两条曲线关于 INT=50 对称。成败判定仍走既有的 outcome roll，这里只改落袋的钱；`funMulIntLev: 0` 即关闭 | 倍数校验区间 `[-1, +3]` |
| `debt` | **学生贷款本金增减**（绝对额，不受 dyn 标尺缩放）。还/减（负值）视为按时：连续逾期计数 `loanLate` 归零；余额与当年欠息桶锁死不为负。见 §15 | — |
| `rep` | 声望增减 | 0-100 |
| `appr` | **总统支持率增减**（#21 M1）：`G.pres.appr` 夹取累加。**非总统在位时空操**（与 `camp` 键同纪律：内容写错不该打扰玩家）。只写绝对百分点（`+4` 就是 +4%），**不进 `SCALE_KEYS`**、不随 `dyn` 标尺膨胀。只该出现在白宫卡（`wh:true`）上 | 0-100 |
| `hp` | **已退役（v0.9）**：handler 保留但空操，防"未知键"告警刷屏。健康是后台静态量：`endYear` 年度老化直接结算（驱动生病/死亡结局），事件不再碰它 | — |
| `ap` | **已退役（v0.9）**：精力彻底退出玩法，事件写了也无效。老卡残留的 `cost:{ap:2}` 等同样不扣（休眠） | — |
| `fav` | 人情点增减 | 0-20 |
| `lev` | **把柄份数增减** | 下限 0（可为负 = 花掉一份，但不会变成负数） |
| `tier` | 层级升降（变动重置"在位时长"、重算选民池）。正常晋升一步一级要吃 `balance.tierGates` 资历闸（熬不够折 +3 声望）；`tier:+2/+3` 破格直提**绕过闸**，代价是被跳过的级不记 `counters.served_N`，"德不配位"类事件会找上门。**跨进 `tierMax`（总统）那一步另有一道硬闸**：只认投票日来源（`ballot: true` 的选项 / 竞选链 `onWin`，由 `P.applyEffects(eff, { election: true })` 传入），普通事件卡再大的成功也进不了白宫，拦下时与资历闸同样折 +3 声望。每次升层级同步记**生涯峰值 `G.peakTier`**（2025 成就结算用，见 §4.19） | `balance.tierMin~tierMax` |
| `voters` | **选民池增减**（v0.5.2）：`{ warm: 人数, diehard: 人数, oppose: 人数 }`——有好感/死忠/反对。见 §10 `voterBase`/`voterDynamic` | 人数 |
| `count` | **隐藏计数器**：`{ wrath_press: 8, cap_legal: 1 }` → 累加，**下限 0**（`effects.js`）。与 flags 分工：flags 记"有没有"，counters 记"攒了多少"。刻意不上状态面板——后续事件用 `countMin/countMax/countEq` 读它（见 §4.18） | — |
| `fall` | 软 BE「下野」：`v` = 下野深度 1~2，降层级、按比例摔声望、丑闻降级、清 `investigation_open`、挂 `fallen` 标记。**12 个月保护期**内不叠加；之后仍有东山再起（`fallen_return` 结局认账） | — |
| `hardEnd` | 硬 BE：只写 `G.pendingHardEnd`，终局判定由 `view/stage.js` 的 afterEvent 统一收口。取值见 §12.5（`prison`/`disgrace` + 清算四新值 `ruined`/`purged`/`framed`/`assassinated` + `bankrupt`，见 §4.18/§15） | — |
| `setTrack` / `setStance` | 路线转向：把玩家直接挪到另一条轨道/姿态（键必须存在于注册表；代价应写在剧情里） | — |
| `camp` | **竞选选情增减** `{momentum:±x, warchest:±y}`：只用在竞选各幕事件里，撬动当前 campaign 的选情表（见 §14）。**不计入三值性净值、不上状态资源条**（`campaign.js` 经 `P.effect("camp")` 注册；无活跃竞选时静默忽略） | — |
| `score` | 自定义累计分（供结局条件用） | — |
| `flags` | 增加状态标记 | — |
| `notFlags` | 移除状态标记 | — |
| `contact` | **人脉好感增减**（`{id: 数字}`，首次出现即"从此认识"） | -100~100 |
| `forget` | **彻底断掉一段关系**（`["id"]` 或 `"id"`） | — |

> **attr 只首次生效（#37③）**：`stage.js` 在结算选项效果与黑天鹅之前过一道 `P.filterOnceAttr(eff, id)`（`engine/effects.js`）——按 `卡id:维度` 在 `G.attrGiven` 记账，同一张卡的同一维属性**第二次起被摘掉**，`rep` / `fac` / `fun` / `fav` 等照给不误；结果框显示的也是过滤后的实际所得。这封掉了旧版 `shady_doctor` 那种"单局重演 25 次、每次 CUN+2"的刷点传送带。**写作上不必做任何事**（不需要标 `unique`），但要知道：给可重复卡写高属性已经等于不写。

**把柄的"得到"和"花掉"是两种不同的写法**：
- **花掉**：用 `cost: { lev: 1 }`（付不起就点不动，玩家看得见代价）。这比在 effects 里写 `lev:-1` 准确 —— 后者在每一档结果里都得重复，容易漏。
- **得到**：写在 `effects` 里（`lev: 1`），通常只在成功档给，失败档不给 —— 用"把柄没拿到"来惩罚失败。

**自定义效果键**（内容团队可自行扩展，无需改引擎）：

```js
POTUS.define("effect", {
  legacy: function (v, G) { G.legacy = (G.legacy || 0) + v; }   // v 为该键的值，G 为存档状态
});
// 之后效果里就能写 effects: { legacy: 10 }
```

> 用未注册的键会打印警告但不报错——这是有意设计，方便先写内容后补注册。

## 7. ending（结局规则，声明式）

引擎按 `priority` 从高到低取**第一条命中**的规则。

```js
POTUS.define("ending", [{
  id: "retire_kingmaker",
  priority: 85,                          // 越大越优先
  when: { /* 条件，全部可选；空对象 = 永远命中（做兜底） */
    reason: "retire",                    // 触发原因：president|prison|death_health|retire|default
    flags: ["owns_media"],               // 必须全部拥有
    notFlags: ["scandal_4"],             // 必须全部没有
    tierMin: 4, tierMax: 5,
    trackIn: ["operative"], partyIn:["D"], entryIn:["celebrity"],
    scandalMin: 3, ageMin: 70, ageMax: 90, funMin: 1000000, repMin: 60,
    cond: function(G){ return true; }    // 自定义条件
  },
  title: "从不参选的人",
  grade: "S",                            // S/A/B/C/D/F
  body: "支持 {age} {tier} {track} 占位符；也可写成 function(G, POTUS){ return "..."; }"
}]);
```

`reason` 的取值由引擎在终局时给出（收口点全在 `engine/view/stage.js` 的 `afterEvent` / `endYear`）：
- `prison`：拥有 `prison` 或 `scandal_5` 标记
- `death_health`：健康 ≤ 0（后台老化结算出来的，事件碰不了 hp）
- `retire`：年龄 ≥ `balance.retireAge`
- **hardEnd 值直接作为 reason**：事件写 `effects.hardEnd:"<值>"` 后 `pendingHardEnd` 原样传入 `P.ending(why)`。现役取值：`prison` / `disgrace` / `ruined` / `purged` / `framed` / `assassinated`（清算系统，§4.18）/ `bankrupt`（学贷断供，§15）
- `career_end`：活到 `balance.endYear`（2025）硬墙后，玩家在年历卡点「查看生涯结算」→ `P.careerEnd()` → `P.ending("career_end")`
- **`president` 不再是终局**（v0.11 P1）：首次达到 `tierMax` 只挂 `president_done` 状态旗，游戏继续打到 2025。老的 `reason:"president"` 规则仍留在 `40-endings.js` 里休眠；2025 结算用 `career_president_*`（靠 `flags:["president_done"]` 区分，与结算时点所在层级无关）。

**career_end 家族的写法**（`40-endings.js`，共 25 条规则）：`when: { reason:"career_end", tierRaw:true, tierMin:7|5|3|1 }` 按**终局 tier** 发阶梯成就，另有 `career_quiet` 无 tierMin 兜底；`{late}` 占位符由 `progression.js` 渲染时填 `G.loanLate`（结算页同时展示 `peakTier` 峰值职位与生涯跨度）。

> **存档格式契约（v0.12 #26）**：`core.js` 的 `POTUS.SAVE_FORMAT = 12` 随 `serialize()` 盖进 `G.saveVer`；
> 读取（`doLoad` / `importSave`）在 `migrate()` **之前**按 `SAVE_FORMAT_MIN` 硬校验，旧档一律弹「旧政权」对话框
> 只给**删档 / 开新局**，自动档则静默丢弃——**存档格式破坏性变更没有过渡带**。
> 因此：**改 `G` 字段语义或删字段 = 必须同步升 `SAVE_FORMAT` 与 `SAVE_FORMAT_MIN`**（旧档按上式作废）；
> 只是 `migrate()` 里补默认值的新增字段**不用**升版本（旧档缺字段由 migrate 兜底，仍可载入）。

## 8. filler（填充模板）

事件池抽空时使用，保证**事件永不枯竭**。两种写法：

**声明式**
```js
POTUS.define("filler", {
  "2008_CRASH": {
    topics: ["一场市政债违约", "…"],       // 标题池
    acts:   ["你被卷进", "媒体追问："],     // 前缀池
    bodyTpl: "{act}{topic}。你必须在聚光灯下做出选择。",
    choices: [ /* 与事件 choice 同构，五档结果必须齐全 */ ]
  },
  "*": { /* 全时代兜底包 */ }
});
```

**函数式**（完全自由）
```js
POTUS.define("filler", {
  "2016_POPULIST": function (P, G) {
    return { id:"…", era:["2016_POPULIST"], title:"…", body:"…", choices:[…] };
  }
});
```

>
> **引入新 flag 要登记**（否则不显示、无 hover 说明）：在文件末尾加 `POTUS.define("balance", { tagNames: { <flag>: { name:"中文名", desc:"是什么", effect:"游戏影响" } } });`。

1. **多行格式**。每个选项的 `outcomes` 独占一块，五档逐行排列：
   ```js
   { id:"x", text:"…", base:0.5, mods:[…],
     outcomes:{
       crit:{ body:"…", effects:{…} },
       ok:{ body:"…", effects:{…} },
       meh:{ body:"…", effects:{…} },
       fail:{ body:"…", effects:{…} },
       critfail:{ body:"…", effects:{…} }
     }
   },
   ```
   **不要**把整个选项压成一行手数括号——本项目历史上最大的坑就是单行紧凑写法导致的括号失衡。
2. **文本一律用 ASCII 双引号 `"` 作为字符串定界**；正文里要强调某个词时，用全角引号 `「」`，**绝不要**在字符串内部再写 ASCII 双引号（会直接语法报错）。这是本项目第二大的坑。
3. **不要写逻辑**。事件里不写 `if`/循环/副作用；需要特殊判断用 `cond(G)`。
4. **id 全局唯一**，建议前缀用时代或支线名（`2008_`、`prog_`、`affair_`）。
5. 模板可以直接内联在事件里（`templates:` 字段）——见下一节扩展点。
6. **每个事件都要有 `brief`、`grade`、`category`、`valence`、`dyn`**（见 §4.7 / §4.8 / §4.16）。经济字段一律写**系数**（配 `dyn: true`），不写绝对金额。这是可玩性与分工的底线：
   - 玩家不该被丢进一个连"发生了什么、谁在推动"都看不懂的局面；
   - 玩家也不该在 `brief` 里读到主角不可能知道的东西；
   - 没有 `grade` / `category`，界面就没有量级徽章和配图，也没法按类型分工。
   校验脚本会对三者逐个检查，缺一个直接判失败。
7. **`month` 只在史实锚点上写**（见 §4.6）。写了 `month` 的事件在那个月之外抽不到，写多了会让事件池变浅。
8. **`known` 是主角视角，不是上帝视角**。写之前先问一句：**这一刻，他手上有哪些纸、见过哪些人、听过哪些话？** 只写这些。
9. **`unknown` 要写"后果的位置"，不是"后果本身"**。它存在的意义是让懂历史的玩家知道"这里可以占便宜"，而不是替他做决定。
10. **日期要对得上历史**。有真实锚点就用真实日期；这不只是装饰，是给玩家的信息。
11. **年代不对的事不要写**。1910 年没人发推文，1960 年没有热搜，2010 年没有短视频。
    如果这个事件依赖某种媒介，写上 `medium`（见 §4.9），让引擎按年份自动放行——
    **不要**用 `fromYear` 硬编码一大堆年份窗口，那是引擎该做的事。
12. **每个事件必须留一个保底选项**：既没有 `cost`、也没有 `req` 的那个（见 §4.3.1）。
    否则玩家钱花光 / 声望被打下去之后，会撞上"所有选项都点不动"的死局。
    校验脚本会逐个检查，`validate.js` 直接判失败。
13. **写 `stake` 时核对 `cap ÷ w ≥ 1`**，并算一下可投档数 `ceil(cap ÷ w)` 是否和你在文案里
    承诺的上限对得上（见 §4.4）。上限比一档还小的投注是"花钱买 0"，校验器会拦。
14. **提到一个人，就必须先在 `content/07-contacts.js` 里登记他**（见 §4.10）。
    `ev.contacts` / `req.contact` / `effects.contact` / `effects.forget` 里的每一个 id 都会被逐条核对：
    id 不一致是最典型的"内容团队自己踩自己的坑"——文案里写着"掮客"，代码里写着 `broker`，接口就跑不通。
15. **链上的每一幕都要 `unique: true`，并且用 `after` 表前情、用 `flags` 表岔路**（见 §4.11）。
    顺序写错会让故事要么重复演，要么悄悄断掉。
16. **把柄（`lev`）用来"花"，不用来"囤"**（见 §4.3）。它的设计意图是**易腐**的临时筹码：
    手里超过 `leverageAt` 份就会招来调查，而且每年都会坏掉几份。
    某个事件若让玩家能无限囤把柄，那是内容失衡，不是机制问题。
17. **每个时代都要有中事件和小事**。只给一个时代写大事件是不够的——大事件 `unique`，
    一局只演一次，之后那个时代在抽取里就等于不存在（校验器的"按时代专属占比"会直接把这件事报出来，见 §4.8）。
18. **写静好岁月的片段时，记住它没有转折**（见 §4.13）。它是"日子"，不是"事件"：
    写成小高潮就等于把事件的活儿干了两遍，而且会让平静的月份显得不平静。
19. **每个槽位都留一条无条件片段**（时令除外，时令要覆盖 12 个月）。
    条件写得越满，越容易在"玩家又病又穷又被调查"的时候一段都抽不出来。
20. **不要替模型写数值**。随笔里只写画面，成长由 `balance.vignette` 统一结算。

## 11.7 文字质量与篇幅章程（强制）

本节是对 §4.7 和 §11 的细化，直接约束每个事件的 brief 与选项文本。写事件和审查事件时以此为尺。

### 篇幅硬上限

| 字段 | 上限 | 说明 |
|------|------|------|
| brief 总字数 | **≤300** | lede + known + rumor + unknown + terms 合计 |
| `lede` | ≤50 字 | 一句话说清「此刻的处境是什么」 |
| `known` 单条 | ≤30 字 | **只写决策相关信息**，不写政治课 |
| `known` 条数 | ≤4 | |
| `rumor` | 最多 2 条，每条 ≤25 字 | 一句话传闻，真假不明 |
| `unknown` | 最多 2 条，每条 ≤20 字 | 写「后果在哪里」不写「后果是什么」 |
| `terms` | 最多 2 个，解释 ≤20 字 | 只解释真正生僻的术语，能从上下文猜出来的不加 |
| 选项 `text` | ≤30 字 | 一个动词句说清在做什么 |
| 选项 `note` | ≤40 字 | 「赌的是___。风险：___。」格式 |

### 清晰度铁则

1. **不写公民课**：known 不是百科词条。不要写「地方选举投票率常年极低」这类通识；要写「你知道如果动员够这四千张票，这次就能赢」。
2. **不自我矛盾**：known 确认「你确实有东西可挖」，选项 note 就不能写「他们可能什么都没挖到」。如果情况有不确定性，写在 unknown 里，不要在 known 先肯定再在别处否定。
3. **每个选项必须有一个可辨识的赌注**：玩家看完三个选项，应该能回答「A 在赌什么、B 在赌什么、C 在赌什么」，而不是三个看起来都是「好像都行」。
4. **后果要能落地**：不用写具体数值（掷骰隐藏原则），但要让玩家知道最坏情况是什么样（比如「会烧掉党内关系」「可能丑闻标记」）。
5. **标题是索引，正文是散文**（§11.6 原则五）。标题用陈述句说清「发生了什么事」，意象和悬念全部放到 body。

### 流程事件（camp_ / chore_）的 brief 写法

竞选链各幕和日常公务不是「不需要交代背景」，而是「需要的信息不同」：

- `lede`：当前选情/处境一句话（「你的对手已经连任八年，名字邻居都认识」）
- `known`：2–3 条决策相关事实（资金状况、对手弱点、可用资源）
- `rumor`：可省
- `unknown`：一条「什么情况下会崩」即可
- `terms`：通常不需要（选民都熟悉的词不要解释）

目标总字数：100–150 字，不要写满 300。

### 压缩指南（处理超标事件时）

1. 先删 known 里属于「政治课」或「通识」的条目（玩家早就知道的不用告诉他）
2. 把 rumor 和 unknown 合并精简（如果二者说的是同一个意思，只留 unknown）
3. terms 删掉玩家能从上下文猜出来的（只留「不解释就看不懂选项」的术语）
4. 把冗长条目拆成短句，删掉破折号后面的二次解释
5. 最后检查：压缩后是否仍然让玩家清楚「赌的是什么、最坏会怎样」

## 11.6 设计原则（v0.5.2 从玩家实测反馈沉淀，写事件前必读）

这些原则来自真实试玩反馈，validate.js 有对应断言。新事件不遵守会被校验器拦下或被打回。

### 原则一：经济要诚实（投入与回报）
- **投资型选项**（押本金做生意/竞选自掏腰包）：回报用 `funMul`（比例），不要写死 `fun` 数额——
  押 $30k 和押 $2M 的人不应该都赚 $15k。
- **消费型选项**（买广告/请律师/压稿）：ok 档必须有看得见的非钱回报（rep≥5 或 派系净变动≥5 或 contact/flag），否则就是花钱打水漂。
- 高投入（≥$50k）选项会被校验器逐个审查：ok 档要么回本 30%+，要么拿资产。
- 投注（stake）只加胜算不加回报——面板上已明示，写事件时不要再拿"加码"当收益卖点。

### 原则二：触发门槛要与身份匹配
- **大资金事件不要对低地位穷人开放**：要么 `req.fun` 挡住，要么给穷人留一条"出力不出钱"的变体选项。
- **高地位没钱的人**：应该有"用人际关系牵线/空手套白狼"的选项（req.tier 或 req.contact）。
- **低地位有钱的人**：可以有"直接投钱入局"的选项（钱开门，但政治后果自负）。
- 同一个局面按身份分化选项，比按身份屏蔽整个事件更好。

### 原则三：事件必须有前因后果
- 玩家读到的第一句就要知道**为什么是我、为什么是现在**：谁牵的线、你做过什么让这件事找上你。
- 禁止"头目听了你十分钟"这种无来由开场——他是谁？你们怎么认识的？他要什么？
- brief.known 的第一条永远先交代来龙去脉，再写局势。
- **深远影响**：重要事件要有 `after` 余波幕（minMonthsAfter 通常 6-42），让选择在几个月/几年后回响
  （工会的背书两年后会来兑账、救市签名会在下次竞选被翻出来）。unique:true 一局一次；
  互斥用 flags + notFlags（事件 A 的 a 结果给 flag，事件 B 用 notFlags 挡）。

### 原则四：身份驱动一切
- **工资按职位实算**（reg.officeSalary，参考真实公职薪水的月度换算），不按抽象层级。
- **职位名要用真人间的叫法**（学区委员/州参议员/竞选经理），"T2"这种内部代号不允许裸奔见玩家。
- 事件的 rep/fac 收益量级要配身份：市议员的事件给 rep 4-8，联邦级事件给 10-16。
- 每月日常（quietWorks）按 轨道×层级 写具体的工作颗粒（见选民/开会/巡排水系统），不写抽象散文。

### 原则五：显示要让人看懂
- 属性/资源一律中文名（魅力/智力/手腕/公信力；人脉好感不叫"人情往来"）。
- 诚信=**公信力**：不设选项门槛（不挡"你能不能选"），只在需要公信的判定里加分（吹哨/作证/改革）；
  UI 上放声望旁边。它只能被选择改变，不随年龄自然长。
- 状态标记一律带 hover 说明：是什么 + 游戏里有什么影响（tagNames 的 {name, desc, effect}）。
- 没登记词条的 flag 不显示原文（宁缺毋滥）。
- **事件标题是一句通顺、完整、一眼看得懂的陈述句**，直接说清「发生了什么」。`title` 是玩家扫视事件列表、看「承前」链、事后翻存档时的唯一索引，读不懂就等于这条事件对他不存在。比喻、留白、意象这类文学性写法一律放进 `body`（正文），不拿它当标题——标题是索引，正文才是散文。
  - 反例（看不出在说什么）：「第七版上的那支笔」「名单的最后一位」「冷板凳与椅子」
  - 正例（一眼明白）：「你在饭局上被介绍给本市报纸的专栏编辑」「你被列进州贸易代表团的出访名单，排在最后一位」

### 原则六：数字的语义要经得起追问
- 任何 -100~100 的条满了都要能回答"这意味着什么"（基层+100=全国满意？）。
- 选民维度用具体人数（warm/diehard/oppose 三池，见 reg 选民池一节），不用百分比——
  人数随选区扩大重新换算，直接影响选举判定的胜算。
- 静好岁月的账要实：工资进、开销出（quietAccount），别让玩家"几个月不吃饭"。

## 14. campaign（竞选链：多幕民选晋升）

**在本作里，每一次民选晋升都不是一锤子买卖，而是一连串强制推进的事件。** 当玩家熬够资历、触发某一级民选台阶时，引擎（`engine/campaign.js`）自动为他开打一场竞选：把“这一场怎么选”拆成一幕一幕，直到投票日。**设计理念见 [`DESIGN.md`](DESIGN.md) 的“核心系统六：竞选链”；这里是字段契约。**

### 14.1 注册与文件

```js
POTUS.define("campaign", { camp_federal: { … }, … });   // 一个文件里可放多条链
```

内容侧样板：`content/61-campaigns.js`（9 条链定义）+ `content/events/65-campaign-acts.js`（各幕事件）。竞选链是**纯新增子系统**：从 `index.html` 删两行 `<script>` 即可完全回退。

### 14.2 一条链的字段

```js
camp_federal: {
  office: "联邦众议员",            // 必填，这一场在选什么（界面显示）
  lede:   "通往国会的那一跳……",    // 可选，一句话点题
  tier:   6,                       // 必填，目标级 = 末幕要抵达的那一级（= 起跳级 + 1）
  retryable: true,                 // 可选，基层链标此 → 败选来年可卷土重来（末幕 prog_* unique:false）
  gate: { tierRaw: true, tierMin: 5, tierMax: 5, minTenure: 24 },  // 谁能开打这一场（P.when 词汇，与对应 prog_* 同调）
  meters: { momentum: 45, warchest: 30 },   // ⚠ #35 后 momentum 这个数是**起步天花板**（见下），不再是起手值
  stages: [                                   // 一幕一幕，每一幕都必须演出来
    { event: "camp_federal_announce", title: "宣布角逐国会席位", maxMonths: 5, metersDelta: { momentum: 4 } },
    { event: "camp_federal_primary",  title: "国会初选", maxMonths: 6, metersDelta: { momentum: 5 },
      drop: "primary", abortBelow: { momentum: 10 } },                     // drop：这一幕可以投放把柄（#23）
    { event: "camp_federal_money",    title: "筹款与金主", maxMonths: 6, metersDelta: { momentum: 4 } },
    { event: "camp_federal_swing",    title: "摇摆选区的最后一周", maxMonths: 6, metersDelta: { momentum: 6 },
      drop: "general", abortBelow: { momentum: 12 } },
    { event: "prog_federal",          title: "投票日 · 决战国会", final: true, maxMonths: 8 }   // 末幕 = 复用统一晋升台阶
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `office` | ✔ | 界面显示的官职名 |
| `lede` |  | 一句话点题 |
| `tier` | ✔ | 目标级（0..9）。引擎在链走完后看 `G.tier >= tier` 判 WON/LOST |
| `retryable` |  | 基层链标 `true`（配 `prog_*` 的 `unique:false`），败选可过 `retryCooldown` 再战 |
| `gate` | ✔ | 开启条件。用统一的 `P.when` 词汇（与事件门槛同一套），**与对应 `prog_*` 的 `tierRaw/tierMin/tierMax/minTenure` 完全对齐** |
| `meters` | ✔ | 选情表。**#35 起 `momentum` 的语义是「起步天花板」**：真正的起手值由 `P.seedMomentum()` 按人物状态播种（层级/声望/基本盘/组织关系/**家底**，夹在 `balance.campaign.seed` 的 `[12,35]`），再与本字段取小 —— 这里写的数只是"这张脸最多能起手多高"。**#39 起州级三链刻意把它压到 30（低于播种上限 35）**：少掉的那一截要靠筹款幕与加码一幕一幕挣，这正是"软门槛"的落点。validate 只钉 `momentum ≥ seed.floor`（低于 floor 等于新人一开局就顶格、播种白算），**不再要求顶到 ceil**。`warchest` 仍是字面初值，且 #39 起它有读者了（见 §14.3 与 §4.2） |
| `stages[]` | ✔ | 分幕数组，按下面子字段 |

#### stage 子字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `event` | ✔ | 这一幕的事件 id（必须是已存在的卡）。**末幕一律复用 `60-progression.js` 的 `prog_*`** |
| `title` |  | 幕标题（不写则取事件 title） |
| `final` |  | `true` 标记投票日：演完就按是否抵达 `tier` 判胜/败 |
| `maxMonths` | ✔ | 这一幕的窗口；窗口内始终没演出来 = 竞选拖垮 = 崩盘（LOST） |
| `metersDelta` |  | 演完这一幕后的选情保底增减（代表“推进竞选本身的惯性”） |
| `abortBelow` |  | 这一幕结束时的崩盘闸。**#35 起只允许 `momentum` 一种表**（`{ warchest }` 会被 validate 判红：金库见底只是买不动广告，不判败选）。闸门值要按 `seed` 的低起步标定（现行：初选幕 10 / 关键幕 12） |
| `drop` |  | **#23 投放把柄的靶子**，只能是 `"primary"`（初选/提名幕，打党内同僚）或 `"general"`（大选幕，打对手阵营）。宣布幕与 `final` 投票日**不许标**（validate 判红）。竞选面板上因此出现「投放把柄」按钮：一次花 `balance.campaign.levDrop.cost` 份把柄（默认 1），每幕限一次。primary 掷"对手退赛"（成功率随累计投放次数与 CUN 上升，命中 `momentum +primaryWin`、未命中 `+primaryFail`）；general 收益更稳（`+generalWin`）但要过反噬检定（暴露率随 INTG 下降），暴露则只 `+generalBack` 并 `rep` 受损 + `flags:["dirty_trick"]` + `count:{wrath_opposition}`（喂 §4.18 清算池）。四幕以上的链应两种靶都有 |

### 14.3 选情怎么动（与三值性契约）

- **选情主要靠各幕事件自己的 `outcomes` 撕动**：事件里写 `effects: { camp: { momentum: ±x, warchest: ±y } }`（`camp` 效果键见 §6）。`stages.metersDelta` 只给一点“推进惯性”位移，`abortBelow` 只给少量崩盘闸。
- **投票日的胜率不是写死的骰子**（#35）：末幕 `prog_*` 里标了 `ballot: true` 的选项，其 `base` 在掷骰前被 `P.ballotBase()` 覆写为 `f(momentum)`（`floor 0.10 + momentum × perMomentum 0.008`，夹在 `[0.10, 0.85]`；momentum 50 = 五五开）。没有活跃竞选时回落到内容写的 `base`（诊断口径）。
- **钱退到门票之外**：当选类选项不再写 `req.fun`（validate 判红）；钱的作用改写成成功加成 `mods:[{src:"res",key:"fun",min:…,w:…}]`，而总统的资格闸改由基本盘 `req.voterShare` 把守。幕事件里的大钱手段一律写 `cost: { funLevel: N }`（N 档**级别价**，由 §15 的月薪表推导，`P.realize` 展开成 `cost.fun`），不再写绝对美元。
- **各幕事件都是 `risk`**（有输有赢、可搭砸），量级 `mid`（总统幕 `major`），带 `tierRaw:true` 与 `tierMin/tierMax` 钉在本场起跳级。它们**不锁 track**——各级民选台阶是所有轨道共用的晋升阶梯。
- **这些幕事件不会被随机抽到**：campaign.js 把它们锁定，只在它们正是“当前幕”时强制演出（借 `drawEvent` 对带 `eventId` 的定点档期直接返回、不查 `eligible` 的既有通道）。
- **资源是入场券（#39）**：语义上就是"砸钱换声势 / 借人脉办事"的幕选项要接 `stake`（`const CAMP_FUN = { fun: { w: 0.06, cap: 0.42 } }` / `const CAMP_FAV = { fav: true }` 两个常量在 `65-campaign-acts.js` 顶部），于是投注面板在竞选幕真的会弹。竞选幕的资金档**比日常陡**（6%/档、7 档封顶 +42%，日常 4%/30%），单价仍走 §4.16.3 的级别价，不另开口径。三条契约由 validate 钉住：
  1. **投票日（`ballot:true`）绝不接 `stake`** —— 钱只买声势，买不到开盘夜那张票；
  2. **每一幕至少留一个不带 `stake`、不带 `cost`、不吃 `req.camp` 的选项** —— 投不投是真选择，不是默认最优；
  3. **`req.camp`（金库闸，见 §4.2）只能挂在 `meters.warchest != null` 的链上**，且同一张卡不许整卡都上闸；
  4. **闸要两头都钉住**（validate）：`闸值 > 这条链的起步金库`（否则它永远不咬人，等于又一张只写不读的表）、
     且 `闸值 ≤ 起步金库 + 前面每一幕的最好进项`（否则这条广告永久买不动，把玩家逼进死局）。
     现行标定：起步金库只给"半波广告"（州级 10/12/14 · 联邦 16 · 参州 18 · 总统 24），闸值 20—34 随职级递增；
     中间那截靠**每幕定额拨款 `stages.metersDelta:{warchest:3}`**（19 个投票日之前的幕）+ 三处事件进项挣回来。
     **一条链没有需要金库的一幕，就整张表都别写**（`camp_vp`/`camp_reelect`/`camp_midterm` 因此不设 `warchest`）。
  覆盖面按裁定收紧：基层两链（council/city）整体不接（入场家底 $0—1k，给了只是一排按不动的按钮）；辩论/审查类幕不接（砸钱不改台上表现）；在任两条链（`camp_reelect`/`camp_midterm`）本轮未接，属**已知缺口**。
- **州级三链共用一张筹款幕**（#39）：`camp_raise_state`（`tierMin 2 / tierMax 4`）插在初选之后、造势之前，四手棋分别把 派系好感 / 魅力 / **私人积蓄（`cost:{funLevel:3}`）** / 党机器好感 换成 `camp.warchest`。它是"押上积蓄换取打得起广告的一战"的字面机制。金库的正现金流只此三处（另有 `camp_federal_money`、`camp_senate_announce`/`camp_senate_debate` 的声量带动捐款、`camp_pres_nomination` 的代表大会），写新幕时照这个清单加，别把金库写成只进不出的装饰。

### 14.4 引擎参数（`balance.campaign`）

```js
POTUS.define("balance", { campaign: {
  meterDrift: 0.8,      // 每个平静月选情自然流失
  retryCooldown: 12,    // 败选后隔这么多个月才允许卷土重来（仅 retryable 链）
  meterNames: { momentum: "选情", warchest: "金库" }
}});
```

状态字段：`G.campaign = { id, stageIdx, since, meters, status }`、`G.campaignLog`、`G.campaignCool`（均 `core.js` migrate 补齐）。

### 14.5 规模随职级缩放

| 链 | 幕数 | 台阶 |
|---|---|---|
| `camp_council` / `camp_city` | 3 | 宣布 → 基层动员/辩论 → 投票日 |
| `camp_state` / `camp_upper` / `camp_stwide` | 5 | 宣布 → 初选 → **筹款（#39，三链共用 `camp_raise_state`）** → 造势 → 投票日 |
| `camp_federal` / `camp_senate` / `camp_vp` | 5 | 宣布 → 初选 → 筹款/辩论 → 摇摆 → 投票日 |
| `camp_president` | 6 | 宣布 → 初选 → 提名 → 辩论 → 摇摆州 → 投票日 |

> 非民选轨道（任命 `prog_appoint` / 操盘手 `prog_kingmaker` / 巨富 `prog_magnate` / 名人 `prog_star`）**不套竞选链**——它们不是选举，有自己的里程碑事件。

## 15. 学贷死亡螺旋（studentLoan · v0.11+）

开局就被固定现金流咬住——这是「真资源」设计：钱不只是投注筹码，还是每月要交的账。
参数单一来源 `01-config.js` 的 `balance.studentLoan`，月计引擎 `core.js` 的 `POTUS.loanStep()`。

**开局负债**（按难度，建角时挂账见 view/create.js）：

| 难度 | 起步债务 |
|---|---|
| normal | $65,000 |
| hard | $42,000 |
| brutal | $28,000 |
| easy / legendary | 无贷（世家不背学贷） |

**月计规则**（loanStep 逐步语义）：
- 月息 = `debt × interestAnnual(0.045) / 12`，进欠息桶 `G.debtAccr`——**单利**：桶内欠息当月起不再生息；每年 1 月桶资本化一次（计入本金）。
- 月供目标 = `max(minPayment 120, 月薪 × payShare 0.25)`，随收入上升自动加速。
- **断供**的定义 = 当月还款 < 当月新息（欠息桶在增长）。`G.loanLate +1`；只要盖住利息即归零重新计时——部分还款不算断供。
- 连续断供到 `lateLimit`（#19 起重校为 **三档同宽 20/20/20**，未列难度不启用）→ `pendingHardEnd = "bankrupt"` → reck_bankrupt 成就「你的竞选经理带着剩余资金去了巴哈马」（文案 `{late}` 占位由 progression.js 填最长连续断供月数）。
- `lateMonths: 12`：长期违约 + 现金持续见底 → 只提高催收/征信类负面事件概率，**不直接 BE**（艰难度日是允许的）。
- **缓交 forbear**（`{maxMonths:24, perMonths:6, repCost:3}`）：一次冻结 6 个月、全局至多 24 个月，花费 3 点声望（rep）。冻结期不还款、不记逾期（既不 +1 也不清零），欠息照常进桶。
- **PSLF 豁免**（`{months:120, minTier:1}`）：低薪公共部门口径连续供款攒满 120 个月 → 本金+欠息一笔清零，记 `pslf_forgiven` 成就 flag——给硬核玩家的一条慢兑现出口。

**校准口径**：`node dev/tools/validate.js --diff=X --games=100` 的「学贷断供」面板；
`--late-cap=99` 是**不设防测量**（把阈值临时钉到 99 月，只测断供分布、永不 BE），末尾会打印
「若 lateLimit=N → 破产局占比」换算表，用来反推阈值。

**#19 定稿（2026-09-25）**：普通难度 cap-99 实测连续断供中位 10 月 / p90 35 月 / 峰值 64 月，
换算表 3→100%、4→95%、5→85%、6→80%、8→70%、10→70%、12→65%、16→60%、**20→50%**。
即原 6/4/3 会让八成局在前期死于学贷（且越穷宽限期越短，方向反了），故改为 **20/20/20**：
定稿后实测 `--games=100`（normal）**信用破产 41/100 局**、每局最长连续断供中位 14 / p90 20（撞闸即停）——
即约六成活过学贷关，落在「前期有一半局不该因学贷出局」这条口径内。
难度差异只体现在**负债起点**（65k/42k/28k）而不体现在宽限期上，断供 12 月起先由催收/征信事件报警。
50% 存活率是按「前期不该有一半局因学贷出局」这条产品口径取的，不是几何最优——
调整前先跑一次 `--late-cap=99` 重取换算表。

## 16. 建角：三步向导（现行主路径）

现行入口（`view/create.js`）：**第 1 步 难度 + 姓名 → 第 2 步 天赋抽卡 → 第 3 步 自由点分配**。年份**锁 1980**（无时代选择器，时代随年份自然推进——§1.5 的世界线取代「选时代」）；党派/出生州/起点/轨道由代码填或随机掷。

| 难度 | 出身（origin） | 可选卡 | 难度 bonus（只给非属性门） |
|---|---|---|---|
| legendary 传奇 | dynasty（政治世家中的世家） | 5 张 | 声望 +12、人情 +4、建制 +20、商业 +10 |
| easy 简单 | dynasty | 4 张 | 无（出身自带 建制 +30） |
| normal 普通 | elite（法学院/商学院精英） | 3 张 | 无（出身自带 商业 +40、人情 +2） |
| hard 困难 | immigrant（移民二代） | 2 张 | 无（出身自带 基层 +20、建制 −20） |
| brutal 炼狱 | labor（蓝领工人） | 1 张 | 声望 −6、人情 −1、建制 −10 |

- **难度 = 出身 + 能选几张卡**，`P.cardPickCount(difficulty)`。**难度不发钱也不发属性**（#36/#37② 两轮收口）：开局资金只有 `startFun: 0` 打底，钱全在【天赋卡池】与【自由点折钱】里。**唯一的例外**是随机起点「商界起手」那一笔本金：`entry.business.effects.fun: 8000`（= 4 个自由点 · $8k，仍高于卡池最贵的那张钱卡「老钱家族」$6k）。它是 #36 换尺时漏网的 v0.5.2 绝对额（原值 `1500000` ≈ 750 点，足以在 1980 年一次性买断学贷与破产线）→ 现按同一把尺收回，并新增断言**出身/起点/州的 `fun` 绝对额不得超过 4×`freeFunPerPoint`**。
- **属性只有两条门（#37② 铁律）**：`startAttr`（CHA/INT/CUN 各 0、INTG 50）+ 自由点 + 天赋卡池。出身/起点/州/难度都不给属性——唯一例外是起点那两条**隐藏诚信负数**（名人 −15 / 商人 −10，只减不增）。validate 静态扫内容表 + 运行时逐组合断言，见 §6 `attr` 行。
- **第 3 步预览是全部来源的和**：属性行显示 `startAttr + 自由点×10 + 已选卡`，卡给的属性另挂 `卡+N` 角标，下方一行汇总"已选 X 张天赋卡带来 …"。玩家在游戏里第一眼看到的数字，必须就是他在向导里能算出来的数字。
- **自由点**：第 1 周目 12 点，每完成一个周目永久 +1（`loopFreeBonus`）；1 点 = +10 属性 = +$2k（与卡池同一把尺），单维上限 10 点 = 属性 100，点不完的自动落进「金钱」档（不受 cap）。
- **卡池**：一次呈现 `gacha.offer: 12` 张，四档稀有度**逐位独立掷**；整面卡墙每局可刷 `gacha.rerolls: 1` 次；**橙卡（命卡，玩家口径叫金卡）受周目门槛 `orangeLoop: 2`**——第 2 周目起才进池，第一周目最多抽到紫。
  **卡池有自己的一把尺（#40 重标）：卡面 1 属性点 = $1k**，档位单位 **白 1 / 蓝 3 / 紫 6 / 金 15**，形态：白 = 单系 +1 或「+2 并别维 −1」或 $1k；蓝 = 单系 +3 或三围各 +1 或 $3k；紫 = 三围各 +2（或单系 +6）或 $6k；金 = 三围各 +5（或单系 +15）或 $15k，外加**特效**（`spare` 免死一类）。
  它**故意比自由点尺（1 点 = +10 属性 = $2k）小一个数量级**：一张金卡的属性面只有建角 12 点池（120 属性点）的 13%，卡池于是从"成长预算的一大块"退回成**风味倾斜 + 只有池子给得出的被动**（免死 / 大成功翻倍 / 健康衰减 / 派系 / 人情）。
  三条纪律由 validate 的「卡池标尺」节钉住：**净值 ≤ 档位单位**、**正项 ≤ 单位 + 负项**（只许用"还给池子的点"换超额单项，于是 +2/−1 合法而 +6/−1 的白卡判红）、**钱卡 = 单位 × $1k**；白/蓝另要求净值**恰好等于**档位（紫/金只要求不超，多维合计）。派系点 / 声望 / 人情 / `mods / crit / luck / hpDecay / voterDrift / spare` 不占这把尺。
- normal/hard/brutal 开局挂学贷（§15，`startDebt 65k/42k/28k`）；easy/legendary 无贷。断供闸三档同宽（`lateLimit 20/20/20`），不"越穷宽限期越短"。
- **作弊码**在建角页（第 2 步天赋墙旁，`#cheatcode` 输入框 + 键盘连打两条路）：`woshishabiN` 把本局当"第 N+1 周目"开——自由点额度与高稀有卡概率一起抬（夹到 `cheatMax: 10`，可累加，只影响本次建角、不写 localStorage）。已掷过的牌面不变脸，要看橙卡得「换一批」。
- 「定命一掷」（掷骰/重掷/VIP 码加点）已在 #20 **整条删除**，`balance` 里不再有 `rollAttrs`；写内容契约与文案时按上面的三步向导口径说话。
